# 13. KNN 分类器 (K-Nearest Neighbors)

## 学习目标与前置知识

第 11 章把字符变成特征向量，第 12 章用距离找到相似模板。本章继续问：**如果最近的那个样本恰好有噪声，能不能多参考几个邻居再决定？** KNN 的名字就是 K-Nearest Neighbors，意思是 K 个最近邻。

学完后，你应能亲手完成一次距离排序和投票，解释 K 与距离权重如何改变结果，并用分开的训练、验证、测试样本比较配置。需要先了解第 11 章的特征与归一化、第 12 章的距离和字符预处理。

在 OCR 流程中，本章的输入是**已经切好的单个字符图像**；输出是一个类别，例如字符串 `'8'`，以及邻居、距离、投票支持率。它不会自动把整张照片切成字符，也不会判断文本的阅读顺序。

## 1. 从“找一个模板”到“找 K 个邻居”

KNN 把带答案的样本保存下来，遇到新输入时再逐个比较。这叫“懒惰学习”：这里的训练主要是存储样本，没有神经网络那样反复更新权重的过程。

为了只观察投票，先不用图像，改用一个数作为特征。输入特征为 `[0]`，样本库有三项：

| 样本 | 已知标签 | 特征 | 到输入 `[0]` 的欧氏距离 |
|---|---|---|---|
| 第一个 | A | `[0.1]` | `√(0−0.1)²=0.1` |
| 第二个 | B | `[0.2]` | 0.2 |
| 第三个 | B | `[0.3]` | 0.3 |

A、B 只是这个手算例的类别名；实际 OCR 会用数字标签。因为特征只有一个数，欧氏距离就是数值差的绝对值。样本已按距离从近到远排好。

1. K=1 时只取第一个邻居，预测 A。
2. K=3 时取三个邻居，普通投票中 A 得 1 票、B 得 2 票，预测 B。
3. B 的票数占比为 `2/3≈66.7%`。这表示三个邻居中有多少支持 B，不能据此保证新输入有 66.7% 的概率正确。

本例在 Node 实验 6 中可以复现。图像实验只是把一个数换成第 11 章提取的一串特征，后面的排序与投票过程相同。

## 2. 距离在比较什么，归一化又改变了什么？

用 x 表示待识别字符的特征向量，用 v 表示某个训练样本的向量，D 表示每个向量有多少项。欧氏距离为：

```text
d(x,v) = √[(x₁−v₁)² + (x₂−v₂)² + … + (x_D−v_D)²]
```

下标只是第几项特征。训练与预测必须用相同的特征顺序、尺寸和预处理：如果 x 的第一项是填充率，v 的第一项却是平均灰度，即使长度相同也没有可比性。

| 距离 | 怎样理解 | 需要注意什么 |
|---|---|---|
| 欧氏距离 | 各项差的平方和开方 | 数值范围大的特征容易主导结果 |
| 曼哈顿距离 | 各项绝对差相加 | 同样依赖特征尺度 |
| 余弦距离 | `1−余弦相似度`，比较向量方向 | 会弱化整体倍数差；零向量没有通常意义的方向 |
| 相关距离 | `1−归一化互相关`，先减去各自均值再比较 | 常量向量没有可用方差，需遵守第 12 章的回退约定 |

课程默认对**每个向量单独做 L2 归一化**：先计算它的长度，再让每项除以这个长度。例如 `[3,4]` 的长度是 `√(9+16)=5`，归一化得到 `[0.6,0.8]`。`[6,8]` 也得到同样结果，所以这种处理会主动忽略整体倍数差。它没有使用整个数据集的均值或方差，也不会自动让不同类型的特征具有同等重要性。

开头的 `[0.1]、[0.2]、[0.3]` 如果使用 L2 归一化，都会变成 `[1]`，原本的距离差就消失了。因此那个手算例明确设置 `normalizeMethod:'none'`；不能只复制输入数字而遗漏这一配置。真实字符默认 `combined` 特征为 85 项，构成见第 11–12 章。

## 3. 加权投票：一个很近的邻居能不能抵过两个较远的邻居？

仍用第一节的三个邻居，把每票的分量改成：

```text
每个邻居的票权 w = 1 / (d + ε)
```

d 是这个邻居到输入的距离；w 是本票的分量；ε（epsilon）是防止距离为零时除零的小正数，默认 `0.000001`。距离越小，分母越小，这一票就越重。

| 标签 | 距离 | 票权，按默认 ε 计算 |
|---|---|---|
| A | 0.1 | 约 10 |
| B | 0.2 | 约 5 |
| B | 0.3 | 约 3.333 |

A 总票权约 10；B 约 `5+3.333=8.333`。这次预测 **A**，票权占比约为 `10/18.333=54.5%`。相同输入、相同 K，仅改变投票方式，就可能得到不同类别。

加权不是必然更准确。如果最近的 A 是错标样本，给它更大权重反而会放大错误。需要在验证数据中比较。源码 `voteByNeighbors` 先按票权排序；并列时比较本类邻居的平均距离，再比较最小距离，最后按标签顺序决定。奇数 K 能减少二分类普通投票平局，却不能消除多分类或加权投票中的所有平局。

```javascript
// 放在章节目录中的脚本使用此相对导入。
const { KNNClassifier } = require('../shared/13-knn-classifier');
const classifier = new KNNClassifier({
    k: 3, normalizeMethod: 'none', weightedVote: false
}).fit([
    { label: 'A', features: [0.1] },
    { label: 'B', features: [0.2] },
    { label: 'B', features: [0.3] }
]);
console.log(classifier.predict([0]).label); // B
console.log(classifier.predict([0], { weightedVote: true }).label); // A
```

## 4. K 应该选多大？

K 指参与决策的邻居数量。小 K 更依赖附近少量样本，因此容易随一个噪声点变化；大 K 会参考更广的区域，可能把局部少数类别淹没在多数类别里。第一节已展示 K=1 和 K=3 的决定可以相反，不能只凭“更平滑”判断哪一个正确。

实际可以在验证集比较 K=1、3、5、7、9，并比较普通与加权投票。它们是实验候选，不是通用最优值。K 必须为正整数；如果训练库只有 3 项而请求 K=5，课程实现只会取实际存在的 3 项。

代价也要考虑。设 N 是训练样本数、D 是特征项数，逐个计算距离需要约 N×D 次特征比较；本实现再把 N 项完整排序，复杂度记为 **O(ND + N log N)**，存储特征需要 O(ND)。减小 K 不会省掉这里对全库的距离计算。因此样本库很大时，预测仍可能慢。

## 5. 训练、验证、测试：三个集合各回答一个问题

| 集合 | 用途 | 能不能据此改配置？ |
|---|---|---|
| 训练集 | 保存供查找的带标签样本 | 可以，构成分类器本身 |
| 验证集 | 比较 K、距离、投票与拒识阈值 | 可以，用来做开发选择 |
| 测试集 | 配置冻结后检查未参与选择的样本 | 若据此继续改配置，它就已参与开发 |

例如，把同一张手写“8”旋转成十张图片，再随机分到训练和测试，会让两个集合都见到近乎相同的字形。程序可能得到很高分，却没有证明能认出新的书写者。因此要**先按原图或书写者分组划分，再做增强**，同一来源的所有变体跟着来源走。

本章 Node 与 HTML 使用相同的程序化数字数据，固定种子为 20260911。种子是控制随机生成顺序的初始数，用同样配置重跑能得到同样样本。数据规模如下：

| 分区 | 造字配置组 | 每组数据 | 图像数 |
|---|---|---|---|
| 训练 | 6 组 | 10 类数字，各 3 种变体 | `6×10×3=180` |
| 验证 | 3 组 | 10 类数字，各 1 张 | 30 |
| 测试 | 3 组 | 10 类数字，各 1 张 | 30 |

`sourceId` 记录来源，各分区互斥。它们仍来自同一造字器与基础数字形状，说明的是“留出一部分合成来源后的表现”，不能替代真实手写照片评估。

默认流程在验证集选择 K 与投票方式，同分时先选较小 K，再选普通投票，然后冻结配置，最后评估测试集。若以后加入“按数据集每一项计算均值/方差”的标准化，也只能在训练集计算这些统计量，再原样应用到验证与测试。本章默认逐向量 L2 不涉及这类拟合。

## 6. 怎样看懂准确率、混淆矩阵和拒识？

换用一个独立的四样本评估例：真实标签为 `['0','0','8','8']`，预测为 `['0','8','8','REJECTED']`。REJECTED 表示系统拒绝给出类别，不是一个数字。

| 真实类别 ↓ / 预测 → | 0 | 8 | REJECTED |
|---|---|---|---|
| 0 | 1 | 1 | 0 |
| 8 | 0 | 1 | 1 |

这就是混淆矩阵：每行固定真实类别，每列记录预测去了哪里。左上和中间对角线各有一个正确样本，总共 2 个正确。于是：

- **全部样本准确率**：`2/4=50%`，拒识也算未正确识别。
- **拒识率**：`1/4=25%`。
- **接受样本准确率**：接受了 3 个，其中 2 个正确，为 `2/3≈66.7%`。报告这个数时要同时报告只接受了 75% 的样本。

课程的距离拒识规则是“最近距离 **d>threshold** 才拒识”。如果最近距离为 0.9、阈值为 0.85，就拒识；最近距离正好是 0.85 则接受。降低阈值才会更严格。演示中的 0.85 是课堂参数，距离尺度随特征与归一化改变，不能直接搬到真实照片中。

还要区分距离与票权占比：所有邻居即使离输入都很远，也可能一致投给某个类，产生 100% 的局部支持率。因此 `confidence` 要配合距离、错误样本与验证结果理解，不能独立视为识别正确的概率。

## 7. 从数字算例接到字符图像

图像入口先复用第 12 章的裁剪与尺寸处理，再调用第 11 章特征提取，最后走前面的距离和投票。训练、预测必须保持同样配置。

```javascript
const classifier = new KNNClassifier({
    k: 3,
    distanceMetric: 'euclidean',
    weightedVote: true,
    featureType: 'combined'
});
classifier.fitFromImages(trainingSamples);
const result = classifier.predictFromImage(testImage);
console.log(result.label, result.confidence, result.neighbors);
```

`trainingSamples` 是 `[{imageData, label}, ...]`，其中 label 是已知答案；`testImage` 是不附带答案的单字符 ImageData。若已有特征，就使用 `fit` 与 `predict`。`tuneK(validationSet, candidateKs)` 比较候选并设置最佳 K；默认演示还通过 `selectDemoParameters` 一起比较投票方式。

当第 12 章模板匹配使用相同预处理、特征、距离和“取最近样本”的规则时，它与 1-NN 对应。其他模板聚合或拒识规则不同，不能只看名称就认为两种方法完全相同。

## 常见问题排查

| 现象 | 先检查什么 |
|---|---|
| 手算距离与代码不同 | 是否启用了默认 L2；是否比较了同一种特征 |
| 一改 K 就换类别 | 看新增邻居属于谁，不要只盯最终标签 |
| 加权后效果下降 | 最近邻是否错标或异常；比较验证集结果 |
| 支持率很高但字错了 | 检查邻居距离、训练样本覆盖与字符是否切错 |
| 拒识率升高 | 是否降低了距离阈值；是否更换特征导致尺度变化 |
| 测试分很高，自己的字很差 | 合成来源与真实字形可能差异很大，核对独立来源和预处理 |

5. 四样本例里接受准确率约 66.7%，为什么全部准确率只有 50%？
