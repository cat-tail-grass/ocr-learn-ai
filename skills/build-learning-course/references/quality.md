# 质量验收与修订

章节子代理先将事实正确性与可理解性分别自检，再检查实践、站点和相互一致性。主会话收到回报后必须依同一尺度验收，复杂知识点可另请独立审查者。明确记录每项检查的执行者，区分作者自检与主会话验收；流程见[逐章委派协议](chapter-delegation.md)。

| 维度 | 通过的依据 | 常见修订动作 |
| --- | --- | --- |
| 目标与依赖 | 每个目标有对应实践或自测，使用的前置能力已说明 | 补前置解释、拆章或缩小范围 |
| 事实与边界 | 关键定义和结论有可靠依据，适用条件准确，例子能复核 | 查教材/官方来源、补条件、修正过强结论 |
| 讲解过程 | 读者能沿同一例子复现关键中间步骤，并解释结果 | 补符号含义、中间值和步骤动机 |
| 方法与反例 | 同条件比较，有一个揭示局限的实例 | 统一输入，补失败案例及原因 |
| 自测 | 有原理、运用和边界题；答案解释依据 | 换掉只有定义复述的题目，补推理 |
| 实践 | 输入可变、反馈真实、默认样例可用、错误可理解 | 实际操作控件，修正未接线功能 |
| 一致性 | 讲义、例题答案、页面、脚本采用相同规则和数据约定 | 复算数值，共用核心逻辑 |
| 阅读体验 | 目录、搜索、公式、代码、答案折叠和实践入口能用，窄屏可读 | 浏览器复验，修复链接和布局 |

## 必须区分的证据

- 机械检查：文件、路径、配置和入口执行。工具返回成功，只能支持它检查过的部分。
- 内容复核：逐个核心知识点读懂并核对定义、算例、答案、反例与目标映射。即使文字通俗也要单独验证事实。
- 浏览器验证：实际修改关键输入或参数，比较前后结果，检查恢复和相关错误状态；只看页面截图不足以证明交互正确。
- 使用者校准：确认学习深度和形式适合自己；不能由生成器自行完成，也不等同于证明所有知识正确。

网络可用时对关键专业结论查询第一手来源，并将链接放在讲义相应位置。没有查到或无法验证的结论明确标记；不要编造来源、测试结果或稳定质量百分比。开放题按可接受答案和评价尺度审查，不把所有不同表达判错。

## 每章记录

在 reviews/<slug>.md 中记录：

1. 本次审查的文件、日期、执行者与审查方式；任务单路径和采用的上下文。
2. 上表各适用项的“通过 / 需修订 / 未验证 / 不适用”和具体证据。证据写输入、操作、观察或命令结果，不能仅写“已检查”。
3. 发现的问题、修正与复验结果。
4. 未覆盖情境、外部资源依赖和剩余限制。
5. 主会话收到回报后的验收结论、依据及返修记录；子代理完成时将这一项留为“待主会话验收”。

修改课程后复验受影响项，旧报告不自动代表新版本。内容、实践或运行仍有关键缺口时保持 draft；机械检查可以通过，但总体课程不能宣称验收完成。

## 技能迁移验收

发布这个技能前，至少选择一个偏数理主题和一个非编程主题，用仅能读取技能包的新上下文生成标杆课，检查实际产物。这个测试说明已覆盖主题的迁移表现，不能保证所有学科同样准确。根据真实失败做窄范围修订，再复验。
