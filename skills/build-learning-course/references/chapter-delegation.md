# 逐章委派协议

这里的子代理是具有独立推理上下文的 Agent；Node 等程序进程负责运行实验或检查。主会话管理全局上下文与验收，每个章节子代理只负责一章及其返修。

## 先完成大纲，再派发一章

主会话先保存课程目标、章节依赖和具体教学安排。course.json 是章节顺序和入口的唯一来源，OUTLINE.md 展开每章的目标、范围、实践与验收依据，二者需要一致。初始化器生成的目录表只是大纲的起点，不能代替这些教学安排。

按大纲确定下一章。所需前章材料必须已验收，或在任务单明确学习者已有的基础与本章要补讲的内容。若用较后章节作首个标杆，大纲须先说明该安排与必要的前置补讲。子代理发现大纲不合理时报告原因与修改建议，由主会话决定并更新后再继续。

批次表示对用户的交付节奏；一次生成任务只有一章。默认串行，完成本章的生成、回报、验收与必要返修后再开始下一章，避免后章依赖尚未稳定的结论。用户明确改变节奏时以其要求为准。

## 主会话提供上下文

在课程项目的 tasks/<slug>.md 保存实际任务单。派发前填入已知事实与有效路径，至少包括：

| 上下文 | 要交给子代理的内容 |
| --- | --- |
| 当前任务 | 章节编号、标题、任务范围和完成标准；说明角色为“章节作者” |
| 学习者与课程目标 | 基础、语言、目标能力、时间预算；COURSE_BRIEF.md 路径及本章相关决定 |
| 大纲安排 | 本章的目标、内容边界、实践成果；course.json、OUTLINE.md 路径 |
| 前后衔接 | 已验收前章的必要结论和实际文件；本章须解释的前置概念；后章需要的输出 |
| 教学尺度 | 技能目录、教学合同、质量表、讲义模板与讲解样例的实际路径；已有标杆和认可反馈 |
| 统一约定 | 已确定术语、符号、单位、示例数据和共享模块接口；没有既有约定时明确写出 |
| 来源与待查项 | 已核实的来源，以及仍需子代理查询或核对的知识点，区分事实与假设 |
| 工作边界 | 课程根目录、允许修改的文件、实际可用的运行及浏览器工具；必须执行的检查 |
| 回报要求 | reviews/<slug>.md 的路径，以及下面的完成回报字段 |

给出简短的相关结论并指向原文件，避免仅说“沿用之前的风格”。每换一章创建新子代理上下文，优先不继承完整主会话历史；通过任务单传递必要信息。有前次返修时，附具体输入、观察、期望及对应文件。

派发时把实际技能路径、课程路径、任务单路径和回报路径交给子代理，并要求先读取任务单和其中的必读文件。只使用宿主确实提供的子代理工具；普通脚本执行不算章节委派。子代理无法读取必需文件或发现上下文冲突时，向主会话报告缺失项，由主会话补充。

## 文件与状态分工

- 已验收章节需要实质修订时，主会话在派发任务前先将该章从 verified 改为 draft，并在审查记录标明“修订中，旧结论待复验”；返修中断或尚未验收时保留 draft，通过本轮验收后才恢复 verified。
- 子代理可以编写本章目录、任务单明确授权的本章共享模块，以及本章 reviews 文件。全局站点模板、其他章节和已有共享模块的改动需求先向主会话说明，获得新的任务范围后处理。
- 本章必需文件齐备后，子代理可以更新 course.json 中**仅本章**的 web/node 入口，并把 planned 改为 draft，以便运行站点与课程检查。委派期间主会话避免同时编辑该条目；课程大纲、其他章节、校准状态与全局进度仍由主会话维护。
- 子代理执行适用的内容核对、例子和浏览器检查，记录观察与未验证项。子代理不得将本章标为 verified，也不得把校准设为 approved 或宣称学习者已掌握。
- 主会话根据回报读取实际产物，对照大纲、教学尺度和前章约定验收；复核关键结论及能证明交互有效的证据，需要时复算或实际操作。将验收结论追加到本章 reviews 文件，由主会话决定 verified 或保持 draft。

主会话可维护框架、配置和上下文文件；章节正文、实践内容与实质性返修交给该章子代理。子代理可用原上下文修订本章；原代理不可用时，新代理读取同一任务单、当前文件与返修记录继续，避免从头覆盖已认可内容。

## 子代理完成回报

子代理完成后保存审查报告，并主动向主会话返回以下信息：

1. **结果状态**：待主会话验收 / 需补上下文 / 未完成，说明具体原因。
2. **产物清单**：修改的真实路径、各产物作用，以及本章入口。
3. **大纲覆盖**：目标对应到讲义、练习和自测；内容取舍及与前后章的衔接。
4. **验证证据**：实际执行的检查、关键输入与输出、内容来源、发现的问题及复验；未执行项明确列出。
5. **遗留事项**：未解决问题、影响验收的限制、需要主会话统一的术语或共享逻辑建议。
6. **审查报告路径**：reviews/<slug>.md；注明执行者、任务单路径与本次采用的上下文。

报告中的“通过”表示对应检查的实际结果；子代理返回成功不等于主会话已经验收。

## 主会话接收与继续

主会话读取回报与相关文件，记录“通过 / 退回修订 / 缺少验证”及理由。退回时给出具体问题、依据与复验要求，等待本章修订完成。通过后更新 course.json 与 PROGRESS.md；可复用的术语、接口或已认可偏好写回 COURSE_BRIEF.md，并带入下一章任务单。

标杆材料通过主会话验收后，仍按主流程等待使用者校准；材料验收不能代替适合学习者的判断。普通后续章节不需要每章再向使用者索取一次批准。

中断后读取任务单、审查报告、实际文件和章节状态；若子代理仍在执行，先取得其状态或已有回报，避免重复派发同一章。无法使用子代理时，交付已完成的大纲与任务单并说明限制；使用者明确选择主会话生成后，将执行方式记录为“主会话生成”，保留同样的质量检查。
