# 系统学习课程

交付能帮助读者逐步掌握目标能力的课程。沿用随包的阅读站点、讲义结构与教学尺度，内容和实践形式按学科选择。默认先交付完整路线与一节完整标杆课，使用者校准一次后再分批生成。

## 主会话与章节子代理

主会话负责大纲、上下文、委派和最终验收。每章的正文与实践产物必须交给独立上下文的子代理生成，一次只委派一章；收到回报并完成验收后，才推进下一章。同一章的返修仍交给该章子代理，换章时新建上下文。调用与回报规则见 [逐章委派协议](references/chapter-delegation.md)，首次委派前必须读取。

收到具体章节任务的子代理，直接执行任务单与下面第3节的写作要求，完成检查后向主会话回报；不重新规划整套课程或递归委派。缺少子代理能力时，主会话可完成大纲和任务单，明确说明执行条件缺失；只有使用者明确接受改由主会话生成，才采用该方式并如实记录。

## 1. 确定学习终点

先读取用户请求、现有课程和学习记录。提取学习者基础、可验收的目标能力、范围、投入时间、语言及运行条件。只询问确实缺失且会改变课程的选择；用户已说清的内容直接采用。

“学习英语”“学习后端”等大主题要落到具体终点，例如“能用英语描述日常安排并应对变化”“能完成带数据库的 API”。若目标尚不明确，给出一个有边界的建议供用户选择；不要把整个学科压成一份速成大纲。

在 COURSE_BRIEF.md 保存决定、假设和使用者反馈。区分课程材料的交付状态与学习者掌握状态，后者只依据使用者自述或真实作答更新。

## 2. 制定路线并创建项目

阅读 [规划与学科适配](references/planning.md)，按前置关系安排章节和阶段成果；每章解决一个可讲透的问题。章节数量由目标决定。尚未交付的章节保留为路线，首页显示“待准备”。

课程正文生成前，必须先保存 COURSE_BRIEF.md、course.json 和 OUTLINE.md。大纲写清每章的学习目标、前置知识、内容边界、实践成果与验收依据；主会话核对目标覆盖和依赖顺序后，才能按大纲派发章节任务。已有明确范围时无需额外等待一次大纲批准。

新项目使用随包模板，先写实际的课程配置，再执行：

```sh
node <本技能目录>/scripts/init-course.mjs --plan <课程配置.json> --out <新项目目录>
```

初始化器只接受不存在或为空的输出目录，实际路径包含空格时需加引号。继续已有课程时直接修改该课程，读取 COURSE_BRIEF.md、course.json、PROGRESS.md 和相关 reviews；不要重新初始化或覆盖已有内容。

## 3. 委派并完成一节标杆课

主会话先准备该章任务单，再派发给新上下文的章节子代理；若实质修订已经 verified 的章节，派发前先改回 draft，复验通过后再恢复。以下要求由章节子代理执行，主会话依同一尺度验收。

写作前阅读 [教学合同](references/teaching-contract.md) 和 [已验证的讲解样例](references/exemplar.md)。按 [讲义模板](assets/lesson-template.md) 完成实际内容；模板中的指引文字需要替换。

为每个主要概念提供“具体问题 → 直觉 → 精确定义 → 同一例子的关键过程 → 输出含义 → 对照与边界”。公式在首次使用处解释符号；语言技能提供语境、可接受表达与纠错依据。先给示例，再让读者练习、核对答案。

实践载体按学习作用选择：

- 每章都有独立可读的 README.md 与有解释的自测答案。
- 能通过改变输入观察结果的内容，提供 index.html。沿用 [实验页面骨架](assets/lab-template.html)，填入真实交互；使用项目 shared/lab.css 和 shared/course-nav.js。
- 可用程序复现的内容，提供 index.js；浏览器与 Node 共用 shared 下的领域逻辑。其他运行语言按学科选择，在讲义说明运行和验证方式，Node 入口可省略。
- 情境练习、写作、证明、动手制作等，以相应练习及评价标准承接，避免为了凑文件生成无学习作用的程序。

本章文件齐备后，只登记 course.json 中本章的 web/node 字段并将本章状态改为 draft。按 [运行与验证](references/runtime.md) 启动课程站，核对讲义、练习和例子。标杆课应当是一次完整交付，而不是仅有标题的预览。

子代理将实际产物、检查证据和未解决项写入 reviews/<章节目录>.md，并向主会话返回完成摘要。主会话读取文件和报告，检查关键算例、练习与课程衔接；需返修时发回该章子代理，验收后才更新材料状态。

## 4. 校准并固化反馈

先按 [验收尺度](references/quality.md) 修订标杆课，再请使用者检查讲解深度、前置假设、练习效果和页面体验；提供可打开的结果与关键实验，方便其判断。

此时停在标杆课，等待使用者校准，不默认扩写整套课程。采纳反馈后修订标杆课，将认可的尺度写入 COURSE_BRIEF.md 和 calibration.feedback，使用者认可后再将 calibration.status 改为 approved。已明确授权的生成节奏以用户要求为准，不重复要求批准。

## 5. 分批生成与复核

每批可交付 1–3 章，但执行单位始终是单章。主会话按大纲顺序选择前置材料已齐备的下一章，更新任务单，逐章执行“提供上下文 → 子代理生成并回报 → 主会话验收或退回修订”。当前章未验收前，不派发下一章的生成任务。每章都带入教学合同、已认可标杆、最新反馈及必要的前章结论，保持术语、示例数据约定和各章接口连贯。

主会话按质量表分别检查事实、可理解性、实践与跨产物一致性；复杂知识点可另请独立审查者复核。生成子代理的自检报告是验收输入，不能自行替代主会话验收。自动检查只证明其实际覆盖的条件。

修复本批发现的问题并复验，在 reviews/<章节目录>.md 记录具体证据、局限与未验证项。通过相应检查后更新材料状态；缺少关键验证时保留 draft。反馈引出的通用规则写入课程说明，具体错误留在对应勘误，避免把个例扩成所有学科的要求。

## 6. 交付与继续

交付入口、已完成章节、实际检查结果和下一批范围。准确说明标杆待校准或尚未生成的章节。中断后读取任务单、子代理回报和主会话验收结论，从当前章继续；生成完成和学习完成分别报告。

首次安装、分享和调用示例见 [安装与使用](INSTALL.md)。技能不依赖原 OCR 项目、专用插件或某一种模型；首次构建阅读站需要 Node.js 和联网安装依赖。无法构建或使用浏览器时继续完成可验证的部分，将对应检查标为未验证，不宣称开箱运行已通过。
