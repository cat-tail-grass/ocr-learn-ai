## 核心概念

### 1. 什么是二值化？

二值化将灰度图像转换为只有**黑（0）和白（255）**两种颜色的图像。

```
灰度图像（256级）         二值图像（2级）
┌─────────────────┐      ┌─────────────┐
│ 0-255 连续灰度  │  →   │ 只有 0 或 255│
└─────────────────┘      └─────────────┘

转换规则：
if (gray >= threshold)
    pixel = 255 (白色/背景)
else
    pixel = 0   (黑色/文字)
```

### 2. 为什么要二值化？

| 原因 | 说明 |
|------|------|
| **简化数据** | 从 256 级简化为 2 级，计算量大减 |
| **分离前景背景** | 明确区分文字（前景）和背景 |
| **便于后续处理** | 连通域分析、形态学操作都需要二值图 |
| **减少噪声影响** | 排除中间灰度级的干扰 |

### 3. 阈值的选择

阈值（Threshold）是分界点，决定哪些像素变白、哪些变黑。

```
灰度值:  0 ─────────── threshold ─────────── 255
         黑色区域(文字)     ↑     白色区域(背景)
                        分界点
```

**阈值选择的挑战**：
- 阈值过高 → 文字变细甚至断裂
- 阈值过低 → 文字变粗，背景噪声增多

### 4. 三种二值化方法

#### 方法一：固定阈值 (Fixed Threshold)

手动指定一个固定的阈值（如 128）。

```javascript
threshold = 128;  // 手动设定
if (gray >= threshold) pixel = 255;
else pixel = 0;
```

**优点**：简单快速  
**缺点**：需要人工调整，不适应光照变化

#### 方法二：Otsu 算法 (大津算法) ⭐ 重点

自动计算最佳阈值，核心思想是：**让分割后的两类（前景和背景）差异最大化**。

```
通俗理解：
想象把学生按身高分成"矮组"和"高组"
- 好的分界点：两组的平均身高差距大（矮组都矮，高组都高）
- 差的分界点：两组的平均身高差距小（混在一起）

Otsu 就是自动找那个"最好的分界点"
```

**优点**：全自动，无需手动调参，效果通常很好  
**缺点**：假设直方图是双峰分布，对光照不均图像效果差

#### 方法三：自适应阈值 (Adaptive Threshold)

每个像素的阈值根据其**局部邻域**动态计算。

```
对于位置 (x, y) 的像素：
threshold(x,y) = mean(邻域) - C
```

**优点**：处理光照不均的图像效果好  
**缺点**：计算量较大

## Otsu 算法详解

### 核心问题：什么是"好的"阈值？

二值化的目标是把图像分成两类：**前景（文字）** 和 **背景**。

一个"好的"阈值应该让：
- 前景像素彼此相似（都是深色）
- 背景像素彼此相似（都是浅色）
- 前景和背景之间差异明显

### 类间方差的直观理解

**类间方差**衡量的是：前景均值和背景均值之间的"距离"有多大。

```
场景：有 10 个像素，灰度值分别是：
[10, 20, 30, 40, 50, 150, 160, 170, 180, 190]

尝试不同的阈值：

阈值 = 100 时：
┌─────────────────────────────────────────────────┐
│ 前景组: [10, 20, 30, 40, 50]   均值 = 30        │
│ 背景组: [150, 160, 170, 180, 190]  均值 = 170   │
│                                                 │
│ 两组均值差距: |170 - 30| = 140  ← 差距大，分离好！│
└─────────────────────────────────────────────────┘

阈值 = 35 时：
┌─────────────────────────────────────────────────┐
│ 前景组: [10, 20, 30]           均值 = 20        │
│ 背景组: [40, 50, 150, 160, 170, 180, 190]       │
│                                均值 ≈ 134       │
│                                                 │
│ 两组均值差距: |134 - 20| = 114  ← 差距较小      │
│ 问题：背景组混入了 40, 50 这些本该是前景的值！    │
└─────────────────────────────────────────────────┘
```

### 为什么类间方差最大化是最优的？

**关键洞察**：图像的总方差 = 类内方差 + 类间方差（这是数学定理）

```
总方差（固定不变）= 类内方差 + 类间方差
     ↓                ↓           ↓
   图像本身         组内差异    组间差异
   的特性           （坏）      （好）
```

- **类内方差**：每组内部像素的差异（越小越好，说明同类像素相似）
- **类间方差**：两组之间的差异（越大越好，说明前景背景分得开）

因为总方差是固定的，所以：
```
类间方差最大 ⟺ 类内方差最小 ⟺ 分割效果最好
```

**通俗比喻**：
> 把学生分成"文科班"和"理科班"  
> - 好的分班：文科班都擅长文科，理科班都擅长理科（类内方差小）  
> - 好的分班：文科班和理科班的特点差异明显（类间方差大）  
> - 这两个目标其实是等价的！

### 类间方差公式解读

```
类间方差 σ²(t) = w₀ × w₁ × (μ₀ - μ₁)²

其中：
- w₀ = 前景像素占比（前景有多少个像素）
- w₁ = 背景像素占比（背景有多少个像素）
- μ₀ = 前景的平均灰度值
- μ₁ = 背景的平均灰度值
- (μ₀ - μ₁)² = 两组均值的差距平方
```

**为什么要乘以 w₀ × w₁？**

这是一个权重因子，防止极端情况：
- 如果前景只有 1 个像素，即使均值差距大，也不是好的分割
- w₀ × w₁ 在两组像素数量均衡时最大

### 具体计算示例

```
假设有一张 6 个像素的简化图像：
灰度值: [30, 40, 50, 180, 190, 200]

尝试阈值 t = 100：

前景（< 100）: [30, 40, 50]
  - 像素数: 3，占比 w₀ = 3/6 = 0.5
  - 均值 μ₀ = (30+40+50)/3 = 40

背景（≥ 100）: [180, 190, 200]
  - 像素数: 3，占比 w₁ = 3/6 = 0.5
  - 均值 μ₁ = (180+190+200)/3 = 190

类间方差 = w₀ × w₁ × (μ₀ - μ₁)²
        = 0.5 × 0.5 × (40 - 190)²
        = 0.25 × 22500
        = 5625  ← 这个值很大，说明 t=100 是好的阈值！
```

### 直方图视角

```
直方图（双峰分布）：

频率
 │
 │     ▓▓                      ▓▓
 │    ▓▓▓▓                    ▓▓▓▓
 │   ▓▓▓▓▓▓                  ▓▓▓▓▓▓
 │  ▓▓▓▓▓▓▓▓                ▓▓▓▓▓▓▓▓
 └──────────────────────────────────── 灰度值
   0   文字峰      ↑         背景峰   255
      (深色)   Otsu阈值      (浅色)
               (谷底)

Otsu 算法自动找到两个峰之间的"谷底"作为阈值
```

### Otsu 算法的局限性

```
❌ 单峰分布（无法分割）：
频率
 │       ▓▓▓▓▓▓
 │      ▓▓▓▓▓▓▓▓
 │     ▓▓▓▓▓▓▓▓▓▓
 └────────────────── 灰度值
    没有明显的两类！

❌ 光照不均（全局阈值失效）：
┌──────────────────────┐
│ 暗区域  │   亮区域   │
│ 文字OK  │  文字消失  │
└──────────────────────┘
一个阈值无法同时适应两个区域
```

## 自适应阈值详解

### 为什么需要自适应阈值？

全局阈值（固定阈值、Otsu）对整张图像使用同一个阈值，但在以下情况效果不佳：

```
光照不均匀的图像示例：

┌─────────────────────────────────┐
│  暗区域      │      亮区域      │
│  (文字清晰)  │  (文字也清晰)    │
│  灰度: 20-80 │  灰度: 150-220   │
└─────────────────────────────────┘

问题：
- 如果阈值=100：暗区域正确，亮区域文字消失
- 如果阈值=180：亮区域正确，暗区域全变黑
```

### 数学原理

自适应阈值为**每个像素**单独计算阈值：

```
threshold(x, y) = mean(邻域) - C

其中：
- 邻域：以 (x, y) 为中心的 blockSize × blockSize 区域
- mean(邻域)：邻域内所有像素的平均灰度值
- C：常数，用于调整敏感度
```

### 直观理解

```
原始图像（光照不均）：        自适应阈值处理后：
┌─────────────────┐          ┌─────────────────┐
│ ░░░ Hello ░░░░ │          │     Hello       │
│ ▓▓▓ World ▓▓▓▓ │    →     │     World       │
│ (渐变背景)      │          │ (背景均匀)       │
└─────────────────┘          └─────────────────┘

每个位置根据局部情况决定阈值！
```

### 参数说明

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `blockSize` | 邻域大小（必须为奇数） | 11-31 |
| `C` | 从均值减去的常数 | 2-10 |

**blockSize 的影响**：
- 太小（如 3）：容易受噪声影响
- 太大（如 51）：失去局部适应性
- 建议：根据文字大小调整，一般为文字笔画宽度的 3-5 倍

**C 的影响**：
- 正值：阈值降低，更多像素变白（适合深色文字）
- 负值：阈值升高，更多像素变黑
- 建议：从 5 开始调整

### 代码实现

```javascript
/**
 * 自适应阈值二值化
 * 
 * @param {ImageData} imageData - 灰度图像数据
 * @param {number} blockSize - 邻域大小（奇数）
 * @param {number} C - 从均值减去的常数
 * @returns {ImageData} 二值化后的图像数据
 */
function binarizeAdaptive(imageData, blockSize = 15, C = 5) {
    const { width, height, data } = imageData;
    const result = new ImageData(
        new Uint8ClampedArray(data),
        width,
        height
    );
    const resultData = result.data;
    const halfBlock = Math.floor(blockSize / 2);
    
    for (let y = 0; y < height; y++) {
        for (let x = 0; x < width; x++) {
            // Step 1: 计算邻域均值
            let sum = 0, count = 0;
            
            for (let dy = -halfBlock; dy <= halfBlock; dy++) {
                for (let dx = -halfBlock; dx <= halfBlock; dx++) {
                    const nx = x + dx;
                    const ny = y + dy;
                    
                    // 边界检查
                    if (nx >= 0 && nx < width && ny >= 0 && ny < height) {
                        const idx = (ny * width + nx) * 4;
                        sum += data[idx];
                        count++;
                    }
                }
            }
            
            const mean = sum / count;
            
            // Step 2: 计算局部阈值
            const threshold = mean - C;
            
            // Step 3: 二值化
            const idx = (y * width + x) * 4;
            const gray = data[idx];
            const binary = gray >= threshold ? 255 : 0;
            
            resultData[idx] = binary;
            resultData[idx + 1] = binary;
            resultData[idx + 2] = binary;
        }
    }
    
    return result;
}
```

### 三种方法对比

| 特性 | 固定阈值 | Otsu | 自适应阈值 |
|------|----------|------|------------|
| 阈值计算 | 手动指定 | 自动（全局） | 自动（局部） |
| 计算速度 | ★★★★★ 最快 | ★★★★☆ 快 | ★★☆☆☆ 较慢 |
| 光照均匀图像 | ★★★☆☆ | ★★★★★ 最佳 | ★★★☆☆ |
| 光照不均图像 | ★☆☆☆☆ | ★★☆☆☆ | ★★★★★ 最佳 |
| 参数调整 | 需要 | 不需要 | 需要 |

### 适用场景

```
✅ 自适应阈值适合：
- 拍照的文档（光照不均）
- 有阴影的图像
- 渐变背景的图像
- 扫描质量不佳的文档

❌ 自适应阈值不适合：
- 光照均匀的图像（用 Otsu 更好）
- 实时处理（计算量大）
- 大面积纯色区域（可能产生噪声）
```

## 如何选择二值化方法？

### 决策流程图

```
                    开始
                      │
                      ▼
            ┌─────────────────┐
            │ 图像光照均匀吗？ │
            └────────┬────────┘
                     │
          ┌──────────┴──────────┐
          │                     │
         是                    否
          │                     │
          ▼                     ▼
   ┌──────────────┐    ┌───────────────┐
   │ 使用 Otsu ⭐ │    │ 使用自适应阈值 │
   │ (自动、快速)  │    │ (处理光照不均) │
   └──────────────┘    └───────────────┘
```

### 判断光照是否均匀的方法

```
方法 1：目视检查
- 图像各区域亮度是否一致？
- 是否有明显的阴影或渐变？

方法 2：直方图分析
- 双峰分布 → Otsu 效果好
- 多峰或平坦分布 → 考虑自适应

方法 3：先试 Otsu，观察结果
- 如果某些区域文字消失或背景变黑 → 换自适应
```

### 实际应用场景指南

| 场景 | 推荐方法 | 原因 |
|------|----------|------|
| 扫描仪扫描的文档 | **Otsu** | 光照均匀，双峰明显 |
| 手机拍摄的文档 | **自适应** | 光照通常不均，有阴影 |
| 截图中的文字 | **Otsu** | 数字图像，光照完美 |
| 户外拍摄的标牌 | **自适应** | 自然光照变化大 |
| 书本翻拍 | **自适应** | 书脊处有阴影 |
| 纯色背景的验证码 | **Otsu** | 背景单一，对比明显 |
| 复杂背景的验证码 | **自适应** | 背景干扰多 |

### 实战建议

```
推荐策略：先试 Otsu，不行再换自适应

原因：
1. Otsu 无需调参，一步到位
2. Otsu 速度快，适合批量处理
3. 大多数扫描文档 Otsu 就够用

只有当 Otsu 效果不佳时，才考虑：
- 切换到自适应阈值
- 调整 blockSize 和 C 参数
```

### 组合策略（进阶）

在实际 OCR 系统中，可以结合使用：

```javascript
function smartBinarize(imageData) {
    // Step 1: 先用 Otsu 尝试
    const otsuResult = binarizeOtsu(imageData);
    
    // Step 2: 评估 Otsu 结果质量
    // （例如：检查前景/背景比例是否合理）
    const fgRatio = calculateForegroundRatio(otsuResult.imageData);
    
    // Step 3: 如果结果异常，改用自适应
    if (fgRatio < 0.05 || fgRatio > 0.8) {
        // 前景太少或太多，可能是光照问题
        return binarizeAdaptive(imageData, 15, 5);
    }
    
    return otsuResult.imageData;
}
```

### 常见问题排查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 文字部分消失 | 阈值过高 | 降低固定阈值 / 用自适应 |
| 背景变成黑色 | 阈值过低 | 提高固定阈值 / 用 Otsu |
| 一边好一边差 | 光照不均 | 必须用自适应阈值 |
| 文字边缘毛糙 | 噪声影响 | 先去噪再二值化 |
| 自适应有噪点 | C 值太小 | 增大 C 值（如 10） |

## 与 OCR 的关联

二值化是 OCR 预处理的核心步骤：

```
彩色图 → 灰度图 → [二值图] → 去噪 → 文字检测 → 文字识别
                    ↑
                 当前学习
```

| 影响 | 说明 |
|------|------|
| 文字清晰度 | 阈值合适时文字边缘清晰 |
| 噪声控制 | 不当的阈值会引入噪点 |
| 后续处理 | 连通域分析、形态学操作都依赖二值图 |
