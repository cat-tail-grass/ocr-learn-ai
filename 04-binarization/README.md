## 核心概念

### 1. 什么是二值化？

二值化将灰度图像转换为只有**黑（0）和白（255）**两种颜色的图像。

```
灰度图像（256级）         二值图像（2级）
┌─────────────────┐      ┌─────────────┐
│ 0-255 整数灰度  │  →   │ 只有 0 或 255│
└─────────────────┘      └─────────────┘

转换规则：
if (gray >= threshold)
    pixel = 255 (白色/背景)
else
    pixel = 0   (黑色/文字)
```

**统一阈值约定**：固定/自适应阈值用 T，`gray >= T` 为白。Otsu 遍历整数 t，低灰度类 C₀=[0,t]、高灰度类 C₁=[t+1,255]，所以调用固定阈值时必须用 **T=t+1**。例如 `[0,255]` 的最优 t=0，应输出 `[0,255]`，若误用 T=0 会全白。以下默认黑字白底；反色文档应先明确前景极性。

### 2. 为什么要二值化？

| 原因 | 说明 |
|------|------|
| **简化数据** | 从 256 级简化为 2 级，计算量大减 |
| **分离前景背景** | 明确区分文字（前景）和背景 |
| **便于后续处理** | 本课程二值连通域/形态学使用二值图；也存在灰度形态学 |
| **减少噪声影响** | 排除中间灰度级的干扰 |

### 3. 阈值的选择

阈值（Threshold）是分界点，决定哪些像素变白、哪些变黑。

```
灰度值:  0 ─────────── threshold ─────────── 255
         黑色区域(文字)     ↑     白色区域(背景)
                        分界点
```

**阈值选择的挑战**：
- 阈值过高 → 更多灰度落入黑色类，文字变粗、背景噪声可能增多
- 阈值过低 → 黑色类缩小，文字变细甚至断裂

### 4. 三种二值化方法

#### 方法一：固定阈值 (Fixed Threshold)

手动指定一个固定的阈值（如 128）。

```javascript
threshold = 128;  // 手动设定
if (gray >= threshold) pixel = 255;
else pixel = 0;
```

**优点**：简单快速  
**缺点**：需要人工调整，不适应光照变化

#### 方法二：Otsu 算法 (大津算法) ⭐ 重点

自动计算最佳阈值，核心思想是：**让分割后的两类（前景和背景）差异最大化**。

```
通俗理解：
想象把学生按身高分成"矮组"和"高组"
- 好的分界点：两组的平均身高差距大（矮组都矮，高组都高）
- 差的分界点：两组的平均身高差距小（混在一起）

Otsu 就是自动找那个"最好的分界点"
```

**优点**：全自动，无需手动调参，效果通常很好  
**缺点**：不要求双峰；双峰且可分时通常有效，光照不均、类别比例失衡时可能失败

#### 方法三：自适应阈值 (Adaptive Threshold)

不用一个固定阈值，而是**每个像素有自己的阈值**，根据它周围的情况决定。

```
通俗理解：
想象你在判断一个学生成绩是否"优秀"
- 全局阈值：全校统一标准，80分以上是优秀
- 自适应阈值：每个班级有自己的标准
  - A班平均90分 → 85分以上算优秀
  - B班平均60分 → 55分以上算优秀

图像也一样：
- 亮区域：周围都很亮，所以用较高的阈值
- 暗区域：周围都很暗，所以用较低的阈值
```

**计算方式**：
```
某个像素的阈值 = 它周围一小块区域的平均亮度 - 一个常数

举例：
- 某像素周围 15×15 区域的平均灰度是 180
- 常数 C = 5
- 这个像素的阈值 = 180 - 5 = 175
- 如果这个像素的灰度 ≥ 175，就变白；否则变黑
```

**优点**：处理光照不均的图像效果好  
**缺点**：计算量较大，需要调整参数

## Otsu 算法详解

### 核心问题：什么是"好的"阈值？

二值化的目标是把图像分成两类：**前景（文字）** 和 **背景**。

一个"好的"阈值应该让：
- 前景像素彼此相似（都是深色）
- 背景像素彼此相似（都是浅色）
- 前景和背景之间差异明显

### 类间方差的直观理解

**类间方差**衡量的是：前景均值和背景均值之间的"距离"有多大。

```
场景：有 10 个像素，灰度值分别是：
[10, 20, 30, 40, 50, 150, 160, 170, 180, 190]

尝试不同的阈值：

阈值 = 100 时：
┌─────────────────────────────────────────────────┐
│ 前景组: [10, 20, 30, 40, 50]   均值 = 30        │
│ 背景组: [150, 160, 170, 180, 190]  均值 = 170   │
│                                                 │
│ 两组均值差距: |170 - 30| = 140  ← 差距大，分离好！│
└─────────────────────────────────────────────────┘

阈值 = 35 时：
┌─────────────────────────────────────────────────┐
│ 前景组: [10, 20, 30]           均值 = 20        │
│ 背景组: [40, 50, 150, 160, 170, 180, 190]       │
│                                均值 ≈ 134       │
│                                                 │
│ 两组均值差距: |134 - 20| = 114  ← 差距较小      │
│ 问题：背景组混入了 40, 50 这些本该是前景的值！    │
└─────────────────────────────────────────────────┘
```

### 为什么类间方差最大化是最优的？

**关键洞察**：图像的总方差 = 类内方差 + 类间方差（这是数学定理）

```
总方差（固定不变）= 类内方差 + 类间方差
     ↓                ↓           ↓
   图像本身         组内差异    组间差异
   的特性           （坏）      （好）
```

- **类内方差**：每组内部像素的差异（越小越好，说明同类像素相似）
- **类间方差**：两组之间的差异（越大越好，说明前景背景分得开）

因为总方差是固定的，所以：
```
类间方差最大 ⟺ 加权类内方差最小（对同一幅图像）
这不等于 OCR 识别效果最好，也不保证分出的两类就是文字与背景
```

**通俗比喻**：
> 把学生分成"文科班"和"理科班"  
> - 好的分班：文科班都擅长文科，理科班都擅长理科（类内方差小）  
> - 好的分班：文科班和理科班的特点差异明显（类间方差大）  
> - 这两个目标其实是等价的！

### 方差分解：符号和推导

令 N 是像素总数，n₀/n₁ 是两类计数，wⱼ=nⱼ/N，μⱼ 是类均值，μ=w₀μ₀+w₁μ₁。对每类像素 g，写成 `g-μ=(g-μⱼ)+(μⱼ-μ)` 并平方；交叉项的类内和为0，因为 `Σ(g-μⱼ)=0`。

```
σ_T² = (1/N) Σ(g-μ)²
     = w₀σ₀² + w₁σ₁² + w₀(μ₀-μ)² + w₁(μ₁-μ)²
     = σ_W² + σ_B²
σ_B² = w₀w₁(μ₀-μ₁)²
```

各 σ² 单位均为灰度值平方。注意 σ_W² 是**按占比加权**的类内总体方差。若代码用 `n₀n₁(μ₀-μ₁)²`，它是 `N²σ_B²`，可在同一图内比较阈值，但不能当作本公式中的方差或跨尺寸比较。本项目 `variance` 返回 σ_B²，`w0/w1` 返回比例，`count0/count1` 返回计数。

### 类间方差公式解读

```
类间方差 σ²(t) = w₀ × w₁ × (μ₀ - μ₁)²

其中：
- w₀ = 前景像素占比（前景有多少个像素）
- w₁ = 背景像素占比（背景有多少个像素）
- μ₀ = 前景的平均灰度值
- μ₁ = 背景的平均灰度值
- (μ₀ - μ₁)² = 两组均值的差距平方
```

**为什么要乘以 w₀ × w₁？**

这是一个权重因子，防止极端情况：
- 不能只比较均值差；小类别的权重较小，但一个像素也可能确实是目标
- w₀ × w₁ 在两组像素数量均衡时最大

### 具体计算示例

```
假设有一张 6 个像素的简化图像：
灰度值: [30, 40, 50, 180, 190, 200]

尝试阈值 t = 100：

前景（≤ 100）: [30, 40, 50]
  - 像素数: 3，占比 w₀ = 3/6 = 0.5
  - 均值 μ₀ = (30+40+50)/3 = 40

背景（> 100）: [180, 190, 200]
  - 像素数: 3，占比 w₁ = 3/6 = 0.5
  - 均值 μ₁ = (180+190+200)/3 = 190

类间方差 = w₀ × w₁ × (μ₀ - μ₁)²
        = 0.5 × 0.5 × (40 - 190)²
        = 0.25 × 22500
        = 5625  ← 这个值很大，说明 t=100 是好的阈值！
```

六像素例中，每类总体方差均为 `(100+0+100)/3=200/3`，加权类内方差为 `200/3`；总均值115，总方差为 `5691⅔`。验证：`5691⅔ = 66⅔ + 5625`。把每个像素重复100次，方差和最优分组不变。

`calculateOtsuThreshold` 在两个非空类中搜索，并列取最小 t。空直方图返回 t=128、variance=0、validSplit=false；只有一种灰度时无有效分割，约定 t=0、variance=0、validSplit=false，计数按这个 t 返回。它们是确定性回退，不表示找到有效文字。

### 直方图视角

```
直方图（双峰分布）：

频率
 │
 │     ▓▓                      ▓▓
 │    ▓▓▓▓                    ▓▓▓▓
 │   ▓▓▓▓▓▓                  ▓▓▓▓▓▓
 │  ▓▓▓▓▓▓▓▓                ▓▓▓▓▓▓▓▓
 └──────────────────────────────────── 灰度值
   0   文字峰      ↑         背景峰   255
      (深色)   Otsu阈值      (浅色)
               (谷底)

Otsu 最大化类间方差，不直接寻找局部谷底。此例 t=50…179 都产生相同分组；本实现并列取最小值50，而不是谷底中心。
```

### Otsu 算法的局限性

```
⚠ 单峰分布（仍能求阈值，但未必有语义上可分的两类）：
频率
 │       ▓▓▓▓▓▓
 │      ▓▓▓▓▓▓▓▓
 │     ▓▓▓▓▓▓▓▓▓▓
 └────────────────── 灰度值
    没有明显的两类！

❌ 光照不均（全局阈值失效）：
┌──────────────────────┐
│ 暗区域  │   亮区域   │
│ 文字OK  │  文字消失  │
└──────────────────────┘
一个阈值无法同时适应两个区域
```

## 自适应阈值详解

### 为什么需要自适应阈值？

全局阈值（固定阈值、Otsu）对整张图像使用同一个阈值，但在以下情况效果不佳：

```
光照不均匀的图像示例：

┌─────────────────────────────────┐
│  暗区域      │      亮区域      │
│  (文字清晰)  │  (文字也清晰)    │
│  灰度: 20-80 │  灰度: 150-220   │
└─────────────────────────────────┘

问题：
- 如果阈值=100：暗区域文字和背景都可能变黑，亮区域文字消失
- 如果阈值=180：亮区域正确，暗区域全变黑
```

### 核心思路：看看周围再决定

自适应阈值的思路很简单：**判断一个像素是黑是白，要参考它周围的情况**。

```
步骤分解：

Step 1: 选一个像素，看看它周围一小块区域（比如 15×15 的方块）
┌─────────────┐
│ · · · · · · │
│ · · · · · · │
│ · · ★ · · · │  ← ★ 是当前要处理的像素
│ · · · · · · │     周围的 · 是它的"邻居"
│ · · · · · · │
└─────────────┘

Step 2: 计算这些邻居的平均亮度
        比如周围像素的平均灰度 = 180

Step 3: 用这个平均值减去一个常数，得到阈值
        阈值 = 180 - 5 = 175

Step 4: 判断当前像素
        如果 ★ 的灰度 ≥ 175 → 变白（背景）
        如果 ★ 的灰度 < 175 → 变黑（文字）
```

**为什么要减去常数 C？**

```
常数 C 的作用是"调整敏感度"：
- C = 0：像素灰度等于周围平均值时，判定为白色
- C = 5：像素灰度必须比周围平均值低超过 5 才会被判定为黑色
- C 越大，越容易判定为白色（背景）

通俗理解：
C 就像一个"宽容度"
- C 大：只有明显比周围暗的才算文字
- C 小：稍微暗一点就算文字
```

### 直观理解

```
原始图像（光照不均）：        自适应阈值处理后：
┌─────────────────┐          ┌─────────────────┐
│ ░░░ Hello ░░░░ │          │     Hello       │
│ ▓▓▓ World ▓▓▓▓ │    →     │     World       │
│ (渐变背景)      │          │ (背景均匀)       │
└─────────────────┘          └─────────────────┘

每个位置根据局部情况决定阈值！
```

### 参数说明

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `blockSize` | 邻域大小（必须为奇数） | 11-31 |
| `C` | 从均值减去的常数 | 2-10 |

**blockSize 的影响**：
- 太小（如 3）：容易受噪声影响
- 太大（如 51）：失去局部适应性
- 建议：根据文字大小调整，一般为文字笔画宽度的 3-5 倍

**C 的影响**：
- 正值：阈值降低，更多像素变白（适合深色文字）
- 负值：阈值升高，更多像素变黑
- 建议：从 5 开始调整

### 代码实现

```javascript
/**
 * 自适应阈值二值化
 * 
 * @param {ImageData} imageData - 灰度图像数据
 * @param {number} blockSize - 邻域大小（奇数）
 * @param {number} C - 从均值减去的常数
 * @returns {ImageData} 二值化后的图像数据
 */
function binarizeAdaptive(imageData, blockSize = 15, C = 5) {
    const { width, height, data } = imageData;
    const result = new ImageData(
        new Uint8ClampedArray(data),
        width,
        height
    );
    const resultData = result.data;
    const halfBlock = Math.floor(blockSize / 2);
    
    for (let y = 0; y < height; y++) {
        for (let x = 0; x < width; x++) {
            // Step 1: 计算邻域均值
            let sum = 0, count = 0;
            
            for (let dy = -halfBlock; dy <= halfBlock; dy++) {
                for (let dx = -halfBlock; dx <= halfBlock; dx++) {
                    const nx = x + dx;
                    const ny = y + dy;
                    
                    // 边界检查
                    if (nx >= 0 && nx < width && ny >= 0 && ny < height) {
                        const idx = (ny * width + nx) * 4;
                        sum += data[idx];
                        count++;
                    }
                }
            }
            
            const mean = sum / count;
            
            // Step 2: 计算局部阈值
            const threshold = mean - C;
            
            // Step 3: 二值化
            const idx = (y * width + x) * 4;
            const gray = data[idx];
            const binary = gray >= threshold ? 255 : 0;
            
            resultData[idx] = binary;
            resultData[idx + 1] = binary;
            resultData[idx + 2] = binary;
        }
    }
    
    return result;
}
```

### 实现边界和复杂度

本章直接遍历邻域，包含中心像素；边缘只计入图内有效像素，按实际 count 取平均，是裁剪邻域，不是补零或复制。`blockSize` 为正奇数，C 必须有限；非法参数报错。复杂度为 O(WHb²)，没有使用积分图；全局 Otsu 为统计 O(WH) 加256档遍历 O(256)。OpenCV 的默认边界和 `>` 比较约定与本课程不完全相同，复制参数时应一并核对。

输入要求灰度 R=G=B；各算法保留 alpha。HTML 输入先合成不透明白底，直方图和前景比例因此与显示一致。二值图在 RGBA 中仍是4字节/像素，未做1-bit打包。用于形态学/连通域前若做均值或高斯平滑，会重新产生灰度值，必须再二值化。

### 三种方法对比

| 特性 | 固定阈值 | Otsu | 自适应阈值 |
|------|----------|------|------------|
| 阈值计算 | 手动指定 | 自动（全局） | 自动（局部） |
| 计算速度 | ★★★★★ 最快 | ★★★★☆ 快 | ★★☆☆☆ 较慢 |
| 光照均匀图像 | ★★★☆☆ | ★★★★★ 常适合 | ★★★☆☆ |
| 光照不均图像 | ★☆☆☆☆ | ★★☆☆☆ | ★★★★★ 常适合 |
| 参数调整 | 需要 | 不需要 | 需要 |

### 适用场景

```
✅ 自适应阈值适合：
- 拍照的文档（光照不均）
- 有阴影的图像
- 渐变背景的图像
- 扫描质量不佳的文档

❌ 自适应阈值不适合：
- 光照均匀时可先试 Otsu，自适应未必增加收益
- 本章直接扫描邻域较慢；积分图实现可以把均值计算加速
- 纯色区域在 C≥0 时按本章 ≥ 约定全白；微小波动与不当 C 会产生斑点
```

## 如何选择二值化方法？

### 决策流程图

```
                    开始
                      │
                      ▼
            ┌─────────────────┐
            │ 图像光照均匀吗？ │
            └────────┬────────┘
                     │
          ┌──────────┴──────────┐
          │                     │
         是                    否
          │                     │
          ▼                     ▼
   ┌──────────────┐    ┌───────────────┐
   │ 使用 Otsu ⭐ │    │ 使用自适应阈值 │
   │ (自动、快速)  │    │ (处理光照不均) │
   └──────────────┘    └───────────────┘
```

### 判断光照是否均匀的方法

```
方法 1：目视检查
- 图像各区域亮度是否一致？
- 是否有明显的阴影或渐变？

方法 2：直方图分析
- 双峰分布 → Otsu 效果好
- 多峰或平坦分布 → 考虑自适应

方法 3：先试 Otsu，观察结果
- 如果某些区域文字消失或背景变黑 → 换自适应
```

### 实际应用场景指南

| 场景 | 推荐方法 | 原因 |
|------|----------|------|
| 扫描仪扫描的文档 | **Otsu** | 光照均匀，双峰明显 |
| 手机拍摄的文档 | **自适应** | 光照通常不均，有阴影 |
| 截图中的文字 | **Otsu** | 数字图像，常较均匀，但复杂 UI 背景仍会干扰 |
| 户外拍摄的标牌 | **自适应** | 自然光照变化大 |
| 书本翻拍 | **自适应** | 书脊处有阴影 |
| 纯色背景的验证码 | **Otsu** | 背景单一，对比明显 |
| 复杂背景的验证码 | **自适应** | 背景干扰多 |

### 实战建议

```
推荐策略：先试 Otsu，不行再换自适应

原因：
1. Otsu 不需手调全局阈值，仍需检查极性与预处理
2. Otsu 速度快，适合批量处理
3. 大多数扫描文档 Otsu 就够用

只有当 Otsu 效果不佳时，才考虑：
- 切换到自适应阈值
- 调整 blockSize 和 C 参数
```

### 组合策略（进阶）

以下仅为需要按数据集校准的启发式伪代码；`calculateForegroundRatio` 需自行定义黑色前景比例。稀疏文字和满页文字都可能是正确结果，前景比例不能单独判断识别质量。


在实际 OCR 系统中，可以结合使用：

```javascript
function smartBinarize(imageData) {
    // Step 1: 先用 Otsu 尝试
    const otsuResult = binarizeOtsu(imageData);
    
    // Step 2: 评估 Otsu 结果质量
    // （例如：检查前景/背景比例是否合理）
    const fgRatio = calculateForegroundRatio(otsuResult.imageData);
    
    // Step 3: 如果结果异常，改用自适应
    if (fgRatio < 0.05 || fgRatio > 0.8) {
        // 前景太少或太多，可能是光照问题
        return binarizeAdaptive(imageData, 15, 5);
    }
    
    return otsuResult.imageData;
}
```

### 常见问题排查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 文字部分消失 | 阈值过低 | 提高固定阈值 / 尝试自适应 |
| 背景变成黑色 | 阈值过高 | 降低固定阈值 / 尝试 Otsu |
| 一边好一边差 | 光照不均 | 尝试自适应或先做光照校正 |
| 文字边缘毛糙 | 噪声影响 | 先去噪再二值化 |
| 自适应有噪点 | C 值太小 | 增大 C 值（如 10） |

<details>
<summary>点击查看答案</summary>

1. 将灰度图转为只有黑白两色的图像，简化数据并分离前景背景
2. 寻找使概率加权类间方差最大的阈值；这等价于最小化加权类内方差，不保证文字识别最优
3. 当图像光照不均匀时（如阴影、渐变背景）
4. 黑字白底时：阈值过高→文字变粗、背景可能变黑；阈值过低→文字变细断裂
