## 核心概念

### 1. 什么是二值化？

二值化将灰度图像转换为只有**黑（0）和白（255）**两种颜色的图像。

```
灰度图像（256级）         二值图像（2级）
┌─────────────────┐      ┌─────────────┐
│ 0-255 整数灰度  │  →   │ 只有 0 或 255│
└─────────────────┘      └─────────────┘

转换规则：
if (gray >= threshold)
    pixel = 255 (白色/背景)
else
    pixel = 0   (黑色/文字)
```

这里的 gray 是当前像素的灰度值，threshold 是我们选的分界数。例如 threshold=128 时，灰度 `[80,127,128,200]` 变成 `[0,0,255,255]`：**刚好等于 128 的也变白**。默认把黑色当文字、白色当背景；对白字黑底，要先调整这一约定。

后面用大写 T 表示这个“变白的起点”。Otsu 返回的则是小写 t，表示“最后一个仍归入暗组的灰度”。等我们算出 Otsu 的分组，再解释这两个数为什么相差 1。

### 2. 为什么要二值化？

| 原因 | 说明 |
|------|------|
| **简化判断** | 后续可以直接判断黑白；本项目仍用 RGBA 存储，内存不会自动缩小 |
| **分离前景背景** | 明确区分文字（前景）和背景 |
| **便于后续处理** | 本课程二值连通域/形态学使用二值图；也存在灰度形态学 |
| **处理灰度波动** | 合适阈值可让浅色波动归入白底；也可能把噪声变成黑点 |

### 3. 阈值的选择

阈值（Threshold）是分界点，决定哪些像素变白、哪些变黑。

```
灰度值:  0 ─────────── threshold ─────────── 255
         黑色区域(文字)     ↑     白色区域(背景)
                        分界点
```

**阈值选择的挑战**：
- 阈值过高 → 更多灰度落入黑色类，文字变粗、背景噪声可能增多
- 阈值过低 → 黑色类缩小，文字变细甚至断裂

### 4. 三种二值化方法

#### 方法一：固定阈值 (Fixed Threshold)

手动指定一个固定的阈值（如 128）。

```javascript
threshold = 128;  // 手动设定
if (gray >= threshold) pixel = 255;
else pixel = 0;
```

**优点**：简单快速  
**缺点**：需要人工调整，不适应光照变化

#### 方法二：Otsu 算法 (大津算法) ⭐ 重点

自动计算最佳阈值，核心思想是：**让分割后的两类（前景和背景）差异最大化**。

```
通俗理解：
想象把学生按身高分成"矮组"和"高组"
- 好的分界点：两组的平均身高差距大（矮组都矮，高组都高）
- 差的分界点：两组的平均身高差距小（混在一起）

Otsu 就是自动找那个"最好的分界点"
```

**优点**：全自动，无需手动调参，效果通常很好  
**缺点**：不要求双峰；双峰且可分时通常有效，光照不均、类别比例失衡时可能失败

#### 方法三：自适应阈值 (Adaptive Threshold)

不用一个固定阈值，而是**每个像素有自己的阈值**，根据它周围的情况决定。

```
通俗理解：
想象你在判断一个学生成绩是否"优秀"
- 全局阈值：全校统一标准，80分以上是优秀
- 自适应阈值：每个班级有自己的标准
  - A班平均90分 → 85分以上算优秀
  - B班平均60分 → 55分以上算优秀

图像也一样：
- 亮区域：周围都很亮，所以用较高的阈值
- 暗区域：周围都很暗，所以用较低的阈值
```

**计算方式**：
```
某个像素的阈值 = 它周围一小块区域的平均亮度 - 一个常数

举例：
- 某像素周围 15×15 区域的平均灰度是 180
- 常数 C = 5
- 这个像素的阈值 = 180 - 5 = 175
- 如果这个像素的灰度 ≥ 175，就变白；否则变黑
```

**优点**：处理光照不均的图像效果好  
**缺点**：计算量较大，需要调整参数

## Otsu 算法详解

### 核心问题：什么是"好的"阈值？

二值化的目标是把图像分成两类：**前景（文字）** 和 **背景**。

一个"好的"阈值应该让：
- 前景像素彼此相似（都是深色）
- 背景像素彼此相似（都是浅色）
- 前景和背景之间差异明显

### 先用同一组像素比较两种分法

设一张小图共有 6 个像素，灰度为 **`[30,40,50,180,190,200]`**。肉眼容易看出前三个较暗、后三个较亮。现在让算法在不知道“哪些是文字”的前提下，比较不同的分界。

Otsu 的候选数 t 是暗组的上界：灰度 ≤t 进入暗组，>t 进入亮组。两个组都必须有像素，均值才有意义。

| 候选 t | 暗组 | 亮组 | 暗组均值 | 亮组均值 |
|---|---|---|---|---|
| 40 | `[30,40]` | `[50,180,190,200]` | 35 | 155 |
| 100 | `[30,40,50]` | `[180,190,200]` | 40 | 190 |

第二种分法的均值差是 150，比第一种的 120 大；两组内部也各自更集中。但算法不能只看均值差，还要考虑每组占多少像素。因此引入**类间方差**，把这两件事合成一个分数。

### 给分数中的每个符号安排一个具体含义

| 符号 | 含义 | 本例 t=100 时 |
|---|---|---|
| N | 全图像素数 | 6 |
| n₀、n₁ | 暗组、亮组的像素数 | 3、3 |
| w₀、w₁ | 两组各占全图的比例，`w=n/N` | 0.5、0.5 |
| μ₀、μ₁ | 两组的平均灰度；μ 读作 mu | 40、190 |
| σ_B² | 类间方差，即要最大化的分数 | 待计算 |

下标 0、1 标记两组；B 来自 between，表示“组与组之间”；上标 ² 表示平方。它们不是新输入，都是从这六个数统计出来的。

```text
σ_B² = w₀ × w₁ × (μ₀−μ₁)²
```

现在把两种分法放在一起算：

| t | 像素占比的乘积 | 均值差的平方 | 类间方差 |
|---|---|---|---|
| 40 | `(2/6)×(4/6)=2/9` | `(35−155)²=14400` | 3200 |
| 100 | `(3/6)×(3/6)=1/4` | `(40−190)²=22500` | **5625** |

所以这两项里 t=100 更好。乘以占比能防止完全忽略类别大小；它不是要求两组一定一样大，也不能证明分出来的暗组一定是文字。分数的单位是“灰度值的平方”，不是正确率。

### 为什么最大化类间方差，也是在让组内更集中？

仍看 t=100。暗组均值为 40，三个像素偏离均值分别为 −10、0、10；组内总体方差为 `(100+0+100)/3=200/3`。亮组均值为 190，也得到 `200/3`。

全图均值是 `(30+40+50+180+190+200)/6=115`。六个像素相对 115 的平方偏差平均为 `5691⅔`。于是：

```text
全图总体方差 = 按占比加权的组内方差 + 类间方差
   5691⅔    = 0.5×(200/3)+0.5×(200/3) + 5625
             = 66⅔ + 5625
```

同一幅图的全图方差固定；因此让右边的类间部分更大，就会让组内部分更小。这里优化的是灰度分布的分组，不是直接优化 OCR 识别准确率。

<details>
<summary>展开：方差分解是怎样推出来的？</summary>

用 μ 表示全图均值，σ_T² 表示全图总体方差，σ_W² 表示按占比加权的组内方差。下标 T 是 total（全体），W 是 within（组内）；组 j 的方差记为 σⱼ²，j 只能取 0 或 1。

对于组 j 中的一个灰度 g，把它相对全图均值的偏差拆成两段：

```text
g−μ = (g−μⱼ) + (μⱼ−μ)
```

第一段是“像素到本组均值”，第二段是“本组均值到全图均值”。两边平方并对本组求和，交叉项含有 `Σ(g−μⱼ)`，而各像素相对本组均值的偏差之和为 0，所以交叉项消失。

```text
σ_T² = w₀σ₀² + w₁σ₁² + w₀(μ₀−μ)² + w₁(μ₁−μ)²
     = σ_W² + σ_B²
μ = w₀μ₀ + w₁μ₁，且 w₀+w₁=1
代入可得 σ_B² = w₀w₁(μ₀−μ₁)²
```

若另一份实现用像素数 n₀、n₁ 代替比例 w₀、w₁，分数会放大 N² 倍。在同一幅图里仍能比较候选，但不是本节定义的方差，也不应跨图比较数值。本项目返回的 `variance` 使用比例，六像素例得到 5625。

</details>

### 从手算分组走到代码返回值

`calculateOtsuThreshold` 先从直方图知道每种灰度有几个，再从小到大移动 t。移动时只要更新暗组的计数和灰度总和，就能算出两组均值，无需把全图反复分组。代码中 `count0/count1` 是数量，`w0/w1` 是比例，`variance` 是刚才的分数。

本例中 t=50、51……179 都得到同样的两组和分数 5625。实现并列时保留最小 t，因此**返回的是 50，而不是手算时举的 100**。两者产生的黑白图相同；Otsu 不是在找直方图谷底的正中央。

现在连接开头的固定阈值规则：Otsu t=50 表示 50 仍归暗组；固定阈值 T 表示从 T 起变白。因此 `binarizeOtsu` 内部使用 **T=t+1=51**，把输入变成 `[0,0,0,255,255,255]`。对 `[0,255]`，Otsu 返回 t=0，内部必须用 T=1；如果误传 T=0，连黑色 0 都满足 `gray>=0`，整图就变白了。

空直方图或只有一种灰度时，算法找不到两个非空组。返回的 `validSplit=false` 就是在说明这件事；不能把回退阈值解释为“已找到文字”。空直方图回退 t=128，单一灰度回退 t=0，方差均为 0。

### Otsu 算法的局限性

```
⚠ 单峰分布（仍能求阈值，但未必有语义上可分的两类）：
频率
 │       ▓▓▓▓▓▓
 │      ▓▓▓▓▓▓▓▓
 │     ▓▓▓▓▓▓▓▓▓▓
 └────────────────── 灰度值
    没有明显的两类！

❌ 光照不均（全局阈值失效）：
┌──────────────────────┐
│ 暗区域  │   亮区域   │
│ 文字OK  │  文字消失  │
└──────────────────────┘
一个阈值无法同时适应两个区域
```

## 自适应阈值详解

### 为什么需要自适应阈值？

全局阈值（固定阈值、Otsu）对整张图像使用同一个阈值，但在以下情况效果不佳：

```
光照不均匀的图像示例：

┌─────────────────────────────────┐
│  暗区域      │      亮区域      │
│  (文字清晰)  │  (文字也清晰)    │
│  灰度: 20-80 │  灰度: 150-220   │
└─────────────────────────────────┘

问题：
- 如果阈值=100：暗区域文字和背景都可能变黑，亮区域文字消失
- 如果阈值=180：亮区域正确，暗区域全变黑
```

### 核心思路：看看周围再决定

自适应阈值的思路很简单：**判断一个像素是黑是白，要参考它周围的情况**。

```
步骤分解：

Step 1: 选一个像素，看看它周围一小块区域（比如 15×15 的方块）
┌─────────────┐
│ · · · · · · │
│ · · · · · · │
│ · · ★ · · · │  ← ★ 是当前要处理的像素
│ · · · · · · │     周围的 · 是它的"邻居"
│ · · · · · · │
└─────────────┘

Step 2: 计算这些邻居的平均亮度
        比如周围像素的平均灰度 = 180

Step 3: 用这个平均值减去一个常数，得到阈值
        阈值 = 180 - 5 = 175

Step 4: 判断当前像素
        如果 ★ 的灰度 ≥ 175 → 变白（背景）
        如果 ★ 的灰度 < 175 → 变黑（文字）
```

**为什么要减去常数 C？**

```
常数 C 的作用是"调整敏感度"：
- C = 0：像素灰度等于周围平均值时，判定为白色
- C = 5：像素灰度必须比周围平均值低超过 5 才会被判定为黑色
- C 越大，越容易判定为白色（背景）

通俗理解：
C 就像一个"宽容度"
- C 大：只有明显比周围暗的才算文字
- C 小：稍微暗一点就算文字
```

### 直观理解

```
原始图像（光照不均）：        自适应阈值处理后：
┌─────────────────┐          ┌─────────────────┐
│ ░░░ Hello ░░░░ │          │     Hello       │
│ ▓▓▓ World ▓▓▓▓ │    →     │     World       │
│ (渐变背景)      │          │ (背景均匀)       │
└─────────────────┘          └─────────────────┘

每个位置根据局部情况决定阈值！
```

### 用 3×3 小图算出中心和边角的阈值

上面的 15×15 适合图片实验；为了能逐项核对，这里改用 3×3 邻域，C=5。C 是从局部平均值中减去的灰度偏移量，不是颜色通道。

```text
100  100  100
100   60  100
100  100  100
```

中心像素周围包含自身，一共 9 个数。总和为 `8×100+60=860`，局部均值 `860/9≈95.556`，阈值 `T≈95.556−5=90.556`。中心灰度 60 小于 T，输出黑色 0。

处理左上角时，3×3 窗口有一部分在图外。课程实现只用图内四个数 `[100,100,100,60]`，均值为 90，T=85。角像素 100≥85，输出白色 255。这里除以 4，不能仍除以 9；图外并没有自动补上五个黑像素。

同一张图把 C 改为 40，中心 T≈55.556，60≥T，原本的黑点也变白。这说明 C 增大后，像素需要比邻域更暗才能留下。它既可能去掉噪点，也可能擦掉浅色笔画。

### 参数说明

| 参数 | 说明 | 推荐值 |
|------|------|--------|
| `blockSize` | 邻域大小（必须为奇数） | 11-31 |
| `C` | 从均值减去的常数 | 2-10 |

**blockSize 的影响**：
- 太小（如 3）：容易受噪声影响
- 太大（如 51）：失去局部适应性
- 建议：根据文字大小调整，一般为文字笔画宽度的 3-5 倍

**C 的影响**：
- 正值：阈值降低，更多像素变白（适合深色文字）
- 负值：阈值升高，更多像素变黑
- 建议：从 5 开始调整

### 代码实现

下面将刚才的手算写成循环：`halfBlock` 是窗口从中心向每侧伸出的距离，`dx/dy` 是邻居相对中心的偏移，`nx/ny` 是邻居的实际坐标。先从原图累计 sum 与 count，再比较中心灰度，最后只把结果写入新图，避免前一个输出影响后一个窗口。

<details>
<summary>展开：自适应阈值的逐像素实现</summary>

以下展示参数合法时的核心循环；正式共享函数还会检查邻域尺寸和 C。

```javascript
/**
 * 自适应阈值二值化
 * 
 * @param {ImageData} imageData - 灰度图像数据
 * @param {number} blockSize - 邻域大小（奇数）
 * @param {number} C - 从均值减去的常数
 * @returns {ImageData} 二值化后的图像数据
 */
function binarizeAdaptive(imageData, blockSize = 15, C = 5) {
    const { width, height, data } = imageData;
    const result = new ImageData(
        new Uint8ClampedArray(data),
        width,
        height
    );
    const resultData = result.data;
    const halfBlock = Math.floor(blockSize / 2);
    
    for (let y = 0; y < height; y++) {
        for (let x = 0; x < width; x++) {
            // Step 1: 计算邻域均值
            let sum = 0, count = 0;
            
            for (let dy = -halfBlock; dy <= halfBlock; dy++) {
                for (let dx = -halfBlock; dx <= halfBlock; dx++) {
                    const nx = x + dx;
                    const ny = y + dy;
                    
                    // 边界检查
                    if (nx >= 0 && nx < width && ny >= 0 && ny < height) {
                        const idx = (ny * width + nx) * 4;
                        sum += data[idx];
                        count++;
                    }
                }
            }
            
            const mean = sum / count;
            
            // Step 2: 计算局部阈值
            const threshold = mean - C;
            
            // Step 3: 二值化
            const idx = (y * width + x) * 4;
            const gray = data[idx];
            const binary = gray >= threshold ? 255 : 0;
            
            resultData[idx] = binary;
            resultData[idx + 1] = binary;
            resultData[idx + 2] = binary;
        }
    }
    
    return result;
}
```

</details>

### 实现边界和复杂度

代码里的 `blockSize` 是窗口边长 b，必须为正奇数，才有明确的中心；C 必须是有限数。边缘的裁剪方式已经在上面的角像素算例中展示。不同图像库可能使用补边或 `>` 比较，迁移参数时要连同这两个约定一起核对。

如果图像宽 W、高 H，每个像素最多查看 b² 个邻居，那么总工作量随 `W×H×b²` 增长，记为 O(WHb²)。例如把窗口边长从 3 改为 15，内部像素检查的邻居从 9 个增为 225 个，是 25 倍。Otsu 只需扫描一次全图统计直方图，再扫描 256 个灰度档，工作量为 O(WH+256)。第 25 章会介绍用积分图加速局部均值，本章保留直接遍历来展示过程。

函数只读 R，是因为输入已满足 R=G=B；输出也给三个颜色通道写入同一个 0 或 255，A 透明度保持原值。HTML 先合成白底再输入，让这套数字对应实际显示。输出仍是 RGBA，不会自动变成位打包文件。

如果之后使用均值或高斯滤波，黑白交界可能出现 128 等中间灰度。要交给仅接受二值图的形态学、连通域模块，就需要重新二值化；处理顺序要根据算法需要确定。

| 特性 | 固定阈值 | Otsu | 自适应阈值 |
|------|----------|------|------------|

| 计算速度 | ★★★★★ 最快 | ★★★★☆ 快 | ★★☆☆☆ 较慢 |
| 光照均匀图像 | ★★★☆☆ | ★★★★★ 常适合 | ★★★☆☆ |
| 光照不均图像 | ★☆☆☆☆ | ★★☆☆☆ | ★★★★★ 常适合 |
| 参数调整 | 需要 | 不需要 | 需要 |

### 适用场景

```
✅ 自适应阈值适合：
- 拍照的文档（光照不均）
- 有阴影的图像
- 渐变背景的图像
- 扫描质量不佳的文档

❌ 自适应阈值不适合：
- 光照均匀时可先试 Otsu，自适应未必增加收益
- 本章直接扫描邻域较慢；积分图实现可以把均值计算加速
- 纯色区域在 C≥0 时按本章 ≥ 约定全白；微小波动与不当 C 会产生斑点
```

## 如何选择二值化方法？

### 决策流程图

```
                    开始
                      │
                      ▼
            ┌─────────────────┐
            │ 图像光照均匀吗？ │
            └────────┬────────┘
                     │
          ┌──────────┴──────────┐
          │                     │
         是                    否
          │                     │
          ▼                     ▼
   ┌──────────────┐    ┌───────────────┐
   │ 使用 Otsu ⭐ │    │ 使用自适应阈值 │
   │ (自动、快速)  │    │ (处理光照不均) │
   └──────────────┘    └───────────────┘
```

### 判断光照是否均匀的方法

```
方法 1：目视检查
- 图像各区域亮度是否一致？
- 是否有明显的阴影或渐变？

方法 2：直方图分析
- 双峰分布 → Otsu 效果好
- 多峰或平坦分布 → 考虑自适应

方法 3：先试 Otsu，观察结果
- 如果某些区域文字消失或背景变黑 → 换自适应
```

### 实际应用场景指南

| 场景 | 推荐方法 | 原因 |
|------|----------|------|
| 扫描仪扫描的文档 | **Otsu** | 光照均匀，双峰明显 |
| 手机拍摄的文档 | **自适应** | 光照通常不均，有阴影 |
| 截图中的文字 | **Otsu** | 数字图像，常较均匀，但复杂 UI 背景仍会干扰 |
| 户外拍摄的标牌 | **自适应** | 自然光照变化大 |
| 书本翻拍 | **自适应** | 书脊处有阴影 |
| 纯色背景的验证码 | **Otsu** | 背景单一，对比明显 |
| 复杂背景的验证码 | **自适应** | 背景干扰多 |

### 实战建议

```
推荐策略：先试 Otsu，不行再换自适应

原因：
1. Otsu 不需手调全局阈值，仍需检查极性与预处理
2. Otsu 速度快，适合批量处理
3. 大多数扫描文档 Otsu 就够用

只有当 Otsu 效果不佳时，才考虑：
- 切换到自适应阈值
- 调整 blockSize 和 C 参数
```

### 组合策略（进阶）

以下仅为需要按数据集校准的启发式伪代码；`calculateForegroundRatio` 需自行定义黑色前景比例。稀疏文字和满页文字都可能是正确结果，前景比例不能单独判断识别质量。


在实际 OCR 系统中，可以结合使用：

```javascript
function smartBinarize(imageData) {
    // Step 1: 先用 Otsu 尝试
    const otsuResult = binarizeOtsu(imageData);
    
    // Step 2: 评估 Otsu 结果质量
    // （例如：检查前景/背景比例是否合理）
    const fgRatio = calculateForegroundRatio(otsuResult.imageData);
    
    // Step 3: 如果结果异常，改用自适应
    if (fgRatio < 0.05 || fgRatio > 0.8) {
        // 前景太少或太多，可能是光照问题
        return binarizeAdaptive(imageData, 15, 5);
    }
    
    return otsuResult.imageData;
}
```

### 常见问题排查

| 问题现象 | 可能原因 | 解决方案 |
|----------|----------|----------|
| 文字部分消失 | 阈值过低 | 提高固定阈值 / 尝试自适应 |
| 背景变成黑色 | 阈值过高 | 降低固定阈值 / 尝试 Otsu |
| 一边好一边差 | 光照不均 | 尝试自适应或先做光照校正 |
| 文字边缘毛糙 | 噪声影响 | 先去噪再二值化 |
| 自适应有噪点 | C 值太小 | 增大 C 值（如 10） |

## 自测问题

1. 灰度 `[80,127,128,200]` 在 T=128 时变成什么？
2. 六像素例中，t=40 和 t=100 的类间方差是多少？
3. 为什么本例 Otsu 返回 50，而不是 100？
4. Otsu 返回 t=0 时，为什么要给固定阈值函数传 T=1？
5. 3×3 例的中心与角像素分别使用几个邻居，C=5 时结果是什么？
6. 把 C 增大到 40，为什么中心暗点会消失？

<details>
<summary>展开答案与计算依据</summary>

1. `[0,0,255,255]`，等于阈值时按本课程规则变白。
2. `(2/6)×(4/6)×(35−155)²=3200`；`0.5×0.5×(40−190)²=5625`，后者更大。
3. 50–179 都产生相同分组和最大分数，实现并列取最小值；并没有寻找谷底中心。
4. t=0 表示灰度 0 仍在暗组；T=1 才让 0 变黑。传 T=0 会使所有非负灰度变白。
5. 中心 9 个，均值约 95.556、阈值约 90.556，60 变黑；左上角 4 个，均值 90、阈值 85，100 变白。
6. 中心阈值降到约 55.556，60 已高于它，于是变白。C 太大可能连浅色笔画一起抹去。

</details>
