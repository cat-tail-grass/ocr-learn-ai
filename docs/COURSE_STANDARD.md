本标准由 2026-09-08 的旧课程实读提取，用于全课程的新增与修订；第14–26章沿用该交付基线；2026-09-13先修订第05–12章，再将同一可读性要求扩展至全部26章。依据用户要求，以一章完整的“知识讲解 + 交互实验 + Node.js 实验”作为交付单位。

## 2. 三个主要交付文件

每章目录 MUST 包含：

```text
XX-topic/
├── README.md       # 可以独立阅读的完整课程
├── index.html      # 可以实际操作的教学 demo
└── index.js        # node XX-topic/index.js 可直接运行的教学实验
```

允许 browser.js、模型、数据、样式等辅助文件。可复用算法放 shared；三个主入口仍然清楚可见。README 必须说明首次依赖安装、浏览器启动方式及 Node.js 命令。涉及模型文件加载的页面使用本地 HTTP 服务，并在文档解释如何启动；默认小实验应可复现，完整训练另有明确命令与耗时说明。

## 3. README：以一个技术点为解释单位

每章应有以下结构，标题可随内容自然调整：

1. **学习目标和前置知识**：本章回答什么问题，依赖旧课的什么能力。
2. **OCR 中的位置**：输入从哪里来，输出交给谁，本章对最终 demo 的作用。
3. **核心概念逐点展开**，每个主要技术点包含问题动机、直觉或图示、精确定义、公式符号与维度、可核对算例、算法步骤与代码对应、参数与边界。算例必须包含具体输入、关键中间值和输出；有关时展开复杂度和数值稳定性。
4. **方法或配置对照**：例如激活函数、学习率、池化、解码方式、检测方法、模型架构、评估口径；给出选择依据。
5. **代码与运行说明**：三个主文件各自负责什么，关键共享 API 的输入输出，预期观察结果。
6. **常见误区与排障**：能用于理解一次错误，而非泛泛建议“调参”。
7. **自测问题与答案**：覆盖原理、计算和适用边界，读者能用答案核对理解。
8. **重要知识点概括与下一章联系**：供用户自行总结分享，不代替正文解释。
9. **参考来源**：算法原论文和框架官方文档，区分实际实现、教学简化与公开系统。

“定义 + 一条公式 + 链接”、API 罗列、只说框架会自动完成等均不足以交付。数值例子必须与代码和当前术语约定一致；旧课程中的错误或过时结论不能作为新课应继承的标准。

### 3.1 可读性：让读者知道每一步在解决什么

- 先说明本节要解决的具体问题、输入是什么、输出交给哪一步，再引入术语与公式。
- 符号第一次出现时，就在相邻文字中给出名称、含义、单位或范围；同一字母在不同上下文代表不同对象时明确区分，例如透明度 alpha 与复杂度函数 α。
- 数据结构须落到具体值：先说明一个 RGBA 像素的四项，再说只读取哪个通道；先区分灰度值、前景指示和区域标签，再进行运算。
- 对同一方法或对照实验，尽量贯穿同一小输入，按“输入 → 中间计算 → 输出 → 结果意味着什么”展开。换用另一组输入时明确说明，不让读者误以为数字可以直接比较。
- 将实现约定放到能解释其作用的位置。例如计算出灰度 121 后再说明取整和透明度保留；解释梯度正负后再说明为什么不能用 8 位图存中间值。
- 不用“维度正确”“已归一化”“框架会处理”“置信度高”等术语代替说明；讲清维度由哪些部分组成、归一化参数在哪个范围计算、分数能支持什么结论。
- 保留推导、代码、参数边界和反例。较长实现、完整接口表与进阶推导可折叠，但正文应足以跟着算；先通过一次实际调用说明字段的作用，再提供完整参考，不能仅靠隐藏知识点降低门槛。
- 完稿后沿读者顺序复读，并将手算值与当前共享函数核对。数学与代码正确、知识点齐全、读者可理解是三个都要检查的条件。

## 4. HTML：把技术点变成能操作的实验

- 页面直接进入本章实验，提供内置数据/样例或合理默认值，避免读者先准备复杂环境才能看到核心过程。
- 允许改变与算法相关的输入或参数，提供执行与恢复/重置方式。
- 展示输入、至少一个有解释意义的中间状态、最终结果，并标明对应步骤和维度/单位。
- 提供至少一种有意义的对照：改变参数、方法切换、训练前后、正确/错误案例，或原始与处理结果。
- 对训练章节展示真实训练状态与曲线/指标；对序列和矩阵章节展示状态、矩阵、权重、路径或对齐等对应对象。
- 纯粹打印一个 JSON 对象或显示固定截图不算完整交互 demo；表格、Canvas、热力图、步骤列表等可按主题选择。
- 非法输入、空白、计算中、加载失败等相关状态清楚可见；重复运行不积累不可控资源。
- 浏览器调用与 Node.js 相同的算法，避免复制实现后产生差异。

## 5. Node.js：按多个实验验证本章

- `node XX-topic/index.js` 是明确可运行入口，脚本头说明本章内容与运行方式。
- 自带小型可复现输入，按有标题的步骤或实验组织输出；随机实验固定种子。
- 输出关键输入、参数、维度/中间值、结果与简短解释，不能只加载一个模块或转发一个 JSON。
- 覆盖核心算法和一个配置/方法对照，并包含至少一个能说明局限或边界的例子。
- 长训练、数据准备和快速示例有清楚区分，不在不知情时触发不可控的重复训练。
- 关键算法注释解释公式到代码的对应关系；共享模块中的教学算法采用可逐步阅读的格式，不把核心循环和分支压缩成难以断点检查的一行。
- 错误应产生清楚说明与正确退出状态；测试有实际数值/行为依据，不能只证明函数被调用。

## 6. 三种产物的一致性验收

每章 README 加入一张“知识点—文档位置—HTML 实验—Node 实验/函数”对应表。主代理检查：

- 大纲中的核心知识点有没有遗漏？
- 文档描述的算法约定是否等于代码实际行为？
- 文档数值例子能否通过脚本复现或测试核对？
- HTML 的交互是否确实改变运算，能否观察说明中承诺的结果？
- Node.js 是否能独立执行，且输出足够用于学习和调试？
- 对训练、标准数据、合成数据、真实照片的成果描述是否准确？
- 章节间的接口、数据格式与术语是否连贯？

自动检查可以发现缺文件、缺入口、运行失败和部分结构缺失；**不能代替逐章阅读、数值核对和浏览器交互审查**。主代理只有在这些检查后才记录本章交付完成。
