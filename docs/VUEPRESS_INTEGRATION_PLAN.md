# VuePress课程站整合方案

状态：已按本方案完成模块实施、主代理集成和独立验收。日期：2026-09-11。实际交付、版本和验证结果见[整合报告](VUEPRESS_INTEGRATION_REPORT.md)；以下保留方案与分工依据。

## 1. 目标与推荐方案

使用VuePress 2、Vite及官方默认主题，将26章现有README直接渲染为课程文档；提供阶段目录、本章目录、上一章/下一章、搜索和交互实验入口。实验继续以独立HTML页面运行，随文档打包到同一个静态站点。

课程README是唯一正文来源；每章现有的讲义、HTML、Node三个入口继续对应。新增工作集中在阅读布局、内容编排、资源装配和路径适配。

当前项目有26份课程README，共约1.29万行；第11章约1100行。文档中已有公式、矩阵、代码、表格和自测答案，适合通过章节内目录改善阅读。扫描发现92个独立行的`\[`公式起始标记，需要显式支持现有数学分隔符。

## 2. 阅读体验

| 区域 | 建议内容 |
|---|---|
| 首页 | 学习目标、八个阶段的26章目录、开始学习、最终数字串实验入口 |
| 顶部导航 | 课程、实验目录、分享指南、勘误记录、搜索 |
| 左侧 | 按现有八阶段分组的课程目录，当前章高亮、分组可折叠 |
| 中央正文 | 完整技术讲解，保留公式、算例、实现对照、误区、自测与参考来源 |
| 右侧 | 本章二级/三级标题目录，点击定位并跟随阅读位置 |
| 章首操作区 | “打开交互实验”和可复制的Node运行命令 |
| 章末 | 上一章、下一章的编号与标题；第一章/最后一章正确处理边界 |
| 移动端 | 折叠课程目录、本章目录；代码、矩阵和宽表格局部横向滚动 |

知识要点采用“章首学习目标/要点导航 + 完整正文 + 章末重点回顾”的形式。优先复用已有学习目标、分享重点和自测，只补齐缺少的导航摘要，不重写上一轮已复核的理论。

默认一章一页，长章通过本章目录定位。保留直接引用某个公式或小节的锚点链接；在实际阅读验证后再决定是否拆分极长章节。

## 3. 技术组成

| 能力 | 选择 | 项目中的用途 |
|---|---|---|
| 文档框架 | VuePress 2 + Vite | Markdown页面、静态构建、开发热更新 |
| 主题 | 官方默认主题 + 少量布局扩展 | 课程目录、上下章、中文排版、浅色/深色、章节操作区 |
| 公式 | `@vuepress/plugin-markdown-math` + KaTeX | 启用`delimiters: 'all'`，兼容`\(...\)`、`\[...\]`和美元分隔符 |
| 搜索 | `@vuepress/plugin-slimsearch` | 设置`indexContent: true`，索引课程正文和标题；验证中文术语命中 |
| 实验构建 | 现有esbuild | 继续生成22个browser入口；11–13保留直接共享脚本 |
| 资源装配 | 小型Node脚本 + 显式资源清单 | 收集实验HTML、bundle、共享脚本、模型和样例，输出静态实验目录 |

官方文档仍将VuePress 2标注为RC。实际查询npm官方源时，`vuepress@next`为`2.0.0-rc.31`，要求Node≥22.18.0；当前项目Node 24符合。主题/插件版本号与核心不同，实施时按peerDependencies选择匹配组合并精确锁定，保留lockfile。现有`require/module.exports`课程代码继续使用CommonJS，VuePress配置及新增构建脚本使用`.mjs`，不将整个项目改成ESM。

依据：[VuePress安装](https://vuepress.vuejs.org/guide/getting-started.html)、[默认主题上下章](https://ecosystem.vuejs.press/themes/default/frontmatter.html#prev)、[公式插件](https://ecosystem.vuejs.press/plugins/markdown/markdown-math.html)、[全文搜索](https://ecosystem.vuejs.press/plugins/search/slimsearch.html)。版本与引擎范围以实施时实际安装的包元数据为准。

## 4. 内容源与导航生成

建议以项目根目录作为VuePress的sourceDir，使用显式`pagePatterns`只选择首页、26章README和课程辅助文档。现有`docs/`继续存放分享指南、勘误等资料；构建日志、模型元数据和内部任务文件不自动生成阅读页面。

新增统一课程目录配置，记录编号、目录名和阶段。章节标题默认读取README一级标题；由同一份目录配置生成首页列表、侧边栏、实验入口和prev/next。通过VuePress页面扩展给课程注入这些元信息，避免逐章手写26套导航。附录与审查报告不进入01→26的课程顺序。

建议目录：

```text
ocr-learn-ai/
├── 01-image-fundamentals/ … 26-validation/
│   ├── README.md                  # 课程正文来源
│   ├── index.html                 # 交互实验来源
│   └── index.js                   # Node实验来源
├── shared/                        # 现有算法与公共资源
├── docs/                          # 分享指南、勘误等辅助内容
├── .vuepress/
│   ├── config.mjs                 # 框架、页面范围、主题及插件
│   ├── catalog.mjs                # 课程编号/阶段/路径
│   ├── client.mjs                 # 布局组件注册
│   ├── components/                # 章首入口、本章目录等
│   ├── plugins/course-pages.mjs   # 章节元信息及链接适配
│   ├── styles/course.css         # 阅读排版
│   ├── public/labs/               # 自动装配的实验资源，忽略提交
│   └── dist/                      # 最终静态站点，忽略提交
└── scripts/
    ├── prepare-labs.mjs           # 实验资源收集
    ├── dev-site.mjs               # 文档/实验统一开发入口
    └── build.js                   # 原实验构建逻辑
```

README修改后直接热更新。实验源码修改后重新构建受影响的bundle并更新资源目录；课程正文不生成另一份需要人工维护的副本。

VuePress支持控制页面范围和扩展页面元信息，具体依据为[pagePatterns](https://vuepress.vuejs.org/reference/config.html#pagepatterns)及[页面扩展API](https://vuepress.vuejs.org/reference/plugin-api#extendspageoptions)。

## 5. 路由与实验入口

建议使用以下对应关系；最终部署到子目录时统一加站点base：

| 内容 | URL示例 |
|---|---|
| 课程首页 | `/` |
| 第04章讲义 | `/04-binarization/` |
| 第04章实验 | `/labs/04-binarization/index.html` |
| 第17章讲义 | `/17-cnn-classifier/` |
| 第17章单数字实验 | `/labs/17-cnn-classifier/index.html` |
| 最终数字串实验 | `/labs/25-ocr-engine/index.html` |
| 评估记录 | `/labs/26-validation/index.html` |

默认点击“打开交互实验”在新标签页打开完整实验页面，保留当前文档阅读位置。实验顶部提供“返回本章讲义”“课程目录”；25/26之间保留识别与评估切换。实验链接使用普通HTML链接进行完整页面导航。

独立实验页面可使用完整画布空间；TensorFlow.js和模型在进入相应实验后加载。初版不需要将26份HTML重写成Vue组件。若后续确有边读边操作的需要，可针对少量轻量实验增加按需加载的内嵌模式。

## 6. 必须处理的项目适配点

### 6.1 实验资源与相对路径

11–13章通过`../shared/...`加载脚本；17章加载model.json、权重、验证样例与训练报告；20章加载weights.json；25章跨目录加载17章模型和26章样例。构建需保持这些资源在`labs/`下的相对目录关系。

按实际依赖准备资源清单，不只复制index.html。资源清单同时用于检查缺失文件；完整MNIST下载缓存和无关运行产物不进入站点。最终产物包含阅读、已有模型推理和评估所需资源。

### 6.2 文档链接与base

文档中的章节README链接指向对应阅读页；`index.html`和现有固定`127.0.0.1:4173`实验链接指向新的labs地址。代码块中的路径与命令保持示例语义，使用Markdown解析后的链接节点进行转换。

`shared/course.js`现有首页和25/26根路径，以及实验中的固定模型/样例地址，需要集中处理。文档组件使用VuePress的base辅助方法，静态实验使用同一构建配置生成路径；不能认为VuePress会自动改写原HTML和bundle里的硬编码字符串。根路径和`/ocr/`子目录各验证一遍。[VuePress静态资源和base说明](https://vuepress.vuejs.org/guide/assets.html)。

### 6.3 数学与Markdown兼容

除了公式分隔符，还检查矩阵、aligned/cases、上下标、代码块、ASCII图、HTML表格与`details/summary`自测答案。代码展示中的模板符号保持字面值，避免被Vue编译为组件或插值。格式调整需保留公式和数值原意。

### 6.4 本地训练服务与浏览器记录

建议统一开发和预览使用`http://127.0.0.1:4173`，保持当前训练桥允许的来源。17章从头训练仍需要本机4174数据桥；在课程页明确启动步骤，并检查训练页迁移后的连接。其他端口通过明确配置适配。

浏览器localStorage按来源隔离，同一来源只换成`/labs/`路径通常可继续读原记录；换域名或端口时使用现有JSON导入/导出。25和26必须保持同源。迁移不修改模型标识、处理流程版本或已有评估记录内容。

## 7. 构建与使用方式

预期统一命令：

| 命令 | 行为 |
|---|---|
| `npm run dev` | 实验构建/资源准备，启动VuePress开发服务，监听文档与实验变更 |
| `npm run build` | 实验构建→资源装配→VuePress静态构建，任一步失败则整体失败 |
| `npm run preview` | 通过本地HTTP服务预览最终dist |
| `node XX-topic/index.js` | 继续运行现有Node课程实验 |

最终输出为一个可部署的静态目录，可用于公司现有静态服务器。本轮方案不指定托管平台；本地文档、模型推理和评估构建可先验收。数据下载、Node实验与完整训练在文档中保留本地运行说明。

## 8. 实施顺序与分工

**本次工作方式：子代理执行模块任务，主代理输送上下文、协调并最终集成验收。** 主代理已按用户要求将旧OpenSpec任务归档并完成[integrate-vuepress-course-site](../openspec/changes/integrate-vuepress-course-site/tasks.md)，原来5项未完成的实拍验收保存在[独立待办](../openspec/backlog/real-photo-validation.md)，没有因归档勾选为完成。以下分工已执行，接口及交接记录见[实施契约](VUEPRESS_IMPLEMENTATION_CONTRACT.md)。

### 8.1 主代理先冻结接口

分派实现任务前，主代理必须冻结课程目录（编号、阶段、正文来源与顺序）、讲义与实验URL、站点base及其传递方式、资源清单接口与输出目录结构，以及资源准备、开发监听和构建脚本的输入、输出与失败退出约定。同时明确页面元信息字段、组件和插件接入接口、验收命令，形成各代理共同使用的接口约定。

根路径与`/ocr/`子目录须使用同一套约定。接口需要变更时，子代理先报告主代理，由主代理协调并同步受影响模块后再实施，不能自行改变其他模块依赖的接口。

### 8.2 互斥写入范围

共享工作区按互斥写范围分派。主代理在启动各代理前列明具体文件或目录；同一文件同一阶段只有一个写入负责人，未分配文件须先由主代理确定归属。不得通过回滚、覆盖或清理操作擅自撤销其他人的改动。

| 负责人 | 模块任务 | 独占写入范围与边界 |
|---|---|---|
| 主代理 | 接口冻结、上下文输送、依赖协调、最终集成和验收 | `package.json`及lockfile、`.vuepress/config.*`、`.vuepress/client.*`、`.vuepress/catalog.*`、页面元信息实现（如`.vuepress/plugins/course-pages.mjs`）、全局文档和OpenSpec；D获分配的独立验收报告由D写入 |
| A：布局导航 | 章首实验入口、课程导航展示、本章目录、上下章展示与阅读排版 | `.vuepress/components/**`和`.vuepress/styles/**`；消费主代理提供的目录与元信息，不直接修改config、client、catalog或页面元信息 |
| B：实验资源及路径 | 资源装配、统一开发/构建脚本、实验返回入口、base及模型/样例路径适配 | 指定的实验资源清单、`scripts/prepare-labs.mjs`、`scripts/dev-site.mjs`、`scripts/build-site.mjs`、`shared/course.js`及事先列明的实验路径适配文件；不自行修改依赖清单或lockfile |
| C：正文兼容与搜索 | Markdown链接转换、公式和Markdown兼容、搜索接入方案与正文命中检查 | 指定的Markdown链接适配与兼容插件文件，以及确有必要且事先列明的原始课程README格式修正；不改变已复核理论、公式与数值原意，搜索配置由主代理接入全局配置 |
| D：独立验收 | 独立验证浏览器阅读、搜索、实验及跨页流程，记录缺陷与复验结果 | 指定的浏览器验证脚本和独立验收报告；只读检查已接入实现，不同时修改其他代理或主代理负责的实现文件 |

Markdown链接转换与兼容逻辑由C在独立插件文件中交付，主代理负责在配置及页面入口接入；新增依赖、组件注册和全局搜索配置也由主代理统一写入。各代理只在自己的写入范围内工作，跨模块修改需求先报告主代理。构建生成物的输出位置与运行时机同样需要协调，避免并发构建覆盖共享产物。

### 8.3 每个代理的上下文包

启动或重新分派子代理时使用`fork_context: false`，避免携带历史长上下文；由主代理主动输送当前任务所需的最小完整上下文。每个上下文包必须包含：

1. **任务目标**：本次有边界的交付内容、前置依赖和完成条件。
2. **必要文件**：应阅读的方案、源文件及相关阶段结果，不要求代理自行追溯全部历史。
3. **接口**：已冻结的目录、URL、base、资源与构建接口，以及模块所需的元信息、组件或插件约定。
4. **只写范围**：独占文件/目录清单、只读依赖和生成物范围，明确禁止写入的共享入口。
5. **已知边界**：不改已复核理论、保留现有实验与Node入口；列明与本模块有关的17章训练桥、25/26同源记录、模型标识及历史数据约束和已知未决项。
6. **验收命令**：主代理确认的准确命令、前置环境、预期结果及根路径/子目录验证要求；尚未具备的条件必须明示。
7. **结果格式**：改动文件清单、完成内容与接口接入说明、验证命令及结果（含失败或未执行原因）、未决项与剩余任务；中断时使用同一格式提交阶段结果。

### 8.4 按依赖分波次实施

1. **接口与任务准备**：主代理完成接口冻结、共享入口准备及上下文包分派；将新OpenSpec中的任务按负责人、依赖和验收条件拆分。
2. **A/B/C模块实施**：依赖就绪且写入范围互斥后，A、B、C可并行执行。先以04、11、17、25章验证布局、公式/长文、共享脚本、模型加载和最终流程，再按相同接口扩展到26章、辅助文档、中文搜索与完整实验资源。未就绪的依赖先报告主代理，不越界补改其他模块。
3. **主代理接入与集成检查**：审查A/B/C的阶段结果并接入组件、插件、目录、页面元信息、依赖与构建入口，检查完整构建、base适配、开发监听、17章训练桥及25→26记录流转，向D提供可验证的集成版本和必要上下文。
4. **D独立验收与修复闭环**：D在模块接入后，按第9节独立执行浏览器验证并提交脚本/报告。缺陷由主代理分派回对应负责人修复，主代理重新集成后交D复验；D不一边验收一边代改其他人的实现。
5. **主代理最终验收与交付**：结合模块验证、D的独立报告、原525项测试及26个Node入口结果审查整站，确认通过后才勾选OpenSpec任务并更新全局启动指南；失败、未执行和未决项不得勾选为完成。

### 8.5 阶段交接与质量责任

每个代理结束或中断时，都必须提交含改动文件、验证结果与未决项的阶段结果，由主代理接收后及时关闭该子代理。主代理保留已交付改动、审查当前状态，再将有边界的剩余任务连同更新后的上下文包重新分配；若异常退出未能提交报告，由主代理先核查现有改动并补齐交接信息，不把中断视为完成，也不直接重做或回滚其他人的工作。

子代理自报完成不等于任务通过，任务只能在主代理审查验证证据后勾选。并行本身不自动保证质量；质量依靠明确接口、互斥写入、独立检查和主代理最终集成验收保证。
