<title>把系统学习做成可复用的 Skill：从 OCR 项目到可交互课程</title>

输入一个学习主题、自己的基础和目标，让 Agent 先规划完整路线，再生成一节能阅读、能练习、能核对结果的标杆课；确认深度合适后，按同一标准逐章扩展。

这就是 **zaihui-build-learning-course** 想提供的学习方式。它适合技术同学建立自学项目，也可以迁移到微积分、英语等系统性知识。

## 一、为什么从分享图像处理，转向分享学习方法

准备 OCR 与图像处理分享时，我做了 ocr-learn-ai：用 Markdown 讲解概念，用 HTML 实验观察参数的作用，再用 Node.js 脚本复现计算。随着内容展开，我发现，一小时很难讲清整个知识体系；自己理解一个知识点，到能够向别人讲清楚，也需要反复练习。

项目里逐渐积累了一套有用的方法：学习目标明确，前置知识讲清楚，同一个小例子贯穿推导，交互页面能验证讲义，自测答案解释判断依据。这些质量来自多次调整。

因此，这次分享把这些经验提炼成一个 Skill，供大家用自己的主题建立学习项目。我们同时把生成后的核对、反馈和修订写进流程，让后续课程能沿用已经认可的标准。

原始项目：[ocr-learn-ai](https://github.com/cat-tail-grass/ocr-learn-ai)。

## 二、使用后会得到什么

| 产物 | 学习时怎样使用 |
| --- | --- |
| 完整路线与课程大纲 | 看清终点、章节依赖，以及每一阶段应该能做什么 |
| 每章 Markdown 讲义 | 阅读概念、示例、推导、误区和自测答案 |
| 本地课程阅读站 | 使用目录、搜索、公式、阅读位置和章节导航 |
| 与学科匹配的练习 | 通过改变条件、完成题目或提交表达来核对理解 |
| 可复现的程序实验 | 适用于数值计算、算法或开发主题，输出输入、中间步骤和结果 |
| 生成任务与验收记录 | 了解每章用了什么上下文、检查了什么、还有什么没有验证 |

首次交付是“完整路线 + 一节完整标杆课”。其他章节会清楚显示为待准备，后续根据反馈继续生成。

### 讲义的共同结构

每章都围绕这些教学功能组织：学习目标、前置知识、在整体路线中的位置、核心概念、示例与实践、方法比较与常见误区、自测问题与解释答案、要点回顾与下一步、参考来源。

具体的讲解顺序是：**提出问题 → 建立直觉 → 给出定义 → 跟着同一例子推演 → 解释结果 → 检查边界**。公式第一次出现时解释符号，代码说明它与概念的对应关系。

### 实践形式随学科调整

| 主题 | 合适的练习方式 |
| --- | --- |
| 图像处理 | 对同一图像调整参数，比较处理结果并核对计算 |
| 微积分 | 改变函数、观察点和增量，比较差商、导数及不可导情形 |
| 英语 | 情境选句、补全、纠错、自由表达与参考评价 |
| 后端开发 | 运行接口，观察请求经过各层的过程，验证异常输入 |

Node.js 是阅读站的运行环境；是否编写 Node 教学实验，由课程内容决定。学习英语的人不需要为了使用课程而学习编程。

## 三、怎样把多轮打磨沉淀下来

整个流程可以记成一条线：

**主会话完成大纲 → 准备单章上下文 → 独立子代理生成并自检 → 子代理回报 → 主会话验收或退回修订 → 推进下一章。**

主会话负责全局：学习目标、章节衔接、术语与符号、已认可的教学深度，以及最后的验收。每章子代理获得相关的前章结论、教学规范、标杆课和反馈，专注于这一章的讲义与实践。

每换一章使用新的子代理上下文。同章返修可以继续使用原代理。一次任务只生成一章；即使一批交付几章，也按顺序完成每章的生成与验收。

子代理结束时，需要向主会话回报真实产物、目标覆盖情况、运行与内容核对证据、遗留问题。主会话必须读取实际文件并复核关键结论，不能只依据“已完成”的摘要判断质量。

第一节标杆课还需要学习者确认：讲解是否太快、符号是否过早出现、例子是否能跟上、练习是否有帮助。反馈会写入课程约定，再带到下一章。

### 质量检查分开进行

- **结构与运行**：文件、链接、入口和例子能否实际运行。
- **知识与讲解**：定义和结论是否可靠，算例与答案能否复核，前置知识和边界是否清楚。
- **交互与一致性**：改变输入后，结果是否真实改变；讲义、网页和脚本是否采用相同规则。
- **学习者校准**：内容深度和形式是否适合使用者。

课程区分“待生成”“草稿”“材料已验收”，并单独记录学习者的掌握情况。材料通过检查，不能自动标记为已经学会。已验收章节开始实质修订时，也要先退回草稿，再进行本轮验收。

## 四、已经做过哪些验证

除了原 OCR 项目，我们用两个新的上下文，只提供技能包和学习需求，分别生成了微积分与英语的标杆课。

| 样本 | 已完成内容 | 实际检查 |
| --- | --- | --- |
| 微积分 | 8周路线；“从割线到一点的导数”标杆课、交互网页与 Node 实验 | 25项数值与边界断言；10组构建后站点的浏览器检查 |
| 日常英语 | 6周路线；“平时还是眼下”标杆课，包含情境、纠错和自由表达练习 | 15项练习规则断言；19组构建后站点的浏览器检查 |
| 通用课程框架 | 初始化、检查、资源同步与预览工具 | 12项运行回归；解压后初始化检查；技能格式校验 |

微积分示例：调整函数、观察点与增量，比较割线斜率和导数。

英语示例：在同一情境里比较表达，通过选句、纠错和自由表达练习核对理解。

两份样本保存在演示项目的 artifacts/learning-skill-validation/samples 目录，目前没有独立公开的在线预览地址；文中的截图来自实际验证页面。课程样本不包含在本次技能合并申请中。

试用中确实发现并修复了问题。例如，一道英语题把 read 直接当作动词形式错误，但它也可能表示过去式，需要更明确的语境；课程目录中“待准备”章节的样式也经过修正。这些发现说明，实际检查和修订是交付的一部分。

目前的证据覆盖两个主题各一节标杆，尚未证明所有领域都能一次达到同样质量，也没有真实学习者效果测试。9月18日补充的严格逐章委派协议，已经做了指令一致性审查和现有运行回归；上述样本生成于该次更新前，不作为新版委派流程的完整端到端验证。

## 五、怎样开始使用

### 1. 获取完整技能目录

团队仓库：[zaihui/skills](https://pasta.zaihui.com.cn/zaihui/skills)。团队版本名称为 **zaihui-build-learning-course**；最初从 OCR 项目提炼出的本机版本名为 build-learning-course。

当前状态：已提交[合并申请 #5](https://pasta.zaihui.com.cn/zaihui/skills/-/merge_requests/5)，目标分支为 master，尚未合并。可以先查看[本次提交的完整技能目录](https://pasta.zaihui.com.cn/zaihui/skills/-/tree/f153a8562ad771c12758038905b6eda0c75d579a/skills/zaihui-build-learning-course)和[安装说明](https://pasta.zaihui.com.cn/zaihui/skills/-/blob/f153a8562ad771c12758038905b6eda0c75d579a/skills/zaihui-build-learning-course/INSTALL.md)。

合并到 master 后，可使用仓库推荐的安装命令：

```sh
npx add-skill https://pasta.zaihui.com.cn/zaihui/skills -s zaihui-build-learning-course
```

合并前，可以从合并申请对应分支获取整个 skills/zaihui-build-learning-course 目录，再按工具要求放入技能目录。Codex 个人目录通常为 ~/.codex/skills/，Claude Code 为 ~/.claude/skills/。必须保留 references、assets、scripts 和 agents，站点模板与检查程序都在其中。

完整工作流需要支持文件读写、命令执行和子代理的 Agent 环境；生成阅读站需要 Node.js ≥22.18.0，首次安装依赖需要联网。技能本身不要求额外的 API Key 或付费插件。若工具没有子代理能力，会先完成大纲与任务单，说明限制，再由使用者决定是否接受主会话生成。

### 2. 说清主题、基础和学习终点

可以直接复制这个请求，并替换成自己的学习需求：

> 使用 zaihui-build-learning-course。我想系统学习微积分，会基础代数和函数，但没学过极限。目标是能解释并计算简单函数的导数，每周投入3小时。请用中文讲解，先保存完整课程大纲，再通过独立子代理生成一节包含交互实验的标杆课，由主会话验收后交给我试读。

如果换成英语，可以这样描述终点：

> 使用 zaihui-build-learning-course。我认识基础英语单词，目标是能描述日常安排并应对临时变化。请使用中文讲解、英语例句、情境练习和有解释的自测答案，先交付完整路线和一节标杆课。

比起只给出“我要学后端开发”，写明“会 JavaScript，希望独立完成带数据库、鉴权和错误处理的 API”，更容易得到边界清楚、能够验收的课程。

### 3. 先体验标杆，再给具体反馈

> 本章符号出现得太早。请先用一个具体情境说明问题，再沿用同一个例子逐步解释。保留推导，把长接口说明折叠，并将这条偏好写入课程约定。

认可后继续：

> 标杆课的深度和练习方式我认可。请按大纲继续下一批，每章由独立子代理生成，主会话验收后再推进下一章，并保留实际检查记录。

## 六、分享现场可以怎样演示

一小时可以按这个顺序组织：

| 时间 | 内容 |
| --- | --- |
| 0–10分钟 | 从 OCR 自学项目出发，说明课程需要解决哪些学习问题 |
| 10–25分钟 | 展示第05章去噪：讲义、小例子、交互对照和可复现结果 |
| 25–40分钟 | 拆解 Skill：教学合同、站点模板、逐章委派和主会话验收 |
| 40–50分钟 | 展示微积分与英语标杆，比较跨学科时保留与调整的部分 |
| 50–60分钟 | 一起写一个有边界的学习请求，讨论标杆反馈与问答 |

现场使用已经检查过的课程展示效果。生成新标杆的耗时会受主题、模型和运行环境影响，可以演示如何描述需求与如何验收，不把整套课程生成安排为现场必完成环节。

大家可以先选择一个自己真正想掌握的小目标，生成并体验一节标杆课，再用具体反馈决定后续课程的深度。Skill 会记录这些反馈，帮助后面的章节沿用同一套教学标准。
