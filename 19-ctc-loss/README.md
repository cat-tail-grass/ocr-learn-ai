# 19. CTC：对齐、损失、梯度与字符串解码

## 学习目标与 OCR 中的位置

第 18 章能为每个图像特征列产生状态，但“有 10 帧特征、真值是 001”仍然没有逐帧标签。一个字符占几帧并不知道，连续两个相同数字也不能简单合并。CTC（Connectionist Temporal Classification）让训练者只提供顺序正确的字符串，通过对所有合法对齐求和来计算损失。

本章要回答：blank 是什么、重复怎么保留、怎样避免枚举爆炸、为什么贪婪与 beam 不同，以及如何把损失梯度传回网络。前置知识是第 14 章 softmax/交叉熵、链式法则，第 16 章张量，第 18 章逐帧状态。

```text
整行图像 → CNN特征列 → RNN/LSTM → 每帧K类概率 [T,K]
                                     ├→ CTC损失 ← 训练目标字符串
                                     └→ CTC解码 → 预测字符串
```

**真值只连接训练损失和独立评估，不连接解码器。** CTC 不是图像特征提取器，也不等同于整个 CRNN。Node 最后的小实验只训练 3 帧 logits，第 20 章才训练图像到字符串的完整小型模型。最终现场“分割 + CNN”路线不依赖此损失。

## 1. 从字符标签到路径：为什么需要 blank

### 1.1 逐帧交叉熵缺少监督对象

假设图像被编码成 T=5 帧，真值 y=`00`，长度 U=2。若使用普通逐帧分类，你必须知道每帧是哪个 0、还是字符间隙。把 `00` 任意拉伸为 `00000` 会抹去“两个字符”的事实。CTC 把这个未知对齐作为隐变量。

设普通类别集合为 A，在其中增加 blank，得到 `A' = A ∪ {∅}`，K=`|A|+1`。路径 π 是长度恰好为 T 的类别序列，可以包含重复与 blank。字符串 y 的长度可以小于 T。

本项目映射必须牢记：

| 类别索引 | 符号 | 语义 |
|---:|---|---|
| 0 | ∅ | blank，对齐占位 |
| 1 | 数字字符 `0` | 真正要识别的数字零 |
| 2 | 数字字符 `1` | 真正要识别的数字一 |

blank 的索引 0 **不是数字字符 `0`**。共享算法允许别的 blank 索引与更多类别，页面与第 20 章实验固定使用上表。

blank 表示“这一帧不增加字符”。它不是词语里的空格，也不要求在白色背景位置输出；上下文网络可以在笔画区域输出 blank，其他帧输出字符尖峰。

### 1.2 折叠函数 B 的两个步骤

1. 合并**原始路径中相邻且相同**的类别。
2. 删除 blank。

```text
路径 [a,a,∅,a,b,b] → 合并 [a,∅,a,b] → 删除blank [a,a,b]
路径 [a,a]         → [a]            → [a]
路径 [a,∅,a]       → [a,∅,a]        → [a,a]
路径 [∅,∅]         → [∅]            → []
```

如果先删除 blank，再合并重复，第三行会错误变为一个 a。实现必须和原路径的前一项比较，而不是与“上一个输出字符”比较。

```javascript
// collapsePath 的核心逻辑；prev来自原路径。
const labels = [];
for (let t = 0; t < path.length; t++) {
    const current = path[t];
    const sameAsPreviousFrame = t > 0 && current === path[t - 1];
    if (current !== blank && !sameAsPreviousFrame) {
        labels.push(current);
    }
}
```

### 1.3 重复数字需要多少时间步

设 r 是目标中相邻相同字符的对数，则存在结构合法对齐的必要且充分长度条件是：

\[
T\ge U+r
\]

每个字符至少占一帧，每一对相邻相同字符还需要一个 blank 分开。例如：

| 目标 | U | r | 最少帧 | 一条最短路径 |
|---|---:|---:|---:|---|
| `01` | 2 | 0 | 2 | `0,1` |
| `00` | 2 | 1 | 3 | `0,∅,0` |
| `000` | 3 | 2 | 5 | `0,∅,0,∅,0` |
| 空串 | 0 | 0 | 0 | 无字符；非空输入只能全blank |

长度足够并不保证**概率**非零：若所需路径中某类概率恰好为 0，目标总概率仍可能为 0。有限 logits 的 softmax 在数学上为正；直接输入的概率矩阵允许精确零。

本实现为简化张量契约要求 T≥1；空目标合法，零帧矩阵则明确拒绝。

## 2. 损失的定义：从路径概率求和到负对数

### 2.1 符号与条件独立

| 符号 | 维度/取值 | 含义 |
|---|---|---|
| x | 一张整行图或其特征 | 网络的条件输入 |
| z | `[T,K]` | 网络 logits |
| pₜ(k) | `[T,K]` 的一个元素 | `softmax(zₜ)` 后的类别概率 |
| π | 长度 T 的索引数组 | 对齐路径 |
| y | 长度 U 的非blank数组 | 训练目标 |
| B | 路径到标签串的函数 | 合并重复后删除blank |

CTC 的路径模型在给定网络输入后，将各帧的路径发射概率相乘：

\[
P(\pi\mid x)=\prod_{t=0}^{T-1}p_t(\pi_t)
\]

\[
P(y\mid x)=\sum_{\pi:B(\pi)=y}P(\pi\mid x),\qquad
\mathcal L=-\log P(y\mid x)
\]

这不代表网络不能建模上下文：BiLSTM 的每个 pₜ 都可依赖整行图像。条件独立约束体现在上述输出路径分解，不等于输入特征互相独立。

训练希望使所有能解释目标的路径的**总概率**增大，而不是事先挑选某一条正确对齐。定义和动态规划来自 [Graves 等，ICML 2006 原论文](https://www.cs.toronto.edu/~graves/icml_2006.pdf)。

### 2.2 两帧一字符的手算

只有 blank 和 a 两类：

| t | blank | a |
|---:|---:|---:|
| 0 | 0.4 | 0.6 |
| 1 | 0.6 | 0.4 |

目标 a 的合法路径是：

```text
(a,a)       0.6×0.4 = 0.24
(a,blank)   0.6×0.6 = 0.36
(blank,a)   0.4×0.4 = 0.16
合计                      0.76
loss = -ln(0.76) = 0.27443685
```

全 blank 路径的概率为 0.24，两种输出串的概率和是 1。注意路径 `(a,a)` 不是两个 a；本例 T=2 无法输出连续重复 `aa`。

### 2.3 枚举的正确性与成本

T 帧、K 类一共有 Kᵀ 条路径。`enumeratePaths` 用独立递归枚举并折叠每条路径，适合检查小案例。在 T=4、K=3 时只有81条；T=30、K=11 则已经不可行。

Node 演示打印单条路径概率；Jest 将多个目标（包括空串、重复、不可对齐）逐项与 DP 比较。枚举不是训练方案，默认最多100万条，页面进一步限制为10万条，超过后保留 DP 并解释跳过枚举的原因。

## 3. 前向动态规划：每个状态只计算一次

### 3.1 为什么要插入 blank 状态

把目标扩展为：

\[
l'=[\varnothing,y_0,\varnothing,y_1,\ldots,y_{U-1},\varnothing]
\]

状态数 S=`2U+1`。例如目标 `00`，扩展状态 `[∅,0,∅,0,∅]`，两个 0 是不同**状态位置**，虽然类别相同。状态的顺序不能倒退，保证单调对齐。

定义 αₜ(s)：在 t 帧结束、位于扩展状态 s 的所有合法路径前缀概率之和，**包含当前帧发射**。

初始化（其余状态为 0）：

\[
\alpha_0(0)=p_0(\varnothing),\qquad \alpha_0(1)=p_0(y_0)
\]

空目标只有一个 blank 状态，不初始化状态1。

### 3.2 三种来源与跳跃条件

当前状态可从：

1. 同一状态 s 留下：让一个字符或 blank 跨越多帧。
2. 前一状态 s−1 前进：blank 与字符交替。
3. 前两状态 s−2 跳跃：跳过字符间可选 blank，但只允许当前类别非blank且与 s−2 的类别不同。

\[
\alpha_t(s)=p_t(l'_s)\left[\alpha_{t-1}(s)+\alpha_{t-1}(s-1)
+\mathbf1_{\mathrm{skip}(s)}\alpha_{t-1}(s-2)\right]
\]

其中 `skip(s) = s≥2 && l'[s]!==blank && l'[s]!==l'[s−2]`。超出范围的 α 为0。相同字符不能跳过 blank，否则会把一个持续发射的字符误认为两个字符。

完成整个目标的路径可停在末尾 blank 或最后一个字符：

\[
P(y\mid x)=\alpha_{T-1}(S-1)+\alpha_{T-1}(S-2)
\]

空目标仅取唯一状态。损失前向的时间复杂度 O(TU)，只求损失时可用两行 O(U) 内存；本教学实现保留整张 α、β 表供可视化，使用 O(TU+TK) 内存。

### 3.3 连续重复 `00` 的完整小表

本例列顺序 `[blank,数字0,数字1]`：

```text
t0: [0.2, 0.7, 0.1]
t1: [0.8, 0.1, 0.1]
t2: [0.1, 0.8, 0.1]
```

普通概率域的 α 为：

| t | s0 blank | s1 第一个0 | s2 blank | s3 第二个0 | s4 blank |
|---:|---:|---:|---:|---:|---:|
| 0 | 0.2 | 0.7 | 0 | 0 | 0 |
| 1 | 0.16 | 0.09 | 0.56 | 0 | 0 |
| 2 | 0.016 | 0.2 | 0.065 | 0.448 | 0 |

例如 `α₁(2)=0.8×(α₀(2)+α₀(1))=0.56`；`α₂(3)=0.8×(α₁(3)+α₁(2))=0.448`，不能加入 `α₁(1)`，因为 s1 和 s3 都是数字0。

最终 P=`0.448+0`，loss=`0.80296205`。三帧下恰好只有路径 `[数字0,blank,数字0]` 合法，因此独立枚举也得到 `0.7×0.8×0.8=0.448`。

### 3.4 对数域：避免长路径下溢

连续相乘很多小概率容易成为浮点0。代码保存 `aₜ(s)=log αₜ(s)`，用 log-sum-exp 代替加法：

\[
\operatorname{LSE}(v_1,\ldots,v_n)=m+\log\sum_i e^{v_i-m},\quad m=\max_i v_i
\]

不可能状态用 `−Infinity`。若所有候选都是 `−Infinity`，必须直接返回 `−Infinity`，否则 `−∞−(−∞)` 会得到 NaN。

本例 `log α₁(2)=log 0.56=-0.5798185`；最终 logP=`−0.80296205`。浏览器和 Node 显示对数 α；README 的概率表更便于手算。返回的 `probability=exp(logP)` 在极端长序列仍可下溢，但损失由 logP 直接得到，保持稳定。

logits 转为 log 概率时也要避免消减误差。令 `m=max(z)`、`v=z−m`，实际计算 `log p=v−log Σexp(v)`；不要先把 `m+log Σexp(v)` 舍入到一个大数后再用 z 减它。反例是一帧两类 `z=[10¹⁶,10¹⁶]`、目标 `[1]`：正确概率 `[0.5,0.5]`、loss=`ln 2`、梯度 `[0.5,−0.5]`；后一种计算会把归一化项 `ln 2` 吞掉，错得概率 `[1,1]`。本章实现和回归检查保留“每帧 logits 同加常数不变”的性质，处理顺序与 [TensorFlow.js 4.22 的 logSoftmax 源码](https://github.com/tensorflow/tfjs/blob/tfjs-v4.22.0/tfjs-core/src/ops/log_softmax.ts) 一致。若输入在进入函数前已把不同数值舍入为相同浮点数，算法无法恢复丢失的信息。

代码步骤是校验矩阵 → 扩展目标 → 初始化 → 两层循环推进 α → 合并两个终态。`fromLogProbabilities` 是内部函数，公开接口负责区分概率和 logits，避免误把 logits 当概率。

## 4. 后向、后验与可微 CTC

### 4.1 后向的定义要与前向配套

βₜ(s) 定义为从当前状态 s 出发，**仅发射未来 t+1…T−1 帧**并完成目标的概率。它不包含当前帧，这是本实现的约定，不能直接混用包含当前帧的其他教材公式。

最后一帧的两个合法终态 β=1，其他为0。递推为：

\[
\beta_t(s)=\sum_{r\in\mathrm{next}(s)}p_{t+1}(l'_r)\beta_{t+1}(r)
\]

`next(s)` 包含 s、s+1，以及满足相同跳跃规则的 s+2。代码同样在对数域求和。

于是某帧处于状态 s、且最终输出目标的条件后验为：

\[
q_t(s)=\frac{\alpha_t(s)\beta_t(s)}{P(y\mid x)}
\]

同一类别可能在多个状态出现，必须把它们加起来：

\[
\gamma_t(k)=\sum_{s:l'_s=k}q_t(s)
\]

合法非零概率目标下，每帧 `Σₖγₜ(k)=1`，这是有意义的自检；它是**在已知训练目标条件下**的对齐后验，不能拿它当不含真值的预测输出。

### 4.2 从路径概率推导 logits 梯度

对 `−log P(y|x)` 求 `log pₜ(k)` 的偏导，可把路径求和中所有“第t帧取k”的项合并，得到 `−γₜ(k)`。

softmax 满足 `∂log pₜ(k)/∂zₜ(j)=1[k=j]−pₜ(j)`，因此：

\[
\frac{\partial\mathcal L}{\partial z_t(j)}
=-\sum_k\gamma_t(k)(\mathbf1_{k=j}-p_t(j))
=p_t(j)-\gamma_t(j)
\]

这很像普通交叉熵的 `p−oneHot`，区别是 one-hot 标签变成了对所有合法对齐求出的条件后验。

对于上面的三帧 `00`，只有一条合法路径，所以 γ 分别为 `[0,1,0]`、`[1,0,0]`、`[0,1,0]`，梯度为：

| t | blank梯度 | 数字0梯度 | 数字1梯度 | 行和 |
|---:|---:|---:|---:|---:|
| 0 | 0.2 | −0.3 | 0.1 | 0 |
| 1 | −0.2 | 0.1 | 0.1 | 0 |
| 2 | 0.1 | −0.2 | 0.1 | 0 |

梯度下降会增加合法路径所需类别的 logit。若存在多条对齐，γ 通常是软分布，不是人为硬指定的逐帧标签。

### 4.3 TensorFlow.js 的真实支持与实现边界

2026-09-08 在项目安装的 TensorFlow.js 4.22.0 上实测：`typeof tf.ctcLoss === 'undefined'`，`typeof tf.customGrad === 'function'`。因此没有写不存在的框架接口，而是：

1. 接收 `[B,T,K]` logits，读取小批次的数值。
2. 每条样本在 JS 对数域执行前后向，求出真实 CTC loss 和 `p−γ`。
3. 批次损失取算术平均，梯度相应除以 B。
4. `tf.customGrad` 保存该梯度张量，反向时乘以上游标量 dy。
5. 框架继续通过矩阵乘法、循环单元和卷积向参数反传。

```javascript
// 用单条[T,K] logits说明结构，target已在外部定义。
const { ctcLossAndGradient } = require('../shared/19-ctc-loss');
const operation = tf.customGrad((logits, save) => {
    const result = ctcLossAndGradient(logits.arraySync(), target);
    save([tf.tensor2d(result.gradient)]);
    return {
        value: tf.scalar(result.loss),
        gradFunc: (dy, saved) => [saved[0].mul(dy)]
    };
});
```

上段是单样本结构示意，正式批次接口为 `differentiableCtcLoss`，带完整校验和批平均。自定义梯度的机制依据 [TensorFlow.js 官方指南](https://www.tensorflow.org/js/guide/custom_ops_kernels_gradients)。

同步 `dataSync()` 会把数据交给 JS，在 GPU 后端可能阻塞，**不是高吞吐生产 CTC 内核**。该实现只提供经过验证的一阶梯度；保存的解析梯度已脱离高阶计算图，不应拿来声称支持 Hessian/二阶自动微分。

无合法路径时，纯数值评估返回 `loss=Infinity`、`possible=false`；训练接口抛出明确错误，避免悄悄以零梯度跳过样本。不要把 ∞ 随便截成某个常量掩盖图像宽度或标签错误。

### 4.4 真实小实验和验证

`node 19-ctc-loss/index.js` 从 `[1,3,3]` 全零 logits 开始，目标为连续两个数字0，Adam 学习率0.15，40步：

```text
更新前 CTC loss = 3.29583693
更新后 CTC loss = 0.01954518
贪婪路径索引     = [1,0,1]
折叠输出         = [1,1] → 字符串“00”
释放后张量数      = 0
```

初始时三帧每类概率1/3，唯一合法路径概率1/27，故初始损失恰好是 `ln(27)`。这证明 CTC 梯度能学习重复与blank，**只训练 logits，还没有图像模型**。

独立 Jest 用不同目标的中心差分核对每一个 logit 梯度，另查批平均、上游系数与内存释放。第20章报告中的9个坐标有限差分最大绝对误差为 `3.10×10⁻⁸`，并继续核对了卷积参数的真实梯度。

## 5. 贪婪与 Prefix Beam：解码时不需要目标

### 5.1 贪婪解码

先逐帧选最大概率类别，再折叠：

\[
\hat\pi_t=\arg\max_k p_t(k),\quad\hat y=B(\hat\pi)
\]

这是条件独立路径模型下的最佳**路径**，计算 O(TK)。但最大路径所属的字符串不一定拥有最大的路径总和。

代码出现概率平局时保留较小类别索引，确保可复现。返回 `logProbability` 是被选中路径的分数，不是整个字符串的总概率，更不是预测正确率。

### 5.2 一个贪婪失败、beam成功的手算

两帧的概率都为 `[blank=0.4, a=0.35, b=0.25]`。贪婪选 blank、blank，输出空串，路径概率0.16。

字符串 a 的总概率却是：

```text
(a,a)       0.35×0.35 = 0.1225
(a,blank)   0.35×0.40 = 0.1400
(blank,a)   0.40×0.35 = 0.1400
总概率                  0.4025 > 0.16
```

所以此例最佳字符串是 a。切换浏览器“贪婪与beam不同”即可复现，修改目标标签不会改变这两个解码结果。

### 5.3 为什么每个前缀需要两个分数

Prefix beam 为每个已折叠前缀 l 保存：

- `pb(l)`：本帧路径以 blank 结束的总概率。
- `pnb(l)`：本帧路径以非blank结束的总概率。

不能只存一个分数，因为新增相同字符时，是否经过 blank 决定它是“延长当前字符”还是“新增一个重复字符”。

初始空前缀 `pb=1、pnb=0`。每来一帧，对每个前缀执行：

1. 发射 blank：`pb'(l) += [pb(l)+pnb(l)]p(blank)`。
2. 发射 k 且 k 不同于末字符：`pnb'(l+k) += [pb(l)+pnb(l)]p(k)`。
3. 发射 k 且 k 等于末字符：`pnb'(l) += pnb(l)p(k)`；同时 `pnb'(l+k) += pb(l)p(k)`。
4. 同名新前缀要合并概率，再按 `pb'+pnb'` 排序，仅保留前 beamWidth 个。

所有加法在代码里用 LSE，初始 `log pb=0、log pnb=−∞`。不是简单保留若干条原始路径的普通 beam；**合并同一个标签前缀**是核心。

### 5.4 束宽、准确性与复杂度

| 解码方式 | 计算特点 | 适用情况 | 局限 |
|---|---|---|---|
| Greedy | 每帧argmax，O(TK) | 快速基线、模型输出很尖锐时 | 忽略同串多路径的总概率 |
| Prefix beam | 每帧扩展 M 个前缀与 K 类，再排序 | 输出不确定，希望聚合对齐 | 有剪枝近似，不保证最优 |
| 全枚举 | Kᵀ 条路径 | 小矩阵的正确性检查 | 指数成本，不能用于长序列 |

M 是束宽。本实现还复制、序列化前缀，排序也有额外成本，不能只用 O(TMK) 完整描述 JS 实际性能。束越宽通常保留更多质量，所返回某个字符串的累计概率仍可能低于其完整概率；增大束宽不是正确率必然上升的承诺。

此处不接语言模型、不使用词典、不限制输出为训练目标。任意数字串应保留前导零和重复数字，不能为“看起来更合理”修改结果。

关键共享 API：

```javascript
const ctc = require('../shared/19-ctc-loss');
const p = [[0.2,0.7,0.1], [0.8,0.1,0.1], [0.1,0.8,0.1]];
ctc.ctcForwardBackward(p, [1,1]); // 默认blank=0
// {loss, probability, logProbability, possible, minimumFrames,
//  extended, alpha, beta, posterior}
ctc.greedyDecode(p); // {path, labels, logProbability}
ctc.prefixBeamDecode(p, 0, 20); // 已排序的{labels,logProbability,probability}数组
// logits是未经softmax的有限数值[T,K]数组
ctc.ctcLossAndGradient(p.map(row => row.map(Math.log)), [1,1]);
// TensorFlow.js批次接口，返回调用者负责释放的scalar
// ctc.differentiableCtcLoss(tf, logitsTensor[B,T,K], targets[B], blank)
```

概率矩阵必须矩形、K≥2、所有值在[0,1]，行和容差 `1e-6`；不会自动把错误概率归一化。概率、logits、路径和目标的数组都必须填满数值，JavaScript 稀疏数组的空槽不会当作0。目标不能包含 blank；beamWidth 必须为正整数。当前批次所有样本使用同一 T，不提供 `inputLengths` 或补齐帧遮罩；变宽批次留到更完整实现。

## 7. 排障与模型边界

| 现象 | 先检查 | 原因与处理 |
|---|---|---|
| `00` 被合成 `0` | 是否先删blank、后去重 | 折叠顺序错；对照 `[1,0,1]` |
| loss=∞ | T与U+r、是否有精确零概率 | 宽度压缩过度或目标概率为0；不要静默清零 |
| 训练只出blank | 初始类别分布、训练步数、数据与梯度 | blank可占多数帧；观察损失和逐帧输出，不能只看argmax |
| DP与枚举不同 | 初始化、最后两个状态、重复skip规则 | 逐帧打印α，先用T=2/3小例子定位 |
| 梯度方向异常 | beta是否包含当前帧、同类状态是否求和 | 不一致会重复计算发射概率或漏掉后验 |
| beam分数变化 | 束宽、前缀合并、剪枝 | 剪枝结果是近似；不把概率当校准置信度 |
| Node训练可跑但GPU很慢 | `dataSync`同步 | 当前CTC是CPU教学桥接，换后端不等于有原生CTC核 |

CTC 假设标签与帧有单调顺序，适合文字行、语音帧。它不擅长本质非单调的重排，也没有自回归字符依赖模型。换用 Attention 并不是自动更准确，而是改变对齐和输出建模假设。

## 8. 自测与答案

**题1：** 路径 `[1,1,0,1,2,2]`，blank=0，输出是什么？

**答：** `[1,1,2]`，按本章数字映射是“001”。先合并路径重复得到 `[1,0,1,2]`，再删blank。

**题2：** 真值“000”至少需要几帧？若T=4，应该返回什么？

**答：** U=3、r=2，至少5帧；评估概率0、loss=∞、possible=false；训练接口明确报错。

**题3：** 为什么α递推中有时不能使用s−2？

**答：** 当前状态为blank不能这样跳；当前字符与s−2相同也不能跳，否则没有blank分隔的重复会被错误当成两个字符。

**题4：** 两帧都为 `[0.4,0.35,0.25]`，贪婪输出是什么？字符a总概率多少？

**答：** 贪婪输出空串；a概率`0.35²+2×0.35×0.4=0.4025`，大于空串0.16。

**题5：** 为什么 CTC logits 梯度每帧行和为0？

**答：** `Σ(p−γ)=1−1=0`。所有logit同时加常数不会改变softmax，梯度应与该方向正交。

**题6：** 已知目标算出的后验γ可以直接拿来当预测吗？

**答：** 不能。γ条件化了真值，用它输出会泄漏答案；解码仅接收模型概率矩阵。

**题7：** 页面把目标从“00”改为“01”，哪些量应变化？

**答：** 损失、扩展状态、α、β、后验和梯度可能变化；原始概率、贪婪与prefix beam的结果应保持不变。

**题8：** 可微 CTC logits 小实验成功，是否证明 CRNN 已训练？

**答：** 没有。它还没有图像和CNN/RNN参数；第20章需要检查损失经过整个图像模型的梯度与权重更新。
