## 核心概念

### 1. 什么是灰度图？

前两章中，一个彩色像素有 R、G、B 三个颜色值，以及单独的 A 透明度。灰度化要回答的是：**用一个从黑到白的数，概括这个像素的颜色，该怎么算？**

这个数叫 Gray（灰度值），本章范围是 0–255：
- **0** = 纯黑
- **255** = 纯白
- 中间值 = 不同程度的灰色

```
彩色图像（3通道）         灰度图像（1通道）
┌─────────────────┐      ┌─────────────┐
│ R: 255          │      │             │
│ G: 128          │  →   │ Gray: 159   │
│ B: 64           │      │             │
└─────────────────┘      └─────────────┘
```

### 2. 为什么要灰度化？

| 原因 | 说明 |
|------|------|
| **降低复杂度** | 只处理一个强度量；紧凑 RGB→单通道才减少 2/3 存储，RGBA 不变 |
| **去除颜色干扰** | 很多文字识别可用强度形状；彩色文字与背景可能灰度相同而丢失信息 |
| **简化后续处理** | 二值化、边缘检测等操作更简单 |
| **提高处理速度** | 后续计算可以只读一个通道，收益取决于具体算法 |

### 3. 灰度化算法

下面几种方法都处理同一个像素 `RGB(255,128,64)`：R=255、G=128、B=64。先只算颜色，透明度留到结果写回时处理。每种方法的 Gray 都是一个数，最终复制到 R、G、B 三个位置，画面就会显示为灰色。

#### 算法一：平均值法 (Average)

```
Gray = (R + G + B) / 3
```

**特点**：简单快速，但不符合人眼感知

#### 算法二：加权平均法 (Weighted Average) ⭐ 推荐

```
Gray = 0.299 × R + 0.587 × G + 0.114 × B
```

三个权重相加等于 1，所以黑色仍为 0，白色仍为 255。绿色通道的系数最大，这体现了该标准对不同原色的亮度贡献的定义；不能把这些系数理解成眼睛里三种细胞的数量比例。

把同一个输入代入，可以看到每个通道贡献了多少：

| 步骤 | 计算 | 结果 |
|---|---|---|
| 红通道贡献 | `0.299×255` | 76.245 |
| 绿通道贡献 | `0.587×128` | 75.136 |
| 蓝通道贡献 | `0.114×64` | 7.296 |
| 相加 | `76.245+75.136+7.296` | 158.677 |
| 写成整数灰度 | `Math.round(158.677)` | **159** |

这就是前面示意图中 159 的来历。平均值法对同一像素计算 `(255+128+64)/3=149`，两种方法结果不同，是因为“每种颜色占多大权重”的规则不同。

#### 加权编码值与线性光亮度：为什么还会有另一套公式？

上面的 0.299、0.587、0.114 来自 BT.601 的 luma（编码亮度信号）定义。本课程直接把它们用于 sRGB 数字，是一种常见的快速灰度近似。它适合本章的处理流程，但数字不直接表示光强：sRGB 的 128 看似接近 255 的一半，对应的相对线性亮度却约为 0.216。

如果要算物理意义更明确的**相对亮度 Y**，需要三步。这里的 Y 是一个 0–1 的数，与图像纵坐标 y 无关。

1. **解码每个通道。** 先令 `c=通道值/255`，把 0–255 换成 0–1，再用下式转换成与光强成比例的数。f 是“解码函数”的名字。

```text
f(c) = c/12.92                         当 c ≤ 0.04045
     = ((c+0.055)/1.055)^2.4           其他情况
```

2. **计算亮度。** 使用 sRGB 对应的权重，把三个已解码的数相加。

```text
Y = 0.2126×f(R/255) + 0.7152×f(G/255) + 0.0722×f(B/255)
```

3. **转回屏幕能显示的灰度数。** 亮度 Y 还不是应直接写入 RGB 的编码值，要经过编码函数 g，再乘 255、取整。

```text
g(Y) = 12.92×Y                        当 Y ≤ 0.0031308
     = 1.055×Y^(1/2.4)−0.055          其他情况
Gray = round(255×g(Y))
```

为让这三步容易手算，这里换用**纯红色 `(255,0,0)`**：解码后为 `(1,0,0)`，Y=0.2126，编码回中性灰约为 127。同一个纯红色用快速加权法则是 `round(0.299×255)=76`。两者定义不同；切换方法后，不能直接沿用未经验证的二值化阈值。

代码里 `grayscaleLinearSrgb` 对应完整三步；旧名 `grayscaleLuminosity` 只用另一组系数直接加权编码值，并没有先解码。阅读时认准实际步骤，比只看函数里的“亮度”一词更可靠。

#### 算法三：最大值法 (Maximum)

```
Gray = max(R, G, B)
```

**特点**：保留最亮的通道，结果偏亮

#### 算法四：最小值法 (Minimum)

```
Gray = min(R, G, B)
```

**特点**：保留最暗的通道，结果偏暗

#### 算法五：单通道法 (Single Channel)

```
Gray = R  (或 G 或 B)
```

**特点**：只取一个通道，适合特定场景

### 4. 灰度直方图：把每一种灰色出现的次数数出来

先换用一张已灰度化的四像素小图，灰度为 `[0,0,100,200]`。直方图相当于准备 256 个计数格：第 0 格数灰度 0 出现几次，第 100 格数灰度 100 出现几次。

| 灰度 g | 计数 h[g] | 占全部像素的比例 |
|---|---|---|
| 0 | 2 | 2/4=50% |
| 100 | 1 | 1/4=25% |
| 200 | 1 | 1/4=25% |
| 其他值 | 0 | 0% |

g 是正在统计的灰度值；h 是直方图数组；h[g] 是计数，不是亮度。把所有格子的计数相加，得到像素总数 N=4。画图时横轴是 g，纵轴可以画计数或比例，必须标清是哪一种。

直方图保留了“有多亮”，却丢掉了“在哪里”：把四个像素改排成 `[200,0,100,0]`，直方图完全不变。第 04 章 Otsu 利用这个分布选全局阈值，因此它看不见文字在图中的位置。

### 5. 从直方图读统计量，再检查这些数字是否有意义

仍用 `[0,0,100,200]`，各项统计可以逐个核对：

| 统计量 | 计算 | 它说明什么 |
|---|---|---|
| 均值 | `(0×2+100×1+200×1)/4=75` | 全部灰度的平均水平 |
| 中位数 | 排序后中间两个数 `(0+100)/2=50` | 一半数据位于它两侧，不必等于某个像素值 |
| 众数 | 0 出现两次，最多 | 最常见的灰度 |
| 总体方差 | `[2×(0−75)²+(100−75)²+(200−75)²]/4=6875` | 灰度偏离均值的平方平均 |
| 总体标准差 | `√6875≈82.916` | 把方差开方，回到灰度值的单位 |

一般写法是 `均值=Σg·h[g]/N`，其中 Σ 表示“对 0–255 每种灰度求和”。方差相应为 `Σh[g]·(g−均值)²/N`。这里在描述整张图的像素总体，用 N 作分母；不是估计未知总体时常见的 N−1。众数并列时课程函数取较小灰度；空图没有可用的均值，统计函数会报错。

**统计之前先处理透明背景。** 例如 `[0,0,0,0]` 放在白底上看起来是白色，如果只读 R=0，却会把它计入黑色。灰度函数只改 RGB、保留 A，不自动叠加背景。本章实验上传时先合成白底，再灰度化，这样统计与眼睛看到的画面才一致。

**只读 R 的前提是已经灰度化。** 灰度化后每像素的 R=G=B，读任意一个都能拿到 Gray。比如不透明彩色像素 `[255,128,64,255]` 变成 `[159,159,159,255]` 后，直方图只给第 159 格加 1，而不是把三个通道计成三个像素。它仍占四字节，只是三个颜色通道内容相同。

**颜色差别可能消失。** 快速公式把纯红色变成灰度 76，也把中性灰 `(76,76,76)` 变成 76。如果文字与背景恰好是这两种颜色，下一章无论怎样调灰度阈值，都找不回已经丢掉的色差。这时需要回到彩色图，尝试适合该颜色的单通道或其他颜色特征。

## 与 OCR 的关联

灰度化是 OCR 预处理流水线的第一步：

```
彩色图像 → [灰度化] → 灰度图像 → [二值化] → 二值图像 → [后续处理]
              ↑
           当前学习
```

| 作用 | 说明 |
|------|------|
| 数据预处理 | 统一输入格式，简化后续算法 |
| 降低干扰 | 去除颜色对文字识别的影响 |
| 性能优化 | 每像素只需分析一个灰度量；本项目仍保留 RGBA |

## 自测问题

1. 为什么 RGB(255,128,64) 的加权灰度是 159？
2. 算出灰度后，为什么直方图可以只读 R？
3. `[0,0,100,200]` 的均值、中位数和众数分别是多少？
4. 同一组像素重新排列，直方图会改变吗？
5. 为什么透明黑不能直接当作黑字计数？
6. 纯红色的灰度为什么既出现 76，又出现约 127？

<details>
<summary>展开答案与计算依据</summary>

1. `0.299×255+0.587×128+0.114×64=158.677`，取整为 159。
2. 灰度值被复制到 R、G、B，三者相等；每像素只数一次，不能把三个通道当三个像素。
3. 均值 75，中位数 `(0+100)/2=50`，众数 0。三者描述的特征不同。
4. 不会，计数没有变化；直方图不保留像素位置。
5. `[0,0,0,0]` 在白底上显示为白色；直接读取 R=0 会误计为黑色。应先按用途合成背景。
6. 76 来自直接加权编码值；约 127 来自 sRGB 解码、计算线性亮度、重新编码。它们不是同一计算，不能混用阈值。

</details>
