## 核心概念

### 1. 什么是灰度图？

灰度图是只有一个通道的图像，每个像素用一个值（0-255）表示灰度编码值（本章默认 8-bit sRGB）：
- **0** = 纯黑
- **255** = 纯白
- 中间值 = 不同程度的灰色

```
彩色图像（3通道）         灰度图像（1通道）
┌─────────────────┐      ┌─────────────┐
│ R: 255          │      │             │
│ G: 128          │  →   │ Gray: 159   │
│ B: 64           │      │             │
└─────────────────┘      └─────────────┘
```

### 2. 为什么要灰度化？

| 原因 | 说明 |
|------|------|
| **降低复杂度** | 只处理一个强度量；紧凑 RGB→单通道才减少 2/3 存储，RGBA 不变 |
| **去除颜色干扰** | 很多文字识别可用强度形状；彩色文字与背景可能灰度相同而丢失信息 |
| **简化后续处理** | 二值化、边缘检测等操作更简单 |
| **提高处理速度** | 后续计算可以只读一个通道，收益取决于具体算法 |

### 3. 灰度化算法

#### 算法一：平均值法 (Average)

```
Gray = (R + G + B) / 3
```

**特点**：简单快速，但不符合人眼感知

#### 算法二：加权平均法 (Weighted Average) ⭐ 推荐

```
Gray = 0.299 × R + 0.587 × G + 0.114 × B
```

**特点**：
- 基于人眼对颜色的敏感度
- 人眼对绿色最敏感（权重 0.587）
- 对红色次之（权重 0.299）
- 对蓝色最不敏感（权重 0.114）
- 系数来自 BT.601 的 luma 定义；本项目直接用于编码 sRGB，是常见快速近似，不是严格的线性光亮度计算

**可核对算例**：`RGB(255,128,64)` 的加权结果为 `76.245 + 75.136 + 7.296 = 158.677`，按本课程 `Math.round` 得到 **159**；平均值为 149，最大值 255，最小值 64。

#### 加权编码值与线性光亮度的区别

RGB 数字首先是编码值，不直接正比于光强。BT.601/709 的 luma 系数不能简单解释为三种视锥细胞的比例。对 sRGB 计算相对亮度要先解码。令 `c = channel / 255`：

```
f(c) = c / 12.92                         (c ≤ 0.04045)
     = ((c + 0.055) / 1.055)^2.4         (c > 0.04045)
Y = 0.2126 f(R/255) + 0.7152 f(G/255) + 0.0722 f(B/255)
```

Y 在 [0,1]，是相对线性亮度。若要显示为 sRGB 中性灰，再编码 `g(Y)=12.92Y`（Y≤0.0031308），否则 `g(Y)=1.055Y^(1/2.4)-0.055`，输出 `round(255g(Y))` 到 R/G/B。

纯红色的快速 BT.601 加权结果为 76；线性亮度 Y=0.2126，重新编码的中性灰约为 127。它们目的和定义不同，不能混用数值阈值。`grayscaleLinearSrgb` 实现后一流程；旧名 `grayscaleLuminosity` 仅为 BT.709 系数的编码值加权近似。sRGB 灰色 128 的线性亮度约 0.216，重新编码仍是128。

#### 算法三：最大值法 (Maximum)

```
Gray = max(R, G, B)
```

**特点**：保留最亮的通道，结果偏亮

#### 算法四：最小值法 (Minimum)

```
Gray = min(R, G, B)
```

**特点**：保留最暗的通道，结果偏暗

#### 算法五：单通道法 (Single Channel)

```
Gray = R  (或 G 或 B)
```

**特点**：只取一个通道，适合特定场景

### 4. 灰度直方图

灰度直方图统计图像中每个灰度值（0-255）出现的次数。

```
频率
 │
 │    ▓▓
 │   ▓▓▓▓
 │  ▓▓▓▓▓▓▓
 │ ▓▓▓▓▓▓▓▓▓▓
 └──────────────── 灰度值
   0     128    255
```

**用途**：
- 分析图像亮度分布
- 选择二值化阈值
- 图像增强

---

### 5. 统计口径、透明背景和信息损失

直方图 `h[g]` 是计数，长度256，`N=Σh[g]`；相对频率为 `h[g]/N`。均值为 `Σg h[g]/N`，总体标准差为 `sqrt(Σh[g](g-mean)²/N)`，不是样本标准差的 N−1 分母。排序中位数在偶数 N 时取中央两个值的平均，例如 `[0,255]` 的中位数为127.5；众数并列时返回最小灰度。空直方图不能计算这些统计量，会明确报错。

灰度化函数只修改 RGB，保留 alpha，不自动合成背景。直方图只读 R 并按一个像素一次计数，不按透明度加权，因此要求有意义的灰度输入；本章 HTML 上传时先合成白底再灰度化，使画面和统计一致。透明黑若直接忽略 alpha，会被误当作黑字。灰度化后的 R=G=B，仍是 `H×W×4` 字节的 RGBA；逻辑单通道不等于存储单通道。

颜色也可能是有用信息：`RGB(255,0,0)` 与中性灰 `(76,76,76)` 在本快速公式下相同，二值化无法恢复已经消失的色差。

## 与 OCR 的关联

灰度化是 OCR 预处理流水线的第一步：

```
彩色图像 → [灰度化] → 灰度图像 → [二值化] → 二值图像 → [后续处理]
              ↑
           当前学习
```

| 作用 | 说明 |
|------|------|
| 数据预处理 | 统一输入格式，简化后续算法 |
| 降低干扰 | 去除颜色对文字识别的影响 |
| 性能优化 | 每像素只需分析一个灰度量；本项目仍保留 RGBA |

1. 为什么加权公式中绿色的权重最大？

4. 在 OCR 预处理中，为什么灰度化要在二值化之前？

<details>
<summary>点击查看答案</summary>

1. 标准原色与亮度定义下绿色系数最大；不能把 0.299/0.587/0.114 当作三类视锥细胞数量或敏感度比例。
2. 0.299 × 255 + 0.587 × 0 + 0.114 × 0 ≈ 76
3. 分析亮度分布、选择二值化阈值、图像增强
4. 本课程阈值算法比较标量灰度；也可以直接对单个颜色通道阈值化，灰度化不是所有 OCR 系统的强制步骤。
