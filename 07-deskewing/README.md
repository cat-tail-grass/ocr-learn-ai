# 07. 倾斜校正 (Deskewing / Skew Correction)

## 学习目标

文档图像经常因为拍摄角度或扫描不当而产生倾斜，这会严重影响 OCR 识别效果。本章将帮助你掌握：

1. **倾斜的概念** - 什么是文档倾斜，为什么需要校正
2. **投影分析法** - 通过水平投影方差检测倾斜角度（重点）
3. **霍夫变换** - 检测图像中的直线来确定倾斜角度
4. **仿射变换** - 图像旋转的数学基础
5. **双线性插值** - 旋转后像素值的计算方法
6. **完整的倾斜校正流程** - 从检测到校正的完整实现

## 核心概念

### 1. 倾斜校正要回答两个不同的问题

假设一行文字从左到右逐渐向下偏，行尾落到了下一行的高度。第 10 章若直接按“每一行有多少黑像素”切分，就容易把不同文字行混在一起。我们希望先把整页文字摆正。

这里分成两步：**检测**负责估计该转多少角度；**旋转**负责生成转动后的像素图。检测结果是一个数，旋转结果才是一张图。这两步不能混为一谈。

本章处理的是整页文字共同偏转几度的情况。纸张近大远小的透视变形、弯曲书页，以及整页横躺 90°，需要额外的方法；一次小角度旋转不能解决所有拍摄问题。

#### 先约定坐标和角度，避免“校正后更歪”

像素坐标从左上角 `(0,0)` 开始，x 向右、y 向下。`W` 是宽度、`H` 是高度。共享函数 `rotateImage(image, angle)` 的角度单位是度，**正角度表示视觉上的逆时针旋转**。

本章用 `s` 表示输入倾斜角，`c` 表示为了摆正它要施加的校正角，理想情况下 `c=−s`：

| 情况 | 输入倾斜角 s | 应用的校正角 c |
|---|---:|---:|
| 原图被逆时针转了 5° | +5° | −5°，顺时针转回去 |
| 文字行向右下方倾斜 5° | −5° | +5°，逆时针转回去 |
| 已经水平 | 0° | 0° |

`detectSkewAngle(...).angle` 返回的已经是 **c，校正角**，可以直接传给 `rotateImage`。返回字段 `skewAngle` 才是 `−c`。先记住它返回哪一个角，再看下面的搜索过程，就不容易多取一次负号。

### 2. 投影分析法：试着转动，看文字行是否更集中 ⭐

#### 水平投影究竟统计什么

先把图像变成黑字白底的二值图。对于每一行，从左到右数黑像素，把数量记在一个数组里。这个数组叫**水平投影**。它只记录“每行有多少墨迹”，不记录墨迹具体在那一列。

```text
示意图（# 是黑色前景，. 是白色背景）    每行黑像素数
....                                  0
####                                  4
....                                  0
####                                  4
投影数组 P = [0,4,0,4]
```

行与行之间有空白时，投影容易出现明显的高峰和低谷。文字倾斜后，同一行笔画散落到更多像素行，原来的空白行也混入文字，峰谷往往没那么分明。

#### 用方差给“峰谷分明”一个分数

**方差**衡量一组数离平均值有多远。这里的数就是每行黑像素数量，方差越大，意味着行与行之间的墨迹数量差异越大。

令 `P[y]` 为第 y 行的黑像素数，数组长度就是图高 H；`μ`（mu）为所有行的平均黑像素数：

```text
μ = (P[0] + P[1] + … + P[H−1]) / H
方差 = Σ(y=0…H−1) (P[y]−μ)² / H
```

用两组总墨迹相同的投影说明这个分数：

| 投影 | 均值 | 平方偏差的平均值 | 方差 |
|---|---:|---|---:|
| `[0,4,0,4]` | 2 | `(4+4+4+4)/4` | 4 |
| `[1,3,1,3]` | 2 | `(1+1+1+1)/4` | 1 |

第一组墨迹更集中，分数也更高。这是解释评分的两个小例子，并不是声称某张图旋转后必定恰好产生第二个数组。规整的多行文本经常符合这种趋势，图形、单字或多栏排版可能不符合。

#### 怎样从评分得到校正角

对输入图分别尝试若干角度，例如从 −15° 到 +15°，每隔 1° 试一次：

1. 旋转一份输入图，得到候选图。
2. 数候选图每行的黑像素，得到投影数组。
3. 算投影方差，把“试转角、方差”一起记录。
4. 选方差最大的试转角，作为校正角 c。

```javascript
// 概念代码：每次都旋转原输入，不能在上一次旋转结果上继续累加。
let bestCorrection = 0;
let bestScore = -Infinity;
for (const angle of candidateAngles) {
    const candidate = rotateImage(binaryImage, angle, 'nearest');
    const projection = calculateHorizontalProjection(candidate);
    const score = calculateProjectionVariance(projection);
    if (score > bestScore) {
        bestScore = score;
        bestCorrection = angle;
    }
}
```

这里 `candidateAngles` 是准备尝试的角度列表，`binaryImage` 是待校正二值图。假设试转 −4° 时分数最高，−4° 就是这次找到的校正角。它不是“原图歪了 −4°”，因此不能再反过来转 +4°。

共享实现会先粗搜，再在粗搜最佳角度左右各一个粗步长内细搜，例如先隔 1° 找到约 −4°，再在 −5° 到 −3° 内隔 0.1° 尝试，并限制在原搜索范围内。两阶段都包含端点；分数相同时优先选择绝对值较小的角度。细化区间在循环开始前固定，不会随着候选结果不断漂移。

### 3. 霍夫变换：让支持同一条直线的像素一起投票

投影法通过“试转后是否更整齐”间接判断方向。霍夫变换（Hough Transform）换一个思路：寻找图中有许多像素共同支持的直线，再用直线的方向推断倾斜。

#### 为什么要用 ρ 和 θ 表示直线

`y=kx+b` 用斜率 k、截距 b 表示直线，但垂直线没有有限斜率。霍夫变换使用法线表示法：

```text
ρ = x×cos(θ) + y×sin(θ)
```

`(x,y)` 是直线上的点。**法线**是垂直于这条直线的方向；`θ`（theta）是法线与 x 轴的夹角，`ρ`（rho）是从原点沿这条法线到直线的带符号距离，单位为像素。θ 表示的是垂线方向，不是文字行本身的方向。

看一条水平线 `y=2`：法线朝下，`θ=90°`，于是 `cos(θ)=0,sin(θ)=1`，公式变成 `ρ=y=2`。这条线上的 `(0,2)`、`(1,2)`、`(2,2)` 都会算出同样的 `(ρ=2,θ=90°)`。

#### “累加器”就是一张计票表

把 θ 按角度分格、ρ 按距离分格，建一个二维计数表，叫**累加器（accumulator）**。每个黑像素依次尝试所有 θ，算出对应 ρ，在对应格子加一票。

```text
像素 (0,2)，尝试 θ=90° → ρ=2 → 表格 (90°,2) 加 1
像素 (1,2)，尝试 θ=90° → ρ=2 → 同一个格子再加 1
像素 (2,2)，尝试 θ=90° → ρ=2 → 同一个格子再加 1
结果：该格子有 3 票，三个像素共同支持 y=2 这条线。
```

从图像空间看，这些是共线的点；从 `(ρ,θ)` 参数空间看，每个点随 θ 变化画出一条曲线，曲线在同一个参数处相交。交点票数越高，支持该直线的像素越多。

本章对每个 θ 取它所有 ρ 格子中的最大票数作为分数，即 `score(θ)=maxρ accumulator(θ,ρ)`。`maxρ` 的意思是固定 θ，沿距离方向找最高的一格。不能把这一列的票数全相加来选角：每个黑像素对每个 θ 都投一票，加总后所有角度都是同样的黑像素总数。

#### 从法线角换成校正角

在本章 x 向右、y 向下、正旋转为视觉逆时针的约定下，水平附近的线对应：

```text
校正角 c = θ − 90°
```

水平线的 `θ=90°`，得到 c=0°；向右下倾斜 5° 的线，其法线 θ=95°，得到 c=+5°，需要逆时针转回水平。

当前实现只用最强直线作简化评分，没有完整的多峰筛选和多文字行统计。表格边框如果比文字更长、更直，可能获得更多票，把结果带偏。实验中应同时看投票曲线和原图中的实际线条。

### 4. 图像旋转：先搬坐标，再决定颜色

#### 仿射变换与绕中心旋转

仿射变换是一类保持直线、平行关系的坐标变换，平移、旋转、缩放都是例子。本章只需要其中的旋转。

若直接绕左上角旋转，整张图容易跑出画布，所以先把原点移到图像中心。像素中心坐标从 0 到 `W−1`、从 0 到 `H−1`，图像中心为：

```text
cx = (W−1)/2
cy = (H−1)/2
```

3×3 图的中心是 `(1,1)`；4×4 图的中心是 `(1.5,1.5)`，落在四个像素中间也正常。把原坐标相对中心的距离记为 `dx=x−cx,dy=y−cy`，正向旋转公式是：

```text
x' = cx + dx×cos(θ) + dy×sin(θ)
y' = cy − dx×sin(θ) + dy×cos(θ)
```

`(x',y')` 表示转动后的坐标，θ 是旋转角。这个正负号与图像 y 向下有关。以 3×3 图为例，中心右边的点 `(2,1)` 旋转 +90° 后变为中心上方 `(1,0)`，可以用它检查旋转方向。

矩阵形式是 `[x',y']ᵀ=R[x,y]ᵀ+t`，其中 R 的两行为 `[cosθ,sinθ]` 和 `[−sinθ,cosθ]`，t 为平移量；绕中心时 t 由上面的中心坐标决定。矩阵只是把两条坐标公式合写起来。

#### 为什么实际代码反过来找原图位置

原图整数坐标经过旋转通常变成小数，比如某个像素落到目标的 `(3.4,2.7)`。如果直接取整后“扔到新位置”，可能多个输入落到同一格，也可能有格子没人填，出现空洞。

**逆向映射**会逐一访问输出图的每个整数位置，反问“这个位置在原图中来自哪里”。设输出位置为 `(x_dst,y_dst)`，反算出的原图位置为 `(x_src,y_src)`：

```text
x_src = (x_dst−cx)×cos(θ) − (y_dst−cy)×sin(θ) + cx
y_src = (x_dst−cx)×sin(θ) + (y_dst−cy)×cos(θ) + cy
```

还用 3×3 图转 +90° 的例子：输出位置 `(1,0)` 相对中心是 `(0,−1)`，逆算得到 `(2,1)`，正好回到原图中心右边。θ=0° 时，逆算结果等于原坐标，因此零度旋转应逐像素保持不变，包括最右列、最下行和 1×1 图。

JavaScript 的 `Math.sin`、`Math.cos` 接受弧度，函数内部先用 `弧度=度数×π/180` 转换。API 仍传度数，不必在调用前再转一次。

### 5. 插值：原图的小数坐标该是什么灰度

反算得到 `(3.7,2.3)` 时，原图里没有这个整数像素。插值就是根据附近真实像素估计这个小数位置的值。

#### 最近邻：选离它最近的一个像素

把 `(3.7,2.3)` 四舍五入为 `(4,2)`，直接拿这个像素的值。计算简单，也能让 0/255 二值图仍然只有 0/255，但转斜的线条可能出现台阶状锯齿。搜索角度时，本章使用最近邻，避免每次试转都引入中间灰度。

#### 双线性：先沿两行插值，再在两行之间插值

设原图采样点为 `(x=3.25,y=2.5)`。它位于列 3 与 4、行 2 与 3 之间，四个角的灰度如下：

```text
                 x=3             x=4
          y=2    Q11=0           Q12=100
                       ● (3.25,2.5)
          y=3    Q21=200         Q22=240
```

Q11、Q12、Q21、Q22 只是四个角的名字。令 `u=x−3=0.25` 表示从左往右走了一个像素间距的四分之一；`v=y−2=0.5` 表示从上往下走了一半。

```text
先在上面一行取值：R1=(1−u)×Q11+u×Q12=0.75×0+0.25×100=25
再在下面一行取值：R2=(1−u)×Q21+u×Q22=0.75×200+0.25×240=210
最后在两行之间取值：P=(1−v)×R1+v×R2=0.5×25+0.5×210=117.5
输出灰度：四舍五入为 118
```

这里 R1、R2 是两次横向插值的临时结果，与 RGBA 的 R 通道无关；P 是最终插值结果。离哪一个角近，那个角的权重就更大。展开后就是四角加权和：

```text
P = (1−u)(1−v)Q11 + u(1−v)Q12 + (1−u)vQ21 + uvQ22
```

四个权重之和为 1。这与第 05 章的加权平均相似，但权重由采样点的小数位置决定，而不是使用固定高斯核。公式假设相邻整数坐标的间距为 1。

#### 双三次与边界的取舍

双三次插值参考周围 16 个像素，用三次函数估计值，可以改善平滑度并保留部分细节，但计算更多，某些核还会产生过冲或振铃。本章只介绍概念，代码未实现。

共享旋转函数支持最近邻和双线性，图外用指定的常量背景填充，默认白色 255。输出画布仍是原宽高，所以非零角旋转可能裁掉角落内容；“所有输出格子都有值”不等于“所有原图内容都保住了”。双线性会产生中间灰度，若下一步要求严格的二值输入，要再二值化。

### 6. 把检测与旋转接起来

```text
彩色图 → 灰度化 → 二值化 → 角度检测 → 校正角 c → 旋转 → 校正后的图像
```

灰度化、二值化是调用前的准备工作。`deskew` 接收准备好的二值图，内部调用投影法或霍夫法，然后直接使用检测返回的校正角旋转。示例：

```javascript
const result = deskew(binaryImage, {
    method: 'projection',
    minAngle: -15,
    maxAngle: 15,
    step: 1,
    refineStep: 0.1,
    interpolation: 'bilinear',
});
// result.imageData：校正图
// result.angle 与 result.correctionAngle：本次实际施加的旋转角
```

观察实验时，把输入、评分曲线和校正图一起看。若最高分落在搜索边界，可能是范围不够，也可能是文字之外的图形在影响评分；若图片已经摆正，却被继续旋转，要先确认角度的含义及输入是否适合这种评分方法。

## 在 OCR 中的应用

倾斜校正在 OCR 预处理链中的位置：

```
彩色图 → 灰度图 → 二值图 → 去噪 → 形态学 → [倾斜校正] → 文字检测 → 文字识别
                                                ↑
                                           当前学习
```

### OCR 中倾斜校正的注意事项

| 场景 | 处理建议 |
|------|---------|
| 小角度倾斜 (±5°以内) | 使用细步长检测（如 0.1°） |
| 大角度倾斜 (5°-15°) | 使用粗步长 + 细化（先 1° 再 0.1°） |
| 90° 倍数倾斜 | 先检测是否需要 90° 旋转 |
| 透视变形 | 需要透视校正（超出本章范围） |

### 性能优化技巧

```
1. 缩小图像检测角度
   - 检测阶段使用缩小的图像（如 1/4 尺寸）
   - 旋转阶段使用原始图像

2. 两阶段检测
   - 第一阶段：粗搜索（-15° 到 +15°，步长 1°）
   - 第二阶段：细搜索（最佳角度 ±粗步长，并限制在原搜索范围，步长 0.1°）

3. 缓存三角函数
   - 预计算 sin(θ) 和 cos(θ)
   - 避免在循环中重复计算
```

## 搜索评分的限制

全白图没有文字方向，全黑图也没有文字行之间的空隙。投影检测对这两类常量图返回 0°，并设置 `informative=false`，意思是“没有可用于本方法的方向证据”。它不是一个识别正确率；`informative=true` 也只表示图像并非常量图，不代表估计可靠。

稀疏单字、图形、多栏文字、旋转造成的裁剪，或超出搜索范围的倾斜，都可能使最大方差指向错误角度。霍夫法则可能被长边框主导。两种方法都应结合校正前后图像判断。

若要试 K 个角度，每次都旋转并统计 `W×H` 个像素，工作量约 `O(KWH)`。K 是尝试角度数量，不是图像尺寸。减小步长能加密搜索，同时增加耗时；先在缩小图上粗搜、再用原图按最佳角旋转，是可尝试的优化。

## 数学公式总结

### 投影方差计算

```
方差 = Σ(xi - μ)² / n

其中：
- xi = 第 i 行的黑色像素数
- μ = 平均每行黑色像素数
- n = 行数
```

### 旋转变换（绕中心点）

```
逆变换公式（用于计算目标像素对应的原图位置）：

x_src = (x_dst - cx) * cos(θ) - (y_dst - cy) * sin(θ) + cx
y_src = (x_dst - cx) * sin(θ) + (y_dst - cy) * cos(θ) + cy

其中：
- (x_dst, y_dst) = 目标图像坐标
- (x_src, y_src) = 原图像坐标
- (cx, cy) = 图像中心点
- θ = 旋转角度（弧度）
```

### 双线性插值

```
f(x, y) = f(x1,y1)*(x2-x)*(y2-y) + f(x2,y1)*(x-x1)*(y2-y)
        + f(x1,y2)*(x2-x)*(y-y1) + f(x2,y2)*(x-x1)*(y-y1)

其中：
- (x1, y1), (x2, y2) 是 (x, y) 周围的整数坐标
- f(xi, yi) 是对应位置的像素值
```
