## 1. 从固定上下文到按需读取

### 动机与直觉

第18章的编码器可以把整行压到最后一个隐藏状态。文本越长，单个向量就越需要同时保存许多局部细节。一个替代办法是保留所有位置的特征，在每个输出步骤重新读取它们。

可以把一排图像特征看成几条可读取的记录。每条记录有两部分：**Key（键）描述它有什么特征，Value（值）保存真正要读走的内容**。当前解码状态产生 Query（查询），描述这一步需要的信息。

接下来做两件不同的事：用 Query 与各个 Key 比较，决定每个位置占多大权重；再用这些权重混合 Value，得到给下一步使用的内容。Query、Key、Value 都是数值向量，不是“数字 0”“数字 1”这样的预先命名标签；实际模型需要训练这些表示。

```text
当前解码状态 s_t → Query q_t ─┐
                              ├→ 各位置匹配分数 → 权重 α_t → 上下文 c_t
图像各位置特征 h_j → Key k_j ─┘                               ↑
                   → Value v_j ──────────────────────────────┘
```

早期编码器—解码器注意力的核心是让上下文 `c_t` 随输出步骤改变。加性打分来自 [Bahdanau 等人的原论文](https://arxiv.org/abs/1409.0473)；下面的通用符号用于将它和点积注意力放在同一框架下讨论。

### 定义与一个可手算例子

设可读取的输入共有 S 个位置，qₜ 是第 t 次查询，kⱼ、vⱼ 是第 j 个位置的键和值。score 是打分函数，eₜⱼ 是它算出的匹配分数；αₜⱼ 是归一化后分给该位置的份额，cₜ 是最终读出的上下文向量。这里 α 表示注意力权重，与透明度、CTC 前向表无关。

一次查询按以下顺序完成：

\[
e_{tj}=\operatorname{score}(q_t,k_j),\quad
\alpha_{tj}=\frac{\exp(e_{tj})}{\sum_{l=1}^{S}\exp(e_{tl})},\quad
c_t=\sum_{j=1}^{S}\alpha_{tj}v_j.
\]

`t` 表示当前查询/输出步骤，`j` 表示被读取的位置，`e` 是未归一化分数，`α` 是位置权重，`c` 是上下文。只要存在一个合法 key，每个 `α≥0`，一行之和为1。因此每个输出通道都落在对应 V 通道的最小值和最大值之间；这个范围性质不再适用于后续任意线性投影或残差结果。

若两个 value 是10与30，分数是 `ln(3)` 与0：指数变成3与1，权重为0.75与0.25，soft 输出为 `0.75×10+0.25×30=15`。

hard argmax 会直接选第一个 value，输出10；按该分布随机选择位置时，输出是10或30，其期望为15。soft 的确定性混合、hard 的最大分数选择、hard 的抽样是三种不同操作。

### 逐步实现、影响与局限

1. 对每个 key 计算一个标量分数，不能把 value 的各维当成位置。
2. 对同一个 query 的所有合法 key 做 softmax。
3. 用这行权重混合所有 value；value 各通道使用同一行权重。
4. 交给后续分类器或解码器使用，注意力模块本身不必输出字符。

soft 路径在分数和 value 上可微。hard argmax 对选择边界通常不可微，抽样也需要额外梯度估计或松弛机制；本章不实现这些训练方法。提高分数差可能减少混合，却不能保证选到正确字符。

## 2. Q/K/V：角色、投影与维度

### 为什么需要不同表示

用来判断“是否相关”的通道与最终读取的通道可以不同。假设一个位置同时编码笔画方向、宽度和语义，query/key 可能主要匹配方向，而 value 携带后续生成所需的更多内容。因此一般不要求 `K=V`。

在实际模型中，常使用可学习投影：

\[
Q=X_qW_Q,\quad K=X_kW_K,\quad V=X_kW_V.
\]

“投影”在这里就是一次学到的线性组合：把原来的若干特征按权重相加，变成适合匹配或读取的新特征。`X_q` 是查询侧的输入特征，`X_k` 是被读取一侧的输入特征；W_Q、W_K、W_V 是三套需要学习的组合权重。

这些 W 在不同样本之间共用，Q/K/V 则由当前样本算出。因此注意力权重 A 是一次计算的结果，不是模型保存的一张固定“注意力表”。本章基础 API 接受**已经投影后的**矩阵；第23章实现这些投影及多头拆分。

| 量 | 维度 | 每一行表示 |
|---|---|---|
| Q | T×dₖ | 一次查询的匹配描述 |
| K | S×dₖ | 一个输入位置的匹配描述 |
| V | S×dᵥ | 一个输入位置的内容 |
| QKᵀ | T×S | 所有查询对所有键的分数 |
| A | T×S | 对每个查询，沿 S 归一化的权重 |
| O=AV | T×dᵥ | 每个查询读出的内容 |

T 是查询次数，S 是可读取位置数，dₖ 是用于匹配的特征项数，dᵥ 是每个位置所携带的内容项数。比如“问两次、读五个位置、每次带回三个数”就是 T=2、S=5、dᵥ=3。

T 与 S 可以不同，dₖ 与 dᵥ 也可以不同。Q 和 K 必须各有相同的 dₖ 项，才能对应相乘；K 和 V 必须各有 S 行，才知道每个键对应哪条内容。

### 用矩阵乘法检查约束

例如 Q 为 `2×4`、K 为 `5×4`、V 为 `5×3`：

```text
Q Kᵀ : (2×4)(4×5) = 2×5
A V  : (2×5)(5×3) = 2×3
```

两次查询可以读取五个视觉位置，输出各有三个通道。若将 K 写成 `4×5`，这不是“差一点的维度”，而是把位置和通道颠倒了；接口会拒绝。生产实现通常再增加 batch 和 head 轴，本章显式省略这两轴以便手算。

## 3. 缩放点积：为什么除以 √dₖ

### 由相似度到分数

点积 `q·k=Σq_rk_r` 是对应特征相乘再相加，r 遍历匹配通道。例如 `[1,0]` 与 `[1,1]` 的点积是 `1×1+0×1=1`。它只是当前表示下的匹配分数，还不是概率，也不天然等于字符相似度。在假设各分量独立、均值0、方差1时，每项乘积方差为1，dₖ 项相加的方差约为 dₖ；维度变大时，分数尺度可能变大。

softmax 对差距很大的分数容易给出接近0或1的权重，其局部导数可能变小。因此使用：

\[
E=\frac{QK^\top}{\sqrt{d_k}},\qquad O=\operatorname{softmax}(E)V.
\]

这里 E 是整张匹配分数矩阵，O 是输出，Softmax 按行执行；一行只对应一次查询。位置数 S 保持原来的含义，不与分数矩阵混用。

这是 [Attention Is All You Need §3.2.1](https://arxiv.org/html/1706.03762v7) 中的缩放点积。方差推导依赖上述统计假设，不是“所有真实模型的分数方差必为 dₖ”的定律；它也不等于把 q、k 归一化为余弦相似度。

### 完整手算：默认实验的第一行

```text
Q = K = [[1,0], [0,1], [1,1]]      dₖ = 2
V = [[10,0], [0,20], [10,20]]      dᵥ = 2
```

选 `q₀=[1,0]`：

1. 三个点积为 `[1,0,1]`。
2. 除以 `√2`，分数为 `[0.70710678,0,0.70710678]`。
3. 减去最大值后为 `[0,-0.70710678,0]`。
4. 取指数为 `[1,0.49306869,1]`，和为2.49306869。
5. 权重为 `[0.40111209,0.19777581,0.40111209]`。
6. 输出第0维是 `0.40111209×10+0.19777581×0+0.40111209×10=8.02224185`。
7. 输出第1维是 `0+0.19777581×20+0.40111209×20=11.97775815`。

这里第0、第2个 key 得分相同，因此权重相同。它们的 value 内容可以不同。改变 V 不会改变本次注意力权重，但会改变输出。

### 原理到代码

```javascript
const { transpose, matmul, softmax } = require('../shared/21-attention');
// 省略输入校验；完整校验见共享模块。
const scores = matmul(Q, transpose(K))
  .map(row => row.map(score => score / Math.sqrt(Q[0].length)));
const weights = scores.map(softmax); // 每一行归一化，不能对整矩阵一次归一化
const output = matmul(weights, V);
```

本例三个 query 的实测输出为：

| query | 输出通道0 | 输出通道1 |
|---|---:|---:|
| 0 | 8.02224185 | 11.97775815 |
| 1 | 5.98887907 | 16.04448371 |
| 2 | 7.51744922 | 15.03489843 |

## 4. stable softmax、温度与遮罩

### 数值稳定性的动机与推导

JavaScript 中 `Math.exp(1000)` 是 Infinity。直接用 `exp(1000)/(exp(1000)+exp(1001))` 得不到合法概率。利用指数的公共因子：

\[
\frac{e^{s_j}}{\sum_l e^{s_l}}=
\frac{e^{s_j-m}}{\sum_l e^{s_l-m}},\quad m=\max_l s_l.
\]

`[1000,1001]` 变为 `[-1,0]`，结果约 `[0.26894142,0.73105858]`。每个指数都不超过1。仍需拒绝 NaN、正无穷和溢出的点积，稳定 softmax 无法修复已经损坏的输入。乘温度缩放因子后也要校验：例如有限点积 `−Number.MAX_VALUE` 再除以0.5会成为负无穷，必须报溢出，不能冒充一个被遮罩的位置。只有显式遮罩才能产生分数中的 `−∞`。

### 温度：可控的分布尖锐度

页面将分数除以正数 τ，整体为 `QKᵀ/(√dₖτ)`。τ 小时偏向最高分，τ 大时更接近均匀。τ=1 对应默认缩放点积；温度是本章分析参数，不是原模型要求必须存在的额外可训练参数。

以分数 `[ln 3,0]` 为例，τ=1 得 `[0.75,0.25]`；τ=0.5 相当于指数权重9与1，得 `[0.9,0.1]`。如果分数相同，任意有限正 τ 都无法打破平局。τ→0 的极限也不应通过直接传入0实现。

### 遮罩为什么应在 softmax 前施加

遮罩 mask 表示“本次查询允许读取哪些位置”。因果遮罩防止文本位置读取后面尚未生成的词；padding 遮罩则排除为凑齐批次长度而补上的空位置。它们限制可见范围，不是在判断哪个字符更重要。

在分数矩阵 E 上，允许的位置加 0，禁止的位置加 `−∞`。由于 exp(−∞)=0，被禁止位置不再分到权重：

\[
A=\operatorname{softmax}(E+M),\quad
M_{ij}=\begin{cases}0&\text{允许}\\-\infty&\text{禁止}\end{cases}.
\]

因果遮罩要求 `j≤i`，例如第三个 query 可以读取0、1、2，但第一个只能读取0：

```text
true  false false       A 第0行 = [1,0,0]
true  true  false       A 第1行第2列 = 0
true  true  true
```

先 softmax 再把被禁止权重置0却不重新归一化，会令权重和小于1，改变输出尺度。全遮罩行则没有合法分布；本实现明确抛错，不填成“看似正常”的均匀权重。padding mask 和 causal mask 都存在时，用逻辑与组成最终允许矩阵；一个被 padding 掉的 query 若整行不可用，调用方需要先移除或另行定义该行的处理策略。

```javascript
const { scaledDotProductAttention, causalMask } = require('../shared/21-attention');
const result = scaledDotProductAttention(Q, K, V, {
  mask: causalMask(Q.length), // 此例要求 Q/K 等长，true=允许
  temperature: 1
});
```

## 5. 加性注意力：另一种可学习的打分方法

### 动机、公式与维度

query/key 原始通道数可能不同，关系也未必适合直接点积。可以先映射到隐藏宽度 dₐ，再用非线性打分：

\[
e_{tj}=v_a^\top\tanh(q_tW_q+k_jW_k).
\]

这里 `q_t∈R^{d_q}`，`k_j∈R^{d_k}`；`Wq:dq×da`、`Wk:dk×da`、`va:da`。本章实现不带偏置。对 e 做相同的逐行 softmax，再混合 V，所以改变的是打分函数，读取过程没有改变。

### 可手算实例与实现路径

取 `q=[1,2]`、`K=[[0],[1]]`、`Wq=[[1],[0]]`、`Wk=[[1]]`、`va=[2]`：

1. 查询投影为1，两个键投影为0和1。
2. 相加得1和2，过 tanh 得约0.761594和0.964028。
3. 乘 va 得分约1.523188和1.928055。
4. softmax 后约0.400144与0.599856。
5. 以 `V=[[10],[30]]` 加权，输出21.99712818。

`additiveAttention(Q,K,V,Wq,Wk,v)` 执行这五步。隐藏宽度影响打分容量，tanh 饱和会影响梯度。它不是“比点积必然准确”的替换；要在相同数据、预算和评价标准下比较。共享模块只对点积路径实现反向传播，加性路径仅用于前向对照。

## 6. self attention 与 cross attention 在 OCR 中的位置

| 类型 | Q 来源 | K/V 来源 | 常见矩阵形状 | OCR 用途 |
|---|---|---|---|---|
| 图像 self | 图像序列 | 同一图像序列 | S×S | 融合相隔较远的笔画和区域上下文 |
| 文本 self | 已知文本前缀 | 同一文本前缀 | T×T | 在因果条件下建模前缀 |
| cross | 解码器当前状态 | 图像编码器 | T×S | 每个输出位置读取视觉证据 |

self 的含义是来自同一序列，不是 `Q=K=V` 数值完全相同。不同可学习投影通常产生不同矩阵。cross 不要求 T=S，也不应简单套用方形的 `j≤i` 遮罩去限制图像位置。

```text
照片 → 第22章检测/裁剪 → 视觉编码器 → 一串图像特征 K,V
                                        ↑
已输出文本 → 解码器状态 Q → cross attention → 上下文 → 下个 token
```

这是第23章要组合的路径。对第25章“有间隔数字分割 + 自主 CNN”的第一版 demo，本章属于对照路线，不强制进入识别流水线。

与 CTC 相比，常规注意力解码器在输出时可以利用已生成前缀，并通过 cross attention 读取视觉位置；但通常不具有 CTC 路径折叠的强制单调结构。它可能跳读、重复读取或遗漏，热图好看也不等于整串准确。相邻两个“0”是两个输出 token，不能按 CTC 式规则随意折叠。

## 7. 从前向到反向：注意力怎样学习

### 动机与链式法则

“权重会自动找到字符”只是期待。真正发生的是：损失改变梯度，梯度更新投影和编码器参数，新的表示再产生新权重。为了检查这一过程，先把 Q/K/V 当作可求导的输入矩阵。

先看最末一步 O=AV：A 是位置权重，V 是各位置内容，O 是读出的结果。L 是下游定义的标量损失；G=∂L/∂O 是下游传来的变化率，说明 O 各项稍微变化时损失会怎样变。G_V、G_A 等下标标明“对哪个对象求导”，不是另外的输入特征。

按矩阵乘法的链式法则：

\[
G_V=A^\top G,\quad G_A=GV^\top.
\]

对于一行权重 a=softmax(s)，增加一个分数会改变整行归一化分母，因此也影响其他位置。下面 δⱼₗ 是指示数：j=l 时为 1，否则为 0；雅可比把这些“分数到权重”的变化率排成矩阵：

\[
\frac{\partial a_j}{\partial s_l}=a_j(\delta_{jl}-a_l).
\]

因此不必真的构造 S×S 的雅可比矩阵：

\[
(G_E)_{ij}=A_{ij}\left((G_A)_{ij}-\sum_l A_{il}(G_A)_{il}\right).
\]

反向计算时把温度τ也合并进分数E，令 `λ=1/(√dₖτ)`，此时 `E=λQKᵀ`；上式GE指对这个送入softmax的分数求导。于是：

\[
G_Q=\lambda G_EK,\quad G_K=\lambda G_E^\top Q.
\]

维度依次为 `GV:S×dv`、`GA:T×S`、`GE:T×S`、`GQ:T×dk`、`GK:S×dk`。遮罩位置 A=0，对应 GE 也为0；不能在反向中忘记遮罩。

浮点实现还要避免尾部消减：每行先从 `GA` 的所有元素减去最大权重位置的 `GA` 值，再代入上式。因为 `ΣA=1`，这个公共平移在精确算术下完全抵消，仍只需O(S)运算。例：`Q=[[50]],K=[[1],[0]],V=[[1],[0]]`、上游G=1时，O=σ(50)显示为1，但 `∂O/∂Q≈1.92874985e−22` 仍可表示；直接算 `1−加权平均梯度` 会误得0。回归测试用此独立闭式导数核验；已下溢为0的权重仍无法恢复，不能承诺任意精度。

### 手算第一次更新

实验固定 `K=[[1,0],[0,1]]`、`V=[[0],[1]]`，目标 y=0.9，初始 `Q=[[0,0]]`：

1. 分数 `[0,0]`，权重 `[0.5,0.5]`，输出 o=0.5。
2. `L=½(o−y)²=0.08`，上游梯度 `G=o−y=−0.4`。
3. `GA=GVᵀ=[0,−0.4]`，权重加权平均梯度为−0.2。
4. `GE=[0.5×0.2,0.5×(−0.2)]=[0.1,−0.1]`。
5. `GQ=[0.07071068,−0.07071068]`。
6. 学习率η=0.4：`Q←Q−ηGQ=[−0.02828427,0.02828427]`。

为什么第一项 Q 减小、第二项 Q 增大？目标 0.9 比当前输出 0.5 大，而两个 Value 分别是 0 和 1。要提高输出，需要把更多份额交给第二个位置；这一更新恰好降低第一个 Key 的匹配分数、提高第二个 Key 的匹配分数。这里更新的是两个 query 数字，K/V 固定；没有更新整个 OCR 网络。若 Q 来自 `XWQ`，还要继续传回 `GWQ=XᵀGQ` 和 `GX=GQWQᵀ`。

### 有限差分与实测结果

有限差分用独立的前向函数计算：

\[
\frac{\partial L}{\partial q}\approx\frac{L(q+\epsilon)-L(q-\epsilon)}{2\epsilon}.
\]

Jest 检查所有 Q/K/V 元素，在有/无因果遮罩以及 τ=0.7 时都与解析梯度匹配。差分步长过大产生截断误差，过小产生浮点相减误差；本例使用 `1e-5`，按小数位容差判断。

默认 `trainQuery()` 的真实运行结果（120步、η=0.4、无随机初值）：

| 状态 | 预测 | 损失 |
|---|---:|---:|
| step 0 | 0.50000000 | 0.08000000 |
| step 120 | 0.82847213 | 0.00255812 |

最终 Q 为约 `[-1.11357823,1.11357823]`。损失下降不代表已经到达目标0.9；运行程序会展示每20步记录，而不是只打印“训练成功”。增大学习率或步数不保证更好的数值稳定性。

## 8. 算法比较、参数与局限

| 比较维度 | 选项 | 主要差异与使用条件 |
|---|---|---|
| 打分 | 加性 / 缩放点积 | 前者使用隐藏非线性，后者方便矩阵乘法；任务效果需实验 |
| 读取 | soft / hard | 连续混合便于反向；离散选择需考虑训练方法 |
| 来源 | self / cross | 前者同序列关系，后者跨序列读取 |
| 约束 | 全可见 / causal / padding | 应由任务可见性决定，不能把因果约束当去噪选项 |
| 分辨率 | 更多视觉位置 / 更少位置 | 更多位置保留细节，但稠密注意力需要更多运算与存储 |

单头前向打分与读取约需 `O(TS(dₖ+dᵥ))` 运算，显式存储 A 需 `O(TS)`。self attention 中 T=S=N，权重数是 N²。本章纯 JavaScript 数组用于可解释性，不是高效 GPU kernel；真实推理还需批处理、缓存、内存管理和模型权重。

典型错误：沿通道而非 key 做 softmax；把 A 当字符概率；遗漏缩放；在 softmax 后不归一化地遮罩；把 self 理解为只有对角线；把随机注意力的集中区域当可验证解释；把 softmax 输出尖锐当准确率高。

## 9. 共享 API 与输入约定

统一使用有限数值的非空矩形 `number[][]`；行=token，列=channel。矩阵、logits、参数向量及布尔遮罩均不接受数组空洞（如 `[1,,0]`）；缺失值既不是0，也不是禁止位置。矩阵函数不接受嵌套 TypedArray，调用方应显式转换。函数不修改输入，不访问 DOM。

| 接口 | 返回与约束 |
|---|---|
| `matrixShape(M,name?)` | `[rows,cols]`，拒绝空/不规则/非有限矩阵 |
| `transpose(M)`、`matmul(A,B)` | 新矩阵；乘法内轴必须相等 |
| `softmax(logits)` | 一维权重；允许部分元素为 `−Infinity`，拒绝全遮罩 |
| `causalMask(N)` | N×N 布尔允许矩阵 |
| `scaledDotProductAttention(Q,K,V,{mask,temperature})` | `{scores,weights,output}` |
| `attentionBackward(Q,K,V,dOutput,options)` | `{dQ,dK,dV}`，重算前向避免过期缓存 |
| `additiveAttention(Q,K,V,Wq,Wk,v)` | `{scores,weights,output}`，仅前向 |
| `createAttentionExample(temperature,causal)` | 默认固定 Q/K/V 与结果 |
| `trainQuery({steps,learningRate})` | Q/K/V、target、逐步history、最终结果 |

第23章直接 `require('../21-attention')` 复用矩阵与点积接口，无需等待共享总入口导出。`scores` 中遮罩为负无穷；直接 JSON 序列化会变成 null，页面专门显示“−∞（遮罩）”，不要把 null 当作真实分数。

## 10. 自测与答案

5. self attention 是否要求 Q=K=V？
6. ∂L/∂V 和 ∂L/∂Q 的公式是什么？
7. 为什么全遮罩行报错比返回均匀权重更合理？
8. 注意力式识别输出“001”时，能否折叠成“01”？
