# 05. 图像去噪 (Image Denoising / Noise Reduction)

## 学习目标

3. **均值滤波** - 最简单的去噪方法
4. **高斯滤波** - 加权平滑，理解核与 sigma 的影响
5. **中值滤波** - 排序去除少量极值，同时理解细笔画风险

## 核心概念

### 1. 先看问题：一个像素突然变亮了

设想纸面上一小块区域的亮度大约都是 100，拍照后其中一个像素却变成了 255，形成一个白点。这个异常值可能来自噪声。去噪要解决的问题是：**能否参考周围像素，给这个位置一个更合理的亮度？**

这种方法依赖一个假设：相邻像素往往属于同一片纸面或同一段笔画，亮度通常比较接近。假设在文字边缘处就不一定成立，因为黑色笔画旁边本来就是白色纸面。因此，平滑既可能去掉噪点，也可能把文字边缘弄模糊。

本章比较三种做法：均值滤波让邻居平均分担影响；高斯滤波更重视附近像素；中值滤波把亮度排序后选中间值。它们都要看邻居，但计算规则不同。

### 2. 读算例前，先认清一个像素里的四个数

浏览器的 `ImageData` 用四个数记录一个像素，顺序是 **R、G、B、A**：

| 名称 | 含义 | 本章怎样使用 |
|---|---|---|
| R（Red） | 红色通道的强度 | 灰度图中可以用它读取亮度 |
| G（Green） | 绿色通道的强度 | 灰度图中与 R 相等 |
| B（Blue） | 蓝色通道的强度 | 灰度图中与 R 相等 |
| A（Alpha，透明度） | 0 为完全透明，255 为完全不透明 | 本章去噪保留它，不把它加入亮度平均 |

例如 `[100,100,100,255]` 是一个不透明的灰色像素。前三个数相等，所以这张图是灰度图；读 R、G、B 中任意一个，都得到亮度 100。**“只读 R”是利用这个相等关系，不是只处理画面里的红色物体。** 彩色照片要先完成第 03 章的灰度化，不能直接把红色通道当作灰度结果。

下文的小矩阵只写每个像素的一个灰度值，不重复写三份颜色，也省略透明度。0 表示黑，255 表示白。`W` 表示图像宽度，也就是列数；`H` 表示高度，也就是行数。因此一张图有 `W×H` 个像素，在内存里占 `W×H×4` 个通道值。写作 `H×W×4` 时，表达的是“行、列、通道”的结构，并不是把图像放大四倍。

### 3. 常见噪声：轻微波动与极端坏点

| 噪声 | 怎样改变像素 | 直观表现 |
|---|---|---|
| 高斯噪声（Gaussian Noise） | 给原亮度加上随机正负扰动，多数扰动较小，少数较大 | 纸面有细碎的明暗颗粒 |
| 椒盐噪声（Salt-and-Pepper Noise） | 随机选一些像素，直接改成黑色 0 或白色 255 | 出现孤立的黑点、白点 |

例如原亮度是 100，高斯噪声可能让它变成 96、103 或 111；椒盐噪声则可能直接把它变成 0 或 255。极端值会明显拉动平均数，这就是稍后要单独学习中值滤波的原因。

### 4. 卷积操作：让一个小窗口逐点计算 ⭐

#### 邻域、中心像素与核分别是什么

准备一个 3×3 的窗口，让它盖住“要处理的像素及其八个邻居”。窗口中间正对的像素叫**中心像素**，也就是这一步要写入结果的位置。窗口中的九个权重组成一个**核（kernel）**。把九个灰度值分别乘上对应权重，再相加，就得到这个位置的新灰度值。

完成一个位置后，窗口移动到下一个位置。所有位置都从原图读取邻居，结果写入另一张图；否则先算出的结果会影响后续窗口，计算就依赖扫描顺序了。

#### 从九个输入算出一个输出

下面窗口中央的 255 是当前要处理的像素。均值核让九个位置的权重都等于 `1/9`：

```text
原图中的 3×3 灰度邻域       均值核
100  120  110              1/9  1/9  1/9
 90  255  130              1/9  1/9  1/9
 80   95  105              1/9  1/9  1/9
```

按“对应位置相乘，再相加”计算：

```text
新灰度 = (100 + 120 + 110 + 90 + 255 + 130 + 80 + 95 + 105) / 9
       = 1085 / 9
       ≈ 120.556
存入图像：四舍五入得到 121
```

所以这一步把**中心位置**由 255 改成 121，其他位置要等窗口移过去后各自计算。121 比 255 更接近周围的亮度，说明平均操作削弱了突出的亮点；没有干净原图作参照时，还不能断言 121 就是真实亮度。

#### 把结果写回 RGBA：为什么保留透明度

假设这个中心像素原来是 `[255,255,255,64]`，它的透明度是 64。上面的计算只针对灰度值，结果写为 `[121,121,121,64]`：三个颜色通道一起更新，透明度仍是原位置的 64。不会拿八个邻居的透明度一起平均。“中心”会随着窗口移动，它不是指整张图的正中央。

本章返回与原图等宽、等高的新图。每个颜色通道只能保存 0–255 的整数，这叫 **8-bit（8 位）图像**，因为 8 个二进制位能表示 256 个值。代码中的 `Math.round` 负责四舍五入，裁剪负责把小于 0 的数变成 0、大于 255 的数变成 255。

对均值和高斯这类非负、权重和为 1 的核，结果本来就在输入亮度范围内。第 08 章的边缘检测却需要保存“变亮还是变暗”：例如差值 `20−100=−80`。若使用本章接口，−80 会变成 0，方向信息就丢失了。因此第 08 章用可保存负数和小数的浮点数组计算梯度，最后显示时才转成图像。

#### 把操作写成公式：相关与严格卷积的区别

先固定符号，避免把图像坐标与核内位置混在一起：

| 符号 | 意义 | 3×3 时的例子 |
|---|---|---|
| `I(x,y)` | 原图第 y 行、第 x 列的灰度；坐标从 0 开始 | 中心在 `(x,y)` |
| `k`、`r` | 核边长与半径，`r=(k−1)/2` | `k=3`，`r=1` |
| `i`、`j` | 相对中心的水平、垂直偏移 | 左邻居 `i=−1,j=0` |
| `K(i,j)` | 对应偏移处的权重 | 均值核都为 `1/9` |
| `S(x,y)` | 相乘相加后的结果，尚未取整 | 上例为 `1085/9` |

两个求和符号表示：遍历窗口的每一行，再遍历那一行的每一列。

```text
互相关：S(x,y) = Σ(j=-r…r) Σ(i=-r…r) K(i,j) × I(x+i,y+j)
卷积：  S(x,y) = Σ(j=-r…r) Σ(i=-r…r) K(i,j) × I(x−i,y−j)
```

互相关把核直接放到窗口上；严格数学卷积相当于先把核旋转 180°，再做同样的相乘相加。工程资料常把这类滑动计算都简称为“卷积”，阅读代码时仍要确认是否翻核。

用一行数据 `[10,20,40]` 和核 `[1,0,0]`，在中心 20 处计算：互相关取左边的 10，卷积翻核后取右边的 40。本项目 `correlate` 对应前者，`convolve` 对应后者。均值核和高斯核中心对称，旋转 180° 后不变，所以刚才算出的 121 对两者都成立。

### 5. 边界处理：窗口伸到图外时读什么

处理最左列时，窗口左边已经没有像素了。算法必须约定“缺失邻居”怎样取值，否则同一个核也可能算出不同结果。

| 方法 | 图外值的来源 | 影响 |
|---|---|---|
| 零填充（zero） | 当作黑色 0 | 平滑时可能使边缘变暗 |
| 边缘复制（replicate，本章采用） | 使用最近的边缘像素 | 常量图在边缘也能保持原亮度 |
| 镜像（reflect101） | 镜像向内取值，不重复边界像素 | 保留边界附近的变化趋势 |
| 有效区域（valid） | 只计算窗口完全落在图内的位置 | 输出尺寸会缩小 |

例如原图只有一行 `[10,20]`，用三点均值计算最左边：复制边缘得到 `(10+10+20)/3≈13.333`，存为 13；零填充得到 `(0+10+20)/3=10`。区别来自补出的那个数，不是平均公式变了。

对一行 `A B C D`，向两端补一个值：复制得到 `A | A B C D | D`，reflect101 得到 `B | A B C D | C`。本章在两个坐标方向都采用复制，输出尺寸保持不变。

## 三种滤波方法

### 1. 均值滤波（Mean Filter）

均值滤波就是上面的平均过程。对于奇数边长 `k`，窗口有 `k²` 个像素，每个像素权重为 `1/k²`：

```text
output(x,y) = 邻域内所有灰度值之和 / k²
```

`output` 表示结果图。3×3 窗口平均 9 个数，5×5 平均 25 个数。窗口越大，更多邻居共同决定一个输出，平滑通常越明显，细笔画也越容易被混入白色背景。先用 3×3 观察笔画，再决定是否扩大窗口。

### 2. 高斯滤波（Gaussian Filter）：让近邻更有分量

均值核认为九个位置同样重要。高斯核仍然做加权平均，但中心权重最大，距离中心越远，权重越小。

要生成权重，令 `dx,dy` 表示核内位置到中心的横向、纵向距离，单位都是像素；`σ`（sigma）控制权重向外衰减的速度。连续二维高斯函数为：

```text
G(dx,dy) = [1/(2πσ²)] × exp(−(dx²+dy²)/(2σ²))
```

这里 `exp(t)` 表示自然常数 e 的 t 次方。先不必记前面的常数：本章最终会把所有权重除以它们的总和，共同的常数会约掉。真正决定各位置比例的是距离和 σ。

以 3×3、`σ=1` 为例，先计算未归一化权重 `w`：

| 位置 | `dx²+dy²` | `w=exp(−(dx²+dy²)/2)` | 个数 |
|---|---:|---:|---:|
| 中心 | 0 | 1 | 1 |
| 上下左右 | 1 | 约 0.606531 | 4 |
| 四角 | 2 | 约 0.367879 | 4 |

总和约为 `1+4×0.606531+4×0.367879=4.897640`。每项除以这个总和，得到：

```text
0.0751  0.1238  0.0751
0.1238  0.2042  0.1238
0.0751  0.1238  0.0751
```

表里只保留四位小数，代码用完整精度。**归一化到权重和为 1，是为了不无故改变整片区域的亮度**：若九个输入都是 100，输出就是 `100×权重总和=100`。

把本章最初的九个灰度值代入这个核，可得约 135.607，存为 136。它比均值的 121 更接近中心的 255，因为中心获得了更大权重。这也说明：高斯滤波并不天然更适合去掉孤立极亮点。

σ 越小，权重越集中到中心，输出越接近原图；固定窗口下 σ 很大，各位置权重会越来越接近均值核。`k` 决定“看多远”，σ 决定“看见的邻居占多大分量”。覆盖中心两侧约 `3σ` 是常见的窗口选择思路，3×3、σ=1 的小核只是截取后重新归一化的教学例子。

共享函数要求 σ 有限且大于 0；核尺寸须为正整数，传入正偶数会向上调整为奇数，例如 4 变成 5，保证有明确中心。

### 3. 中值滤波（Median Filter）：排序后选中间值

中值滤波不把邻居相加，而是收集窗口内的灰度值，排序后取中间那个。继续使用同一个 3×3 邻域：

```text
排序前：100, 120, 110, 90, 255, 130, 80, 95, 105
排序后： 80,  90,  95, 100, 105, 110, 120, 130, 255
                         第 5 个数 ↑
输出中心灰度：105
```

255 虽然很大，却只占排序后的最后一个位置，不会像平均数那样把所有结果向上拉。对同一组输入，现在有了可比较的结果：均值 121、高斯 136、中值 105。

中值也是参考邻域的滤波，但它不能写成一个固定核的加权和：哪个输入成为中间值取决于这一窗口的排序，下一窗口可能换成另一个位置。这就是“非线性排序操作”的具体含义。

#### 中值也会误删细笔画

3×3 窗口中，若有 4 个噪点为 0、其余 5 个正常值为 128，中值仍是 128；如果变成 5 个 0，中值就变成 0。它利用了多数值的相对稳定性，不能在噪声占多数时恢复正确结果。

同样，白底上一条一像素宽的黑线，在某个窗口内可能只有 3 个黑像素和 6 个白像素。中值会选 255，把真实笔画也擦掉。观察去噪效果时，要同时看噪点和细笔画。

### 4. 噪声模型与可重复实验

为了比较滤波器，先在同一张参考图上加同一份噪声，再分别去噪。否则，滤波器 A 碰巧遇到的噪声较轻，比较就不公平。

高斯噪声的模型写为：

```text
I_noisy = clip(round(I + σ×Z), 0, 255)
```

`I` 是原灰度，`I_noisy` 是加噪后的灰度；`Z` 是每次随机生成、均值为 0、标准差为 1 的高斯随机数；这里的 σ 是**噪声强度，单位为灰度值**，与前面高斯核中以像素为单位的 σ 作用不同。`round` 取整，`clip` 限制到 0–255。例如 `I=100,σ=10,Z=−0.5` 时结果是 95。

代码用 Box–Muller 方法把均匀随机数转换为高斯随机数，并对同一像素的三个颜色通道加相同扰动。接近 0、255 时，一部分结果被裁掉，最终分布就不再是完整的高斯分布。固定随机种子（如实验中的 `20260911`）能重复生成同一序列，便于复核结果。

椒盐噪声的 `density=p` 是每个像素被替换的概率；被选中后，黑、白各占一半概率。100 个像素、`p=0.1`，平均会选中 10 个，但某次可能是 8 个或 12 个。`W×H×p` 是期望数量，不是精确数量；原本就是黑色的像素被改成黑色，外观也可能没有变化。`p=0` 不替换，`p=1` 则每个像素都会被选中。

### 5. PSNR：用参考图衡量像素误差

如果知道干净参考图，可以问：去噪后的每个像素离参考值有多远？先算**均方误差 MSE**：逐像素作差、平方，再取平均；平方让正负误差不能互相抵消。

令 `Iᵢ` 为参考图第 i 个像素，`Jᵢ` 为待评价图对应像素，`N=W×H` 为像素总数：

```text
MSE = Σ(i=1…N) (Iᵢ−Jᵢ)² / N
PSNR = 10 × log10(255² / MSE)，单位 dB（分贝）
```

`log10` 是以 10 为底的对数；255 是本章灰度能取到的最大值。误差越小，MSE 越小，PSNR 就越大。

例如参考为 `[0,255]`，结果为 `[0,0]`：两个平方误差是 0 和 65025，MSE 为 `65025/2=32512.5`，PSNR 为 `10×log10(2)≈3.0103 dB`。两图完全相同则 MSE 为 0，API 返回 `Infinity`，表示没有像素误差。

本章 PSNR 比较等尺寸、非空的灰度图，只读 R，忽略透明度；彩色图或尺寸不一致会报错。上传照片后再加人工噪声，参考图只是“加噪前的照片”，并不代表现实中没有噪声的真值。更高 PSNR 也不能保证 OCR 更准：少量关键笔画被擦掉，可能比大片背景的微小改善更影响识别。没有适用于所有 OCR 场景的“超过 30 dB 就合格”结论。

## 三种滤波器对比

| 方法 | 同一窗口的计算 | 本章算例输出 | 主要取舍 |
|---|---|---:|---|
| 均值 | 所有灰度平均 | 121 | 简单，但极端噪点能拉动平均数，也会模糊边缘 |
| 高斯 | 距离越近，权重越大 | 136 | 可调平滑范围，中心的极端值也会被赋予较高权重 |
| 中值 | 排序取中间值 | 105 | 对少量椒盐噪点有用，但会删除窗口内占少数的细线 |

先根据噪声类型选择小窗口，再观察噪点是否减少、细笔画是否保留。混合噪声可以尝试先中值、再轻度高斯平滑，但应与单独使用各滤波器比较，避免叠加处理过度。

如果图像有 `W×H` 个像素，窗口是 `k×k`，本章均值/高斯实现每个输出都访问 `k²` 个输入，工作量约为 `O(WHk²)`。中值还要排序，约为 `O(WHk² log(k²))`。`O(...)` 描述输入变大时工作量的增长趋势，不是运行秒数。高斯可分离为两次一维滤波，均值也可用积分图优化；本章保留逐窗口实现，方便核对计算。

## 与 OCR 的关联

去噪在 OCR 预处理链中的位置：

```
彩色图 → 灰度图 → [均值/高斯去噪] → 二值图 → 形态学 → 文字检测 → 文字识别
                             ↑
                        当前学习
```

| 影响 | 说明 |
|------|------|
| 减少误识别 | 噪点可能被误认为文字笔画 |
| 改善边缘 | 清晰的文字边缘有助于识别 |
| 后续处理 | 减少连通域分析的干扰 |

**注意**：二值图可用中值滤波（仍保持0/255），但均值/高斯会产生中间灰度，应在二值化前使用，或在平滑后重新二值化。去噪过度会模糊甚至抹去笔画。

## 自测问题

1. 高斯噪声与椒盐噪声怎样改变一个灰度为 100 的像素？
2. 为什么灰度图可以只读 R？中心 alpha 指哪里，是否参与平均？
3. 本章九个数的均值为 120.556，中心像素原来是 [255,255,255,64]，输出写成什么？
4. 数学卷积与互相关有什么区别？为什么均值核得到相同结果？
5. 中值为什么能抵抗少量椒盐噪点，又为什么可能擦掉黑色细线？
6. 怎样选核大小，能否把本章滤波接口直接用于梯度？

<details>
<summary>点击查看答案</summary>

1. 高斯噪声加上随机正负扰动，可能变成 96 或 103；椒盐噪声按概率直接替换成 0 或 255。前者的 σ 控制扰动幅度，后者的 density 控制被选中的概率。

2. 灰度图的 R、G、B 相等，读 R 就得到灰度。中心是本次窗口正对的输出位置；alpha 是该像素的透明度，保留原值，不与邻居平均。

3. 写为 [121,121,121,64]。灰度四舍五入为 121，三个颜色通道一起更新，透明度 64 不变。

4. 数学卷积等价于先将核翻转 180°，互相关直接使用原核。均值核中心对称，翻转后不变；不对称核则可能产生不同结果。

5. 少量极值排在两端，不容易改变中间值。但 3×3 窗口里若黑线只有 3 点、白背景有 6 点，中值会选白色，真实细线也被删除。

6. 从小核观察噪点和细笔画，再决定是否扩大。该接口输出 0–255 整数，负梯度会被裁成 0，因此第 08 章用浮点数组保存中间响应。
