# 01. 数字图像基础 (Digital Image Fundamentals)

## 学习目标

理解数字图像的本质是所有图像处理的前提。本章将帮助你掌握：

1. **像素（Pixel）的概念** - 图像的最小组成单位
2. **分辨率** - 图像的宽度和高度
3. **色彩空间** - RGB、HSV、灰度等颜色表示方式
4. **图像的矩阵表示** - 计算机如何存储图像数据
5. **位深度** - 每个像素能表示多少种颜色

---

## 这章在 OCR 中解决什么问题？

一张照片进入程序后，程序拿到的是一串数字。后面说的“把文字变黑”“去掉一个噪点”，最终都要落实到：找到某个像素，再修改它对应的数字。本章先把这件事说清楚，不需要先学矩阵运算。

阅读时可以一直想着一张 **宽 2、高 2 的小图**：左上红色、右上绿色、左下蓝色、右下黄色。我们会用它连接颜色、坐标和内存三个概念。

## 核心概念

### 1. 什么是像素（Pixel）？

**像素（Pixel）** 是 "Picture Element" 的缩写，是构成数字图像的最小单位。

想象一张图片是一个巨大的马赛克，每一个小方块就是一个像素。每个像素都有自己的颜色值。

```
┌───┬───┬───┬───┐
│ P │ P │ P │ P │   P = Pixel（像素）
├───┼───┼───┼───┤
│ P │ P │ P │ P │   这是一个 4x3 的图像
├───┼───┼───┼───┤   共有 12 个像素
│ P │ P │ P │ P │
└───┴───┴───┴───┘
```

### 2. 分辨率（Resolution）

本章用“像素分辨率”表示图像的尺寸，通常用 **宽度 × 高度** 表示，单位是像素。

| 常见分辨率 | 像素数量 | 说明 |
|-----------|---------|------|
| 640 × 480 | 307,200 | VGA 标准 |
| 1920 × 1080 | 2,073,600 | Full HD |
| 3840 × 2160 | 8,294,400 | 4K |

**像素总数 = 宽度 × 高度**。像素数不同于打印像素密度 PPI，也不保证有效细节更多：把模糊图放大不会恢复信息。表中 3840×2160 是 UHD 4K；2560×1440 通常称 QHD。

### 3. 色彩空间（Color Space）

#### RGB：用三个数描述一个像素的颜色

R、G、B 分别是 Red（红）、Green（绿）、Blue（蓝）的缩写，叫作三个**颜色通道**。可以把通道理解为这个像素的三个数值位置。课程采用每通道 8 位的表示，每个数都是 0–255 的整数。

| RGB 三个数 | 显示的颜色 | 怎么读 |
|---|---|---|
| `(255, 0, 0)` | 红 | 红通道取最大，另外两个为零 |
| `(0, 255, 0)` | 绿 | 只有绿通道取最大 |
| `(0, 0, 255)` | 蓝 | 只有蓝通道取最大 |
| `(255, 255, 0)` | 黄 | 红、绿共同参与显示 |
| `(0, 0, 0)` | 黑 | 三个通道均为零 |
| `(255, 255, 255)` | 白 | 三个通道均取最大 |

为什么同样叫 RGB，还会遇到 sRGB？RGB 说明“用红绿蓝三个量表示”，但没有完整说明“这些数字显示成哪一种颜色”。**sRGB 是本课程默认的颜色约定**，进一步规定原色、白点和数字与光强的关系。现在先按上表读数；第 03 章再解释为什么数值 128 不等于一半的光强。

#### 灰度：只描述黑到白的位置

当三个通道相等时，像素没有偏向某种颜色：`(0,0,0)` 是黑，`(128,128,128)` 是灰，`(255,255,255)` 是白。因此只需一个灰度值，就能描述它的颜色。

这里要分清“需要几个数描述”与“程序实际存了几个数”。紧凑灰度格式可以只存一个 128；浏览器的 ImageData 仍会把它写成三个相等的 RGB 值，并附上下一节要讲的透明度。

#### HSV：为了选颜色，换一组容易调节的数

在选色器中，我们经常想表达“保持红色，但淡一点、暗一点”。HSV 把这个操作拆成三个量：

| 量 | 含义与范围 | 操作时的直觉 |
|---|---|---|
| H（Hue，色相） | 色环角度，`[0,360)` 度 | 选择红、绿、蓝等色调；0° 与 360°重合 |
| S（Saturation，饱和度） | 0–100% | 降低时颜色趋向灰色 |
| V（Value，明暗参数） | 0–100% | 降低时趋向黑色 |

例如纯红色可写为 `H=0°、S=100%、V=100%`；把 S 降到 0、V 保持 100%，得到白色。灰色没有明确色相，代码为方便计算把 H 记为 0，这并不表示灰色是红色。HSV 来自 RGB 的变换，V 取决于最强的颜色通道，并不是物理亮度；它更适合选色，本课程后续 OCR 主要使用灰度。

### 4. 图像的矩阵表示

在计算机中，图像被存储为一个**二维矩阵**（灰度图）或**三维矩阵**（彩色图）。

#### 灰度图：二维矩阵

```
3×3 灰度图像：
┌─────┬─────┬─────┐
│ 120 │ 150 │ 180 │
├─────┼─────┼─────┤
│  80 │ 100 │ 130 │
├─────┼─────┼─────┤
│  50 │  70 │  90 │
└─────┴─────┴─────┘

JavaScript 表示：
const grayImage = [
  [120, 150, 180],
  [ 80, 100, 130],
  [ 50,  70,  90]
];
```

#### 彩色图：三维矩阵

```
每个像素有 3 个值 (R, G, B)：

2×2 彩色图像：
┌─────────────┬─────────────┐
│ (255,0,0)   │ (0,255,0)   │  红色 | 绿色
├─────────────┼─────────────┤
│ (0,0,255)   │ (255,255,0) │  蓝色 | 黄色
└─────────────┴─────────────┘
```

### 5. 位深度：为什么一个通道最大是 255？

一个二进制位只能取 0 或 1。用 8 个位存一个数，就有 `2⁸=256` 种组合，从 0 数到 255。8 位等于 1 字节；“每通道 8 位”和“每像素 8 位”不是一回事。

| 存储方式 | 每像素存什么 | 每像素占用 |
|---|---|---|
| 位打包二值图 | 一个黑白标记 | 1 位，8 个像素合用 1 字节 |
| 紧凑灰度图 | 一个灰度数 | 1 字节 |
| RGB 图 | R、G、B | 3 字节，即 24 位 |
| RGBA 图 | R、G、B、A | 4 字节，即 32 位 |

RGB 的颜色组合数是 `256³=16,777,216`。RGBA 多出来的 A 记录不透明度，并不是第四种颜色。

### 6. Alpha：像素自己的颜色，和最终看见的颜色

**Alpha（透明度通道，记为 A）决定这个像素遮住背景的程度。** A=255 表示完全不透明，A=0 表示完全透明。比如黑色文字通常存成 `(0,0,0,255)`；透明背景上的一个像素也可能有黑色 RGB，却存成 `(0,0,0,0)`。后者放到白底上看见的是白底，不能直接把它算成黑字。

看一个半透明黑像素 `(0,0,0,128)` 放到白底的例子。先把 A 换成比例 `α=A/255=128/255`，约为 50.2%。对 R、G、B 中任意一个通道分别计算：

```text
合成后的通道值 = α × 像素通道值 + (1−α) × 背景通道值
               = (128/255) × 0 + (127/255) × 255
               = 127
```

于是合成结果是灰色 `(127,127,127,255)`。这里的“合成”就是把透明像素和背景合在一起，得到最终显示的颜色。这个算例直接混合编码值；需要模拟物理光强相加时，要先做第 03 章的 sRGB 解码。

知道它的用途后，再看实现约定就容易了：ImageData 的 RGB 是**非预乘**的，即读取到的颜色通道没有预先乘以 α；不能把 128 的 alpha 再当成灰度参与平均。Canvas 内部可能采用预乘表示，半透明像素反复写入、读出会有量化误差。

浏览器新建 `new ImageData(2,2)` 得到透明黑。课程 Node 工具 `createImageData(2,2)` 则默认创建不透明白图，便于在白纸上画黑字。这是两个容器的初始化差别，不是“0 有时表示白色”。

### 7. 从二维坐标找到一维数组里的像素

回到开头的 2×2 小图。约定左上角是 `(x=0,y=0)`，x 向右增加，y 向下增加。按“第一行从左到右，再读第二行”的顺序存储，每个像素连续占四项：

| 坐标 `(x,y)` | 颜色 | RGBA 值 | 数组位置 |
|---|---|---|---|
| `(0,0)` | 红 | `[255,0,0,255]` | 0–3 |
| `(1,0)` | 绿 | `[0,255,0,255]` | 4–7 |
| `(0,1)` | 蓝 | `[0,0,255,255]` | 8–11 |
| `(1,1)` | 黄 | `[255,255,0,255]` | 12–15 |

为什么黄色从位置 12 开始？图像宽度 W=2，前面完整的 y=1 行有 `y×W=2` 个像素，本行再跳过 x=1 个，总共跳过 3 个像素；每个占四项，所以起点为 `3×4=12`。

```javascript
const index = (y * width + x) * 4;
const red = imageData.data[index];
const green = imageData.data[index + 1];
const blue = imageData.data[index + 2];
const alpha = imageData.data[index + 3];
```

以后遇到 `H×W×4`，就把它读成“高 H 行、每行宽 W 个像素、每像素四个通道”。本例是 `2×2×4=16` 个一字节数。把图变成灰度、再变成黑白，只改变这些数的内容；只要仍用 RGBA 存储，数组长度就仍然是 16。

## 自测问题

1. 宽 2、高 2 的 RGBA 图占多少字节？变成灰度后呢？
2. 坐标 `(1,1)` 的蓝通道位于数组哪里？
3. `[0,0,0,0]` 和 `[0,0,0,255]` 放在白底上分别看见什么？
4. `[0,0,0,128]` 与白底按本章编码值公式合成，得到多少？
5. “24 位 RGB”是不是每个通道有 24 位？
6. 把模糊图从 100×100 放大到 200×200，是否找回了文字细节？

<details>
<summary>展开答案与计算依据</summary>

1. `2×2×4=16` 字节。只把 RGB 改成相同灰度而仍使用 RGBA，还是 16 字节；改存紧凑灰度才是 4 字节。
2. RGBA 起点 `(1×2+1)×4=12`，蓝通道再加 2，位于 `data[14]`。
3. 前者完全透明，看见白底；后者不透明，看见黑色。RGB 相同不代表显示结果相同。
4. α=128/255，每个颜色通道为 `0×α+255×(1−α)=127`，得到不透明灰色。
5. 不是，RGB 三个通道各 8 位，总计 24 位，可以表示 256³ 种颜色组合。
6. 没有。像素数量增加不等于原图丢失的信息恢复，只是用更多像素表示已有内容。
