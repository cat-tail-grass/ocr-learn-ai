# ocr-learning-curriculum Specification

## Purpose
约束OCR课程的知识覆盖、三件套颗粒度、理论与实验一致性及真实学习进度，支持面向资深研发的连续技术分享。来源为2026-09-11归档的课程任务；材料正确性复核已完成，归档状态和未完成事项见该任务的ARCHIVE_NOTES.md。

## Requirements
### Requirement: 与旧课保持三件套交付及相同教学颗粒度

第 14–26 章 MUST 以 `index.html` 教学 demo、`README.md` 完整课程、可通过 `node XX-topic/index.js` 运行的 `index.js` 教学实验为三个主要交付物。课程 MUST 遵守从第 04、05、11、12 章实读提取的 `docs/COURSE_STANDARD.md`，以概念覆盖、计算展开、可操作实验和三者一致性衡量颗粒度；允许辅助文件与共享算法，不以代码行数或文件存在代替验收。

#### Scenario: 提交一个后续章节
- **WHEN** 子代理或主代理提交第 14–26 章中的任意一章
- **THEN** 三个主要文件均存在且有明确启动说明，README 包含知识点到 HTML 与 Node 实验的对应表，主代理按旧课基准逐项核对

### Requirement: 核心技术点展开至公式与可核对的运算

README MUST 对主要技术点逐一说明问题动机、直觉、公式与符号/维度、具体输入和关键中间值、算法步骤与代码对应、参数影响及局限，并包含方法对比、OCR 上下游关系、运行说明、误区、自测答案及下一章联系。涉及算法简化时 MUST 明确简化范围，不得将仅有概述、API 名称或外部链接的内容作为完整章节。

#### Scenario: 检查一个神经网络知识点
- **WHEN** 阅读前向传播或反向传播小节
- **THEN** 能看到具体输入与权重、计算约定、中间值和更新结果，并通过 Node 实验或数值测试核对，而非只得到公式名称

### Requirement: HTML 提供可操作的过程与对照实验

HTML demo MUST 提供可用默认数据或样例、可改变的输入/参数、输入与关键中间过程及结果展示，并至少有一种能观察差异的对照。相关的计算中、非法输入、空白和加载失败状态 MUST 清楚可见；只有静态截图、固定结果或一个 JSON 输出的页面不满足交付要求。

#### Scenario: 调整本章核心参数
- **WHEN** 用户在 demo 中改变输入、配置或方法并执行实验
- **THEN** 系统实际重新计算，在对应的图像、矩阵、曲线、路径、表格或对齐展示中呈现变化，并说明其意义

### Requirement: Node 脚本提供独立的多步骤教学实验

Node 脚本 MUST 自带可复现小型输入，以有标题的多个实验覆盖核心算法、参数或方法对比，以及说明局限的边界示例，输出关键输入、中间值/维度和结果解释。长训练与快速演示 MUST 有清楚区别，算法实现 MUST 便于逐步阅读和调试。

#### Scenario: 直接运行章节脚本
- **WHEN** 按 README 完成必要的首次环境准备后执行 `node XX-topic/index.js`
- **THEN** 脚本无需手工拼接内部函数即可运行本章教学实验，输出有意义的分阶段结果；错误清楚报告，长训练以单独命令说明

### Requirement: 三种产物的行为一致且经过审查

README 的公式与算例、HTML 的交互以及 Node 脚本 MUST 对应同一套算法约定和共享实现。主代理 MUST 记录逐章的文档审读、脚本运行、必要数值测试和浏览器交互验证结果，再将章节标记为材料已交付。

#### Scenario: 文档与运行结果不一致
- **WHEN** 发现讲义算例、浏览器展示或 Node 输出之间存在矛盾
- **THEN** 修正并重新验证相关产物，本章在问题解决前保持待验收状态

### Requirement: 按现有深度补齐剩余课程

课程 MUST 按 `OUTLINE.md` 的第 14–26 章顺序覆盖全部剩余知识点，保留当前深入浅出的原理与实践深度。用户已掌握第 01–13 章；后续章节 SHALL 通过必要的前置知识回顾衔接，不要求重学前 13 章。第 25–26 章的整合与验证对象 SHALL 对齐手写数字串 demo。

#### Scenario: 从当前学习进度继续
- **WHEN** 开始执行后续课程任务
- **THEN** 阅读顺序从第 14 章神经网络基础开始，逐个知识点衔接；实施可按用户授权由子代理并行完成独立模块，主代理统一审查接口与交付质量

#### Scenario: 课程与最终实现范围不同
- **WHEN** 推进第 18–24 章的序列识别、Attention、检测网络、Transformer 和后处理内容
- **THEN** 保留各章原定核心知识和可运行原理示例，并说明它们解决的问题以及是否用于最终 demo

### Requirement: 每章技术点可理解且可验证

每章 MUST 包含中文 README、可运行的 JavaScript 示例，以及在有助于理解时提供的浏览器交互演示。讲解 SHALL 覆盖学习目标、前置知识、直觉与数学原理、公式符号、关键计算或维度变化、实现步骤、输入输出、适用条件、局限、常见误区和自测题及答案。使用训练框架时 MUST 解释框架操作与算法步骤的对应关系。

#### Scenario: 学习神经网络训练
- **WHEN** 用户阅读第 14 章并运行示例
- **THEN** 能追踪一次前向计算、损失计算、反向传播和参数更新，并核对小型数值例子的结果

#### Scenario: 学习序列识别
- **WHEN** 用户阅读 CTC 和 CRNN 章节
- **THEN** 能解释输入输出长度不一致、blank、重复字符的折叠规则、特征图到序列的变换，并运行包含相邻重复数字的示例

### Requirement: 共享模块复用与进度真实

通用算法 SHALL 放在按章节组织的 `shared/` 模块中，复用已有能力，并为新增或修正的关键算法提供有意义的 Jest 测试。章节交付 MUST 验证示例可运行和必要的测试通过，再更新材料完成情况；`PROGRESS.md` MUST 区分材料与代码交付状态和学习者实际掌握状态。

#### Scenario: 交付一个新章节
- **WHEN** 当前章的文档、示例与必要验证完成
- **THEN** 更新共享模块说明和进度，记录本章产物、验证结果与下一知识点，但不自动断言用户已掌握本章

### Requirement: 支持多节研发技术分享

课程 SHALL 面向具备机器学习基础的资深研发与技术主管，提供每章重要知识点概括、可讲解的示例和章节之间的联系。分享路线 SHALL 能拆成多节，记录首次分享日期为 2026-09-22；具体课时和用户讲稿不作为固定实施约束。

#### Scenario: 用户整理自己的分享内容
- **WHEN** 用户基于一个已完成章节制作总结
- **THEN** 能找到该章核心结论、必要公式或图示、演示步骤和易错点，并在不同课次之间建立连续的学习路线
