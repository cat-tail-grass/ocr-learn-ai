## Context

当前仓库采用 JavaScript，前 13 章均包含 README、Node.js 示例和浏览器页面，公共算法按章节位于 `shared/`。用户确认已经掌握前 13 章，并会自行总结后续材料用于公司分享。2026-09-08 的基线检查中，11 组、247 项 Jest 测试通过；第 13 章使用合成数字，浏览器还内嵌了一份算法实现，尚无真实手写模型和照片数字串的整合入口。

用户确认首次分享时间为 2026-09-22，允许安排多节课，要求维持现有技术讲解深度。现场流程是同事在白纸上用深色笔写单行数字串，数字留有基本间隔，完整拍照后发群；用户保存照片并导入 demo。允许不同字迹、轻微倾斜和光照不均。

## Goals / Non-Goals

**Goals:**

- 按第 14–26 章顺序补齐课程，讲透关键概念、公式、实现和限制。
- 训练本项目自己的手写数字模型，并通过图片导入识别完整数字串。
- 复用前 13 章成果，让用户和听众能检查从照片到预测的关键计算与中间结果。
- 实现独立、可复核的评估，并形成多节分享可使用的材料。

**Non-Goals:**

- 第一版不承诺处理粘连严重、互相覆盖、多行、任意背景或明显透视变形的文字。
- 不扩展到中文、字母、多语言文档或通用 OCR 产品，也不把全部课程算法强制装入最终 pipeline。
- 不接入群聊消息、自动收图、自动发消息或云端识别服务。
- 不代替用户自行整理讲稿；当前已获得并行实施课程与 demo 的授权。

## Decisions

用户已明确授权子代理按局部模块并行生成、主代理审查集成。教学阅读仍按 14–26 章顺序，实施按互不覆盖的文件范围并行。颗粒度以旧第 04、05、11、12 章实读提取的 `docs/COURSE_STANDARD.md` 为依据，三个主要文件均为必交；每章建立技术点到文档、HTML 和 Node 实验的对应表。

### 2. 第一版使用传统定位分割加自主训练 CNN

主要数据流：

```text
照片文件
  → 解码与方向处理
  → 按需灰度化、去噪、阈值处理与倾斜校正
  → 单行数字区域定位
  → 数字分割与从左到右排序
  → 裁剪、保持比例缩放、留白与居中、统一前景和像素范围
  → 自主训练 CNN 分类
  → 按字符顺序拼接字符串
  → 原始预测与正确答案独立比较
```

对有基本间隔的数字，已有投影和连通域模块可作为实现基础。一个连通域不一定等于一个数字：分割策略需要用断笔、独立笔画和间距变化的照片验证。统一训练与推理的黑白极性、尺寸、灰度范围、居中方式，并保留用于定位的二值图和用于分类的灰度信息；不同预处理步骤按效果选择，不默认全部串联。

接口返回完整字符串、字符区域、各字符候选得分、关键中间图像、整体识别状态与核心流程总耗时，供 demo 与评估共用。页面分别提示输入读取、模型加载和识别状态；各计算阶段通过中间图检查，本版不实现逐阶段性能计时。`elapsedMs` 不包括文件解码、模型下载和界面绘制。前导零和重复数字全程保持字符串语义；不使用真值长度辅助分割。

考虑过直接以 CRNN + CTC 作为最终识别器。它是第 18–20 章的学习与对照路线，但对当前明确有间隔的输入，分割加 CNN 更便于复用已有成果和定位现场错误。如果真实开发照片证明分割成为主要瓶颈，再通过独立实验评估序列路线并更新设计。

### 3. JavaScript 训练与浏览器推理复用同一模型契约

保持 JavaScript 技术栈，使用 TensorFlow.js 定义并训练模型；先在第 16 章验证当前环境可用的版本、训练后端、保存加载和浏览器运行方式，再记录可复现命令。基础反向传播、卷积和 CTC 小例子用于讲解计算，框架用于需要规模化训练的部分。CTC 训练所需算子或梯度支持应在第 19–20 章实践前验证，不能假定框架存在未确认的接口。

模型产物伴随输入尺寸、标签映射、前景极性、归一化方式、模型标识和训练配置。浏览器演示与 Node.js 入口复用公共算法和输入处理定义，避免出现页面内嵌算法与测试模块结果不同的问题。模型预先训练和准备，现场以加载模型、导入照片和评估为主。

考虑过以 Python 训练再跨框架转换，但当前学习项目的实现语言和原大纲均以 JavaScript 为主，先保持一套可解释的训练部署流程。

### 4. 标准数据和真实照片分别评估

以 MNIST 等真实手写单数字数据建立训练基线，另用开发照片验证拍照、分割和输入归一化的影响。对公开数据记录来源、许可和原始划分；对自采数据先按原图及可用的书写者标识划分，再裁剪和增强。同一原图产生的字符、缩略图、压缩图和增强图不能跨训练、验证、测试分区。

调整超参数和阈值使用验证集，最终测试集仅用于冻结配置后的测量。现场使用未参加训练或调参的新照片；可在演示结束后收集失败样本改进下一版，但保留本轮原始结果。已有 KNN 对照实验需要统一数据划分口径，不能继续用测试集选 K 后再把同一结果宣称为独立测试成绩。

### 5. 用明确指标衡量照片数字串表现

- 单数字准确率：独立的已裁剪数字测试集上，预测正确数 / 测试数字数。
- 字符错误率：`CER = Σ(S + D + I) / ΣN`，S/D/I 分别是编辑距离对齐产生的替换、删除、插入次数，N 是正确答案的字符数。若需输出具体对齐，使用固定的平局处理规则。
- 整串完全正确率：预测字符串与正确答案完全一致的照片数 / 有标签有效照片数。
- 同时记录样本数、真实字符数、失败数、待标注数和明确排除的理由。

用字符串比较保留前导零与重复字符。CER 可能超过 100%，不截断，也不将其补数当作通用准确率。对有效但未识别出内容的照片，以空预测计入删除错误和整串失败；损坏文件和超出约定范围的图片单独记录。置信度只用于展示模型判断，不能代替实测成绩或保证正确。

当前没有约定准确率门槛，验收重点是完整流程可运行、指标可复核、对多位书写者的新照片如实报告成绩和限制；不凭空承诺某个准确率。

### 6. 用本地文件导入完成现场流程

用户将群聊照片保存到本地，再通过页面选择文件导入，减少外部系统依赖。界面提供原图、处理中间结果、分割框、逐字预测、完整预测和正确答案录入，记录可导出为 JSON 供复核。多张照片可逐张处理并累积评估结果，不要求第一版实现群聊抓取或一次性批量上传。

## Risks / Trade-offs

- 标准手写数据与手机照片差异较大 → 用独立开发照片验证归一化和增强，分别报告标准数据与照片表现。
- 断笔或距离过近导致分割错误 → 用投影与连通域的互补信息验证分割，展示区域框并保留失败案例。
- 群聊压缩、手机方向和光照影响输入 → 预演覆盖实际保存下来的图片，提供可用格式及图片处理说明。
- Node.js 与浏览器的算子、后端或文件加载行为不同 → 在第 16 章先完成最小训练、保存、加载、推理闭环，新增框架操作先验证再编写教学说明。
- 深度课程内容多于单次分享容量 → 保持逐章推进并按主题拆成多节，不通过跳过技术点压缩进度。
- 小样本现场成绩波动 → 总是展示样本量、逐图结果和错误构成，不把一次演示的成绩泛化为所有手写场景能力。
- 置信度阈值会改变拒识行为 → 在验证集调整，并让拒识的有效照片继续进入端到端评估分母。

## Migration Plan

1. 先创建本 OpenSpec 任务；已有章节与用户未提交的修改保持当前状态。
2. 实施启动时同步大纲、项目约定与进度的目标描述，保留第 01–13 章历史和真实完成状态。
3. 按章节添加文档、示例、共享算法与必要验证，再更新材料交付进度。
4. 第 17 章形成可保存加载的数字模型，第 18–24 章继续完成原理学习与实验，第 25 章整合照片识别，第 26 章完成真实评估。
5. 在独立照片预演中修正输入处理与展示问题，冻结演示模型，形成使用说明和评估报告。
6. 新模型和配置采用可区分的版本标识；实验效果退化时可恢复上一版模型及处理配置，不覆盖已有评估记录。
